# 构建与分发

## 一、环境要求

| 项 | 版本 | 说明 |
| --- | --- | --- |
| macOS | 13+ | 本机开发与 CI 均为 macOS |
| Xcode | **16.4** | 与 GitHub Actions `macos-15` 镜像默认版本一致 |
| XcodeGen | 2.38+ | `brew install xcodegen`，工程文件由 `project.yml` 生成，不入库 |
| SwiftLint / SwiftFormat | 任意较新版本 | `brew install swiftlint swiftformat`（CI 镜像已预装） |
| Python 3 | 3.9+ | 仅用于 `Tools/` 下的辅助脚本 |

部署目标：iOS/iPadOS **15.0**、macOS **13.0**（原生，不使用 Mac Catalyst）。

## 二、本地构建

```bash
# 生成工程（每次改动 project.yml 或新增文件后重跑）
xcodegen generate

# Lint（与 CI 一致；配置见 .swiftformat / .swiftlint.yml）
#   ⚠️ SwiftFormat 配置键必须以 `--` 开头（0.63 起不再支持 `key = value`）
#   ⚠️ 工具版本要与 CI 一致（当前 SwiftFormat 0.63.0 / SwiftLint 0.65.1），否则规则集不同、结论不可比
#   ⚠️ lint 已是**阻断**步骤：改完先本地 `swiftformat .` 再提交（细节见 docs/任务记录/M00P2-全量格式化.md）
brew install swiftformat swiftlint
swiftformat --lint . --config .swiftformat --exclude .build,DerivedData,ThirdParty,Tools,.swiftpm,Packages/*/.build
swiftformat . --config .swiftformat --exclude .build,DerivedData,ThirdParty,Tools,.swiftpm,Packages/*/.build
swiftlint lint --config .swiftlint.yml

# 各包单测（最快的反馈回路）
swift test --package-path Packages/CatVodCore
swift test --package-path Packages/CatVodNet
swift test --package-path Packages/CatVodSource
swift test --package-path Packages/CatVodPlayer
swift test --package-path Packages/CatVodStore
swift test --package-path Packages/CatVodNode
swift build --package-path Packages/CatVodUI   # UI 包无单测目标，至少编译一把

# iOS（模拟器，未签名）
xcodebuild build -project YPlayer.xcodeproj -scheme YPlayer-iOS \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY=""

# macOS（未签名）
xcodebuild build -project YPlayer.xcodeproj -scheme YPlayer-macOS \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY=""
```

## 三、CI（GitHub Actions）

`.github/workflows/build.yml`，全部在 `macos-15` 上运行，**不签名**：

| Job | 内容 |
| --- | --- |
| `lint` | SwiftFormat `--lint` + SwiftLint（**阻断**：任一违规/待格式化即红） |
| `core-tests` | 逐个包 `swift test` |
| `build` | `xcodegen generate` + iOS 模拟器构建 + macOS 构建 |
| `release` | 打 `v*` tag 时产出未签名 `.ipa` 与 macOS `.zip`，上传 Artifacts 与 Release |

另有独立 workflow `.github/workflows/js2p-contract.yml`（**刻意不挂在 push/PR 上**）：
`workflow_dispatch` + 每周一 cron，真实下载并运行 6.29 MB 的 js2p bundle，断言宿主契约
（硬断言：就绪行端口 + `GET /health`；软断言：站点数 + `POST /spider/<key>/init`）。
原因与证据见 `docs/任务记录/M16P2-宿主站点清单实测.md`：bundle 启动依赖上游远端配置，
上游抖动不应把正常 PR 判红。

要点：

- 首次 `swift package resolve` 会下载 MPVKit 的多个 xcframework（体量大），CI 缓存了 `~/.cache/org.swift.swiftpm`。
- macOS runner 按 **10 倍用量**计费；**公开仓库免费**（本仓库已公开）。若仓库是私有的，注意配额，
  否则会出现：
  `The job was not started because recent account payments have failed or your spending limit needs to be increased`。
  ⚠️ 这类失败**没有任何步骤日志**（run 几秒就结束、日志 blob 都不存在），
  只能从 run 的**注解**里看到原因 —— `Tools/out/run_annotations.py` 就是为它写的。
- 未签名 IPA 的打包方式：`xcodebuild archive … CODE_SIGNING_ALLOWED=NO` → `Payload/` → `zip`。

## 四、分发与安装（非 App Store）

| 平台 | 产物 | 安装方式 |
| --- | --- | --- |
| iOS/iPadOS | `YPlayer-unsigned.ipa` | 自行侧载并重签：Sideloadly / AltStore / TrollStore 等；免费 Apple ID 证书 7 天有效，开发者账号 1 年 |
| macOS | `YPlayer-macOS-unsigned.zip` | 解压后首次打开需**右键 → 打开**；或 `xattr -dr com.apple.quarantine YPlayer.app` |

### 从 Windows 侧载到 iPhone（不需要 Mac）

`build.yml` 的 **`ipa` 作业**每次推送都会产出未签名 IPA：

1. 打开 GitHub 仓库 → **Actions** → 选最新一次 `build` 运行 → 底部 **Artifacts** → 下载 `YPlayer-unsigned-ipa`；
2. 在 Windows 上装 **Sideloadly**（或 AltStore 的 AltServer for Windows）；
3. 用数据线连上设备，把 IPA 拖进 Sideloadly → 填 Apple ID → Start（它会用你的证书**重签** App 与其中的
   `NodeMobile.framework` / MPVKit 的 dylib）；
4. 首次启动前需在设备 **设置 → 通用 → VPN与设备管理** 里信任该开发者证书；
5. 免费 Apple ID 签的证书 **7 天过期**，过期后重跑一次侧载即可。

详见 `docs/任务记录/M03P2-实机验证清单.md`（含「上去之后要看什么」与排查要点）。

## 五、已知的构建陷阱（来自 CI 实测）

1. **Xcode 版本**：`macos-15` 镜像只提供 Xcode 16.x；`macos-14`（唯一含 Xcode 15 的镜像）将于 2026-11-02 停止支持，因此基线固定为 Xcode 16.4。
2. **Swift Testing**：`#expect(...)` 的参数里不要写 `await`，先取出到局部变量。
3. **属性默认值**：有 `public init() {}` 的类型，存储属性必须带默认值，否则报 `'self.x' not initialized`。
4. **macOS 不可用的 SwiftUI API**：`.listStyle(.insetGrouped)`、`.navigationViewStyle(.stack)` 等仅 iOS 可用，用 `#if os(iOS)` 分支。
5. **平台 API 差异**：`CatVodUI` 内的平台差异必须收敛在 `PlatformShims` / 条件编译里，业务代码不要散落 `#if`。
6. **Node 运行时（M1.6）**：原生依赖必须随包内嵌，禁止运行时下载可执行代码（未签名 IPA 侧载后无法加载新 dylib）。
7. **同一个 `concurrency` group 里「排队中」的运行会被新的排队者取消**：`simulator.yml` 用
   `group: simulator` + `cancel-in-progress: false`（保护**运行中**那条），但 GitHub 仍会把
   **pending** 的那条取消。所以连续两次推送时，前一次的 simulator 会显示
   `completed/cancelled` —— 那是被新提交顶掉，不是失败；**以最新提交那条为准**。
8. **Swift Testing 宏里不能调用 `mutating` 方法**：`#expect(list.insert(x))` 报
   `cannot use mutating member on immutable value: '$0' is immutable` —— 先取到局部变量再断言。
9. **测试文件要显式导入被测模块**：同一 package 里只写 `import CatVodCore` 而没有
   `@testable import CatVodSource` 时，会报 `cannot find 'X' in scope`（CI 实测：`AggregateParserTests`）。
10. **SwiftFormat `emptyBraces`**：本仓库配置下空实现要写成 `{ }`（带空格），`{}` 判违规。
11. **多行条件的 `{` 要单独一行**：`if a,\n let b {` 必须写成 `if a,\n let b\n{`（`wrapMultilineStatementBraces`）。
12. **`hoistTry` / `hoistAwait`**：`return .case(try await f())` 判违规 ——
    先 `let value = try await f()`，再 `return .case(value)`。
13. **`private(set)` 只对「声明所在文件」开放 setter**：跨文件写属性（如
    `AppModel+LocalProxy.swift` 写 `AppModel.localProxyPort`）要用 `internal(set)`。
14. **泛型包装会把可选值再包一层**：`read<T>` 的返回值是 `T?`，闭包返回 `Row?` 就得到 `Row??`
    （CI 报 `(Row?) -> Favorite` 类型不匹配）—— 改成 `fetchAll(...).first` 更直观。
15. **FlyingFox 与本包 `HTTPRequest`/`HTTPResponse` 同名**：`CatVodNet` 内的服务端代码必须显式限定
    `FlyingFox.HTTPRequest` / `FlyingFox.HTTPResponse`，否则裸名解析成本包类型，报一致性/成员错误。
16. **逃逸闭包里不要写冗余 `self.`**：结构体里的 `session.onSuccess = { self.finish(...) }` 会被
    `redundantSelf` 判违规，改成**方法引用**（`session.onSuccess = handleWebSuccess`）最省事。
17. **新建模型前先查重名**：本仓库在 M01/M02 阶段已经落了一批「最小集」模型（如 `LiveSource`），
    M7a 阶段新建了同名类型导致重复定义。规矩：**新建前先 `search_codebase` 查类型名**，
    已有就「扩充既有文件」，不要另起一个同名类型。
18. **SwiftLint `function_parameter_count` 上限是 10（error）**：字段多的模型**不要**写长成员初始化器，
    统一走 JSON 解码；确实需要构造时只给最少参数（例如 `LiveChannel(name:urls:catchup:)`）。
19. **Core 的测试用 `import CatVodCore`（普通导入，不是 `@testable`）**：被测的类型与方法必须 `public`，
    否则报 `'x' is inaccessible due to 'internal' protection level`（M7a 的 `looksLikeM3U` 撞过）。
    需要暴露给测试的判定函数就老实标 `public` 并写文档注释。
20. **Optional 存储属性不要写 `= nil`**（SwiftFormat `redundantNilInit` 会拦）。
    但如果因此让「成员初始化器」失去全默认形态（如 `LivePlaylistSettings`），
    就显式写一个 `init() { }` —— 两边都满足。

> 8–16 的根因与修复提交见 `docs/任务记录/M08b-存储接线.md` 与 `docs/任务记录/M05c-Web嗅探与聚合.md`
> 的「验证记录」；Windows 侧可先用 `Tools/out/check_swift.py` 自查（覆盖行长/尾随空白/多行字符串基准缩进/
> 同名遮蔽/空实现 `{}`/多行条件 `{` 六类）。

## 六、维护者提示

- Token 只作为命令行参数传给 `Tools/*.py`，**不要写入文件、不要提交、不要写进 remote 配置**；`github_bootstrap.py` 会在推送后把 `origin` 重置为不含 token 的地址。
  - `Tools/out/` 下的诊断脚本一律走 `Tools/out/gh.py`：环境变量 `YPLAYER_GH_TOKEN` 优先，其次读 git-ignore 的 `Tools/.cache/gh_token.txt`；
    `Tools/out/detoken.py` 可机械扫一遍并把源码里的明文换成运行时解析（改完全部 `py_compile` 校验）。
    仓库是公开的，`Tools/out/` 虽已 gitignore，但一次 `git add -f` 就会泄露，所以**明文不进源码**。
- 日志与缓存：`Tools/out/`、`Tools/.cache/` 已在 `.gitignore` 中。
- **本机（Windows）的 PowerShell PSReadLine 会在输入较长命令时抛
  `System.ArgumentOutOfRangeException`（`SetCursorPosition … top=-1`）并截断/重复命令**，
  于是长命令根本执行不了。绕开方式：把命令写进 `Tools/out/cmd.txt`（每行一条），
  用 `python Tools/out/r.py` 执行，输出落在 `Tools/out/cmd-out.txt`。
- **改 `.ps1` 时必须保留 BOM（UTF-8 with BOM）与 CRLF**：PowerShell 5.1 对**无 BOM** 的
  `.ps1` 按系统 ANSI（本机 GBK）解码，中文注释会被误读成破坏语法的字符 —— 实测表现为
  解析器报 `意外的标记 ")"`（`poll_runs.ps1` 就这样坏过一次）。用脚本批量改这些文件时
  要写 `encoding="utf-8-sig"` 且保持原换行；改完用 `Tools/out/chk_ps.ps1`（只解析、不执行）过一遍。
  - ⚠️ 批量替换时**先把新内容算出来，再打开文件写**：`re.sub` 的替换串里出现 `\.` 会抛
    `re.error: missing <`，而「先以 `"w"` 打开、再在 `with` 里抛错」会直接把脚本**清空**
    （`Tools/out/detok_ps1.py` 第一版就这样误清了 `amend_push.ps1`，已按同类脚本形态重建）。
  - `Tools/out/detok_ps1.py` / `fix_ps_encoding.py` / `scrub.py` 分别负责：
    去掉 `.ps1` 里的明文令牌、修正编码、洗掉日志里残留的令牌。
