# M04P16 换音轨（自研 FFmpeg 内核）

- 状态：**已实现**（本地静态闸门全绿 + 新单测；Mac 编译 / 测试 / 上机待 YG）
- 时间：2026-10-10
- 触发：自研内核最后一个「界面明明有、内核没做」的缺口 —— 播放页的音轨选择对系统 / MPV 内核早就有了，
  自研内核这边 `selectTrack` 是空操作、轨道清单也不报（界面上那组选择压根不出现）。

## 一、做法

1. **开片就把轨道清单报出去**：`emit(.tracks(video:audio:subtitle:))` —— 音频列全部音频流下标，
   字幕报**空数组**（还没做；报空 = 界面不显示那组选择，比摆一个选了没用的控件诚实）。
   换轨**不重报**：重报会让界面把用户刚选的那条复位成「自动」（M04P13 界面那边就是这么处理的）。
2. **换轨请求走解码线程**（与 seek 同一套：控制线程只记账 `pendingAudioTrack`，一段读包的人只能有一个）：
   - `.auto` → 回到容器第一条音轨；`.disabled` → 拆掉解码器（不是静音假装）；`.index(n)` → 切到第 n 条；
   - **新解码器先建好，成了才换** —— 换不过去保留旧轨继续响（不静音、不假装），原因进日志；
   - 换完 flush 音频渲染器：不清的话会先响一段旧轨已排队的存量。
3. **下标要验**：`LibavAudioDecoder.open(input:streamIndex:)` 用 `LibavInput.streamKind(at:)` 验它真是音频流
   （界面传回来的可能是任何东西）。顺手把 `firstStreamIndex(of:)` 改成复用 `streamKind(at:)` —— 一套判定只有一处。
4. **播放信息跟着换**：`audio-codec` 按**当前**音轨报（不照抄打开时的第一条）。
5. v1 口径：**不做重定位** —— 新轨从当前读包位置往后接，不回头对齐到当前时刻（写进类文档的缺口清单）。

## 二、测试怎么证明「真的换了」

夹具加一条**不同采样率**的副音轨（44.1k + 48k），假音频渲染器记下每块样本的采样率：

1. 先把解码循环卡在背压上（一个包都还没读）——断言不必跟解码速度赛跑；
2. 切到第二条（解码线程卡在背压里也会先处理待办）；
3. 放行 → 喂来的样本是 **48k**、且**一块 44.1k 都没有** ✓ 这才是「真的换了」的证据
   （不是「没崩就算过」）。

## 三、故意没做

- 字幕轨（libass 上屏）：整条链还没有；
- 换轨后的重定位（新轨与画面重新对齐）；
- 音轨的「命名」（语言 / 标题）——先把「能换」做出来。

## 四、验证点（Mac）

1. `swift test --package-path Packages/CatVodPlayer`：
   - 「Libav 音频解码」+1：拿视频流下标当音轨 → 明确拦住（既有两条用例改传显式下标）；
   - 「FFmpeg 真会话」+1：换音轨（清单两条 / 48k 证据 / 信息行跟着换）；
2. 全包测试 + App 编译照旧；
3. **上机**：播一集（多条音轨的片子）→ 播放页出现「音轨」选择 → 换一条，声音换成新轨
   （换轨后从当前位置往后接，不回头对齐）。
