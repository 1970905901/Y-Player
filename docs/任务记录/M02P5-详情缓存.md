# M02P5 详情缓存

- 状态：已随 CI 全绿（2026-10-08 统一回填：本行原写「待 CI 验证」；缓存挡板条件与上游的校准仍未做，见矩阵）
- 时间：2026-10-07
- 依赖：M2 的 `CMSClient.detail`、M02P2/M02P4 的详情页与搜索页

## 为什么做

详情页（线路 / 选集）在一次浏览里会被反复打开：列表 → 详情 → 返回 → 再进、切线路再回来。
每次重建请求既慢又容易被站点限流。缓存放在 `CatVodSource`（不在 UI 层），便于单测与后续复用。

## 实现

| 件 | 说明 |
| --- | --- |
| `DetailCache`（actor） | 内存 + TTL；键为 `站点 key + vodID`；FIFO 容量淘汰；带命中/未命中/写入/绕过计数 |
| `DetailProvider` | `CMSClient` + `DetailCache`：缓存命中直接用，否则请求并写入；支持 `forceRefresh` |
| `AppModel.makeDetailProvider()` | 全进程共享一个 `DetailCache` |
| `AppModel.load(forceRefresh:)` | 配置重载成功后 `invalidateAll()`（详情可能对应旧站点/旧线路） |
| `VodDetailView` | 详情页支持**下拉刷新**（`refreshable` → `loadDetail(force: true)`），需要时手动绕过缓存 |

默认参数：`ttl = 300s`、`capacity = 64`。TTL 取得较短，因为**详情里的播放地址多为短时效**，
缓存过久会把过期地址喂给播放器（表现为「能进详情但播不了」）。

## 挡板（不缓存的情形）

1. **设置类 / Spider 站点（`type=3`）**：详情可能携带会话态信息（本地 Node 端口、动态生成的 api/url），
   缓存后重新进入会拿到失效地址 → `shouldCache(site:) == false`，读与写都直接绕过；
2. **失败或空结果**：`msg` 非空（沿用上游「msg 非空视为错误响应」的约定）或 `list` 为空 → 不缓存，
   避免把一次偶发故障固化；
3. **显式失效**：`invalidate` / `invalidateAll` 与 `forceRefresh` 必须能绕过缓存。

> 注意：**没有**把 `code != 0` 当作不可缓存条件。部分源用非 0 的 `code` 表示成功或“有数据的非标准状态”，
> 按 `code` 严格判定会误伤；此处只依赖已被上游文档验证过的 `msg` 规则。

## 与上游的关系（已核对，2026-10-09）

这一节原来叫「待校准（诚实记录）」，挂着三个问题等上游源码。已经查过了，**结论是：没有上游可对齐**：

- `FongMi/TV`（fongmi 分支）的 `app/src/main/java/com/fongmi/android/tv/bean/` 目录里没有详情缓存类
  （按字母序从 `Vod.java` 直接到 `Word.java`，中间没有 `VodDetailCache` 之类）；
- 参考项目 webhtv 那边同样没有。

所以三条挡板是**本项目自定**的，判定依据就是「宁可少缓存」这条原则，不再声明「等拿到源码再校准」。
当初那三个问题则变成我们自己的决定，各自的依据写在这里：

| 问题 | 我们的决定 | 依据 |
| --- | --- | --- |
| 是否对 `type=3` 站点完全跳过 | **跳过** | Spider 详情可能带会话态（本地 Node 端口、按会话生成的 api/url），缓存后重进会拿到失效地址 |
| TTL 取值、是否按站点/分类区分 | **统一 300 秒，不分类** | 详情里的播放地址多为短时效；再细的分档没有证据支持，属于过度设计 |
| 是否缓存「需要解析（`parse=1`）」的地址 | **缓存**（受 TTL 约束） | 缓存的是**详情响应**而不是解析结果，`flag` 通常是站点级而非会话级；真会话级的站点已由第一条整类跳过。若某个 CMS 站点因此出问题：下拉刷新即可绕过（`forceRefresh`），必要时把该站点加进跳过名单 |

这一节留在这里，是为了让后来的人知道**这三个问题被想过、答案是什么、依据是什么** ——
而不是每次都重新问一遍「上游是怎么做的」。

## 验收

- `CatVodSource` 单测 `DetailCacheTests`：命中/键独立/Spider 挡板/TTL 过期/失败与空结果挡板/容量淘汰/失效与强制刷新。
- CI：`CatVodSource tests` + `CatVodUI (build only)` + iOS/macOS 未签名构建。
- 人工：进详情 → 返回 → 再进，第二次应不再发请求（站点日志/代理可见）；下拉刷新应重新请求。

## 回滚

把 `VodDetailView+Data.loadDetail()` 改回 `model.makeCMSClient().detail(...)` 即可；
`DetailCache` / `DetailProvider` 为独立文件，可整目录删除，不影响其它模块。
