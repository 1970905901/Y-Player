# M08g 孤儿类型审计（「实现了、没人用」怎么系统性地找）

- 状态：审计脚本落地，全仓扫过一轮；清掉 3 处死脚手架
- 时间：2026-10-09
- 依赖：无（工具 + 清理）

## 一、为什么需要它

这半天里抓到三个**同一形态**的东西：

- `HLSAdRuleState` 的开关层（M06h 前）：开关算得对、有单测，但没人调用；
- `AggregateParser`（M06d 前）：聚合解析完整实现，零调用点；
- `DanmakuService`（M08c 前）：取用链写好了，界面上没有入口。

共同现象是 **测试全绿、功能不存在**：单测只证明「这个类型自己是对的」，
不证明「有人在用它」。人工 grep 一次只能查一个类型，查不完全仓，
所以把这个判断交给脚本 —— `Tools/out/audit_orphans.py`。

## 二、判定口径（宁漏报，不误报）

1. 只看 **`Sources` 里的顶层类型声明**（`struct` / `enum` / `class` / `actor` / `protocol`，缩进 0）。
   测试里声明的都是夹具，天然没人引用，先排除掉；
2. 引用计数 = 在全部 `.swift`（含 `Apps/` 与 `Tests/`）里按**整词**匹配的次数，**扣掉声明自己的那个文件**；
3. 分两桶：
   - `only-tests`：源码里没有别的文件引用它 → 疑似「实现了、没接上」；
   - `unused`：连测试都不引用 → 疑似死代码；
4. 每行额外报「本文件自用」次数：命中 ≤ 1 的才是真死代码，
   大于 1 说明它在本文件里被用着（例如 `AdaptiveToolbar` 在自己文件里被套用），那就是误报。

已知的一类误报要排掉：`@main` 的入口类型（`YPlayerIOSApp` / `YPlayerMacApp`）**永远不会被引用**，
脚本按「上一非空行是不是 `@main`」跳过。

## 三、这一轮的结果

**只有一处真命中**：`DanmakuPlan` —— 它的消费方是还没写的渲染层（见 `M08d-弹幕调度计划.md`），
属于**已知待办**，不是漏接。其余两个桶里的 10 个名字都是「同文件内自用」的误报。

顺手清掉三处零引用的脚手架：

| 类型 | 位置 | 为什么删 |
| --- | --- | --- |
| `CatVodLog` | Core `Support/CatVodError.swift` | OSLog 的 subsystem 与八个分类常量，零引用。想加分类日志时直接 `os.Logger` 就行，这块脚手架没有价值 |
| `LenientCoercion` | Core `Coding/LenientDecoding.swift` | 单值宽松转换（`string`/`int`/`double`/`bool`），零引用。真正在用的是**容器版**的 `lenientString` 等，这一组是它的遗留 |
| `SiteAvailabilityBadge` | UI `PlatformShims.swift` | 不可用原因徽标，零引用 —— 别处（设置页解析器清单、详情页）都**直接用 `availability.reason` 渲染**，这个包装从没被采纳 |

`PlatformShims.swift` 因此只剩 `accent` 与 `cardCornerRadius`，顺手把三个用不到的 import 也去了。

## 四之二、补充：属性级审计（M06m 之后加的）

类型审计看不见「字段解析进来了、没人读」这一类 —— `doh` / `hosts` 就是这么漏过去的：
它们**有**模型类型（`DohConfig` ✓），类型本身也被 `SourceConfig` 引用着，
所以 `audit_orphans.py` 认为一切正常，而实际效果是「配置写了等于白写」。

补的脚本：`Tools/out/audit_config_fields.py` —— 对 `SourceConfig` 每个 `public var` 字段，
统计 `\.字段名` 在**其它源文件**里的出现次数（不含模型自己），分成「零读取」与「只有测试在读」两桶。

跑出来的第一批结果（M06m 处理完之前）：

```
== 零读取（源码里没人读，测试也不读）：0 个
== 只有测试在读：3 个      flags / notice / wallpaper
```

处理方式写进输出里了，三选一：接上去、加进 `ConfigCoverage.ignored(in:)` 如实上报、或者删掉。
`doh` / `hosts` 走第二条（平台缺口），`flags` / `wallpaper` / `logo` / `notice` 也走第二条（还没接界面）。
处理完之后重跑：**零读取 0、只有测试在读 0** —— 每个字段都有人读，读者要么是功能、要么是那份如实上报。

## 五、怎么读这份报告（工具会误报，也会漏报）

### 一个亲手踩出来的坑：注释被算成引用

`DanmakuPlan` 本来被正确报成「只在测试里出现」，结果某次改动在 `AppModel.swift` 的**注释**里
提了一句它的名字，它就从报告里消失了 —— 计数把注释算成了使用。
现在计数前会先剥掉 `//` 与 `/* */` 注释：注释里提到某个类型，恰恰说明它更需要被发现。

### 两类「看着像孤儿、实际正常」的情况

- **协议 / 工厂的隐式使用**：类型只通过协议被使用，或者只被工厂函数构造，
  名字可能不出现在任何调用点。所以报告是**提示你去查**，不是判决书 —— 每一条都要 grep 一遍再下结论；
- **字段类型**：`SourceConfig.doh` 的元素类型 `DohConfig` 只在测试里被构造，但它是模型的一部分，
  用「字段级」的 `audit_config_fields.py` 看才准。

### 当前（2026-10-09）的报告与判断

`only-tests` 桶：

| 名字 | 判断 |
| --- | --- |
| `DanmakuPlan` | 已知待办：消费方是还没写的渲染层（M08d） |
| `MpvEngine` + `AppDatabase` | 都不是静默孤儿，见下 |

- `MpvEngine`（`CatVodPlayer`）：**渲染路径没定之前不接这条线** —— 这句话写在 `PlayerEngine.swift`
  里，是**有意**留的（见 M03P1 记录），不是漏接；
- `AppDatabase`（`CatVodStore`）：M2 时代为「GRDB 落库」预留的协议 seam，
  M08a 把 GRDB 落库做完之后，**消费方仍拿具体类型**（`GRDBPlaybackProgressStore(database:)`），
  没人改用协议类型。两种收法 —— 把上层改成协议类型（同时让内存实现能顶上），或删掉协议 ——
  哪个更好取决于「磁盘不可用时要不要整库降级」，见 `M08b-存储接线.md` 的遗留，等定了再动；
- `DiscoverFilterChip` / `ParserExt`：**误报**（同文件内自用，报告里的「本文件自用」列 > 1）。

`unused` 桶里每条都带「本文件自用 > 1」，即在自己文件里被用着（如 `AdaptiveToolbar`），同样是误报。

**新增命中就要解释**：要么接上去、要么删掉、要么在注释/记录里写清为什么先留着。
