## 一、为什么需要它

这半天里抓到三个**同一形态**的东西：

共同现象是 **测试全绿、功能不存在**：单测只证明「这个类型自己是对的」，

所以把这个判断交给脚本 —— `Tools/out/audit_orphans.py`。

## 二、判定口径（宁漏报，不误报）

1. 只看 **`Sources` 里的顶层类型声明**（`struct` / `enum` / `class` / `actor` / `protocol`，缩进 0）。
   测试里声明的都是夹具，天然没人引用，先排除掉；
2. 引用计数 = 在全部 `.swift`（含 `Apps/` 与 `Tests/`）里按**整词**匹配的次数，**扣掉声明自己的那个文件**；
3. 分两桶：
   - `only-tests`：源码里没有别的文件引用它 → 疑似「实现了、没接上」；
   - `unused`：连测试都不引用 → 疑似死代码；
4. 每行额外报「本文件自用」次数：命中 ≤ 1 的才是真死代码，
   大于 1 说明它在本文件里被用着（例如 `AdaptiveToolbar` 在自己文件里被套用），那就是误报。

已知的一类误报要排掉：`@main` 的入口类型（`YPlayerIOSApp` / `YPlayerMacApp`）**永远不会被引用**，
脚本按「上一非空行是不是 `@main`」跳过。

## 三、这一轮的结果

**只有一处真命中**：`DanmakuPlan` —— 它的消费方是还没写的渲染层（见 `M08d-弹幕调度计划.md`），
属于**已知待办**，不是漏接。其余两个桶里的 10 个名字都是「同文件内自用」的误报。

顺手清掉三处零引用的脚手架：

| 类型 | 位置 | 为什么删 |
| --- | --- | --- |
| `CatVodLog` | Core `Support/CatVodError.swift` | OSLog 的 subsystem 与八个分类常量，零引用。想加分类日志时直接 `os.Logger` 就行，这块脚手架没有价值 |
| `LenientCoercion` | Core `Coding/LenientDecoding.swift` | 单值宽松转换（`string`/`int`/`double`/`bool`），零引用。真正在用的是**容器版**的 `lenientString` 等，这一组是它的遗留 |
| `SiteAvailabilityBadge` | UI `PlatformShims.swift` | 不可用原因徽标，零引用 —— 别处（设置页解析器清单、详情页）都**直接用 `availability.reason` 渲染**，这个包装从没被采纳 |

`PlatformShims.swift` 因此只剩 `accent` 与 `cardCornerRadius`，顺手把三个用不到的 import 也去了。
