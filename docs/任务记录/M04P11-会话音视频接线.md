# M04P11 会话接上音视频（统一 demux + 双向背压 + 音量）

- 状态：**已实现**（本地静态闸门全绿 + 新单测；Mac 编译与测试待 YG）
- 时间：2026-10-10
- 触发：M04P10 零件齐了。这一步把统一 demux、双向背压、音量接进会话 ——
  **自研内核的完整形态出来了**（还差 seek 与 UI 接线）。

## 一、做法

1. **统一 demux**：解码线程每轮 `input.nextPacket()`，按 `streamIndex` 分发给
   视频 / 音频解码器，再喂各自渲染器；读包失败但不是 EOF（网络抖动）→ 10ms 后重试。
   一段读包、两个解码器 —— 两线程各读各的会打架（M04P10 定的路）。
2. **双向背压**：有音轨时**两侧渲染器都要吃得住**才继续解；纯视频文件不看音频侧
   （没有音频解码器 = 没有那道闸）。
3. **共享时间轴**：会话建 `AVSampleBufferRenderSynchronizer`，
   视频显示层与音频渲染器**都挂上去** —— 音画同步是结构自带的；
   `LibavVideoRenderer(surface:synchronizer:)` 是新的生产入口（单独用仍可自开一条）。
4. **音轨缺失 vs 解不开**：没有音轨 = 正常（就是静默视频）；**有音轨但解码器建不起来
   = load 失败**（不偷偷变默片）。
5. 音量透传给音频渲染器（夹 0...1）；`stats()` 补上 `audio-codec` 一行。
6. EOF：两侧各 `drain()` 一次收干净后才报 `.ended`；`close()` 关两个解码器。
7. 顺手清理：`LibavVideoDecoder.reachedEnd` 删掉 —— 会话改用 `input.isAtEnd` 判尾，
   写没人读的状态不留。

## 二、故意没做

- **seek / 起点续播**（下一个独立片：`av_seek_frame` + 两侧 flush + 显示层清队 + 时间轴重定位）；
- 软解；音轨切换；UI 接线（`FFmpegVideoView` + PlaybackView 分支）——
  **availability 仍 false**，等 seek 补上、上机能播能听再翻。
