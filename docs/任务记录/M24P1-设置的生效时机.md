# M24P1 播放设置「什么时候生效」说清楚

- 状态：**已实现**（纯文案，静态闸门全绿）
- 时间：2026-10-10
- 触发：读设置页代码时发现 —— **内核 / 解码方式 / 本地代理**三项都是「**进入播放页时**读走并生效」的：
  播放页在 `.task` 里建内核（`start()`），此后不会再换内核（换内核要重建播放器、画面会断）。
  于是「改了设置、正在播的那一页没变化」是**预期行为**，但设置页一个字都没说 ——
  用户只会以为「改了没反应 / 改坏了」。

## 一、改了什么

一句话，**两处共用同一份**（`PlaybackSettingsSection.appliesOnNextPlaybackNote`，避免两处各写一句以后飘）：

> 以上三项在**下次进播放页**时生效：正在播的那一页不会中途换内核（换内核要重建播放器，画面会断）。
> 改完想立刻生效，退出播放页再进一次。

- 设在 `PlaybackSettingsSection`（「设置 → 播放 → 内核」与「源地址 → 播放设置」两处入口共用，加了就有）；
- 也挂在「设置 → 播放 → 播放器」那个 Section 的 `footer` —— 那一页**第一行就是换内核的入口**，
  用户在哪儿改的就该在哪儿看到这句。

## 二、为什么只写这三项

弹幕 / 字幕的显示设置走的是另一条路（值 + 闭包传进播放页），**「改了正在播的那一页会不会变」我没有实测**，
所以不在这条文案里下结论 —— 宁可少说一句，也不写一句可能错的说明。
真要看清楚，得在模拟器上改一次字号看画面变不变（属于下次上机的顺手项）。

## 三、故意没做

- 不在播放页加「设置已改，重进生效」的提醒条：那是把一个一次性认知问题变成常驻噪音；
- 不做「改内核自动重启播放」：那是**用户没要求就中断播放**，比不改更烦人。

## 四、验证点（Mac）

1. 「设置 → 播放 → 播放器」：那一块下面应出现「以上三项在**下次进播放页**时生效…」；
2. 「播放器 → 内核」页里（`PlaybackSettingsSection`）同样应有这一句（两处共用）；
3. 顺手确认弹幕字号那条：**改完字号，正在播的页面上弹幕字号会不会跟着变**？
   变了的话告诉我，我把结论补进这份记录（现在的记录里明确写着「没实测、不下结论」）。
