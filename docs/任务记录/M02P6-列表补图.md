# M02P6 列表补图（`/picture`）

- 状态：已随 CI 全绿（2026-10-08 统一回填：本行原写「待 CI 验证」）
- 时间：2026-10-07
- 依赖：M2 的 `ApiURLBuilder.pictureRequest` / `CMSClient.fillingPictures`

## 背景

部分源（`type 0/1/2`）在首页/分类接口里**不返回封面**，需要按 `ids` 再批量取一次图。
此前只实现了 URL 层与客户端方法，界面上从未调用（矩阵里一直标「调用待 M2」）。

## 实现

| 件 | 说明 |
| --- | --- |
| `PictureFiller`（`CatVodSource`） | 判定是否需要补图 + 调用 `fillingPictures`；**best-effort** |
| `AppModel.makePictureFiller()` | UI 侧入口 |
| `HomeView+Data` | 首页与分类加载后补图 |
| `SearchView+Data` | 搜索结果补图 |

判定规则：

1. 列表非空；
2. 站点类型属于 `type 0/1/2`（`type=4` 的 api 是 `ext` 远程文本、`type=3` 走 Spider 通道，均不适用）；
3. **缺图比例 ≥ 阈值**（默认 0.5）——少量缺图不值得多打一次接口。

失败处理：补图请求抛错、或返回空列表时，**原样返回原结果**，绝不因为补图而让列表加载失败或变空。

## 验收

- 单测 `PictureFillerTests`：阈值判定、成功补图（并校验请求含 `ac=detail&ids=1,2,3`）、失败回退、不支持的类型、空列表。
- CI：`CatVodSource tests` + `CatVodUI (build only)` + 两个 App 的未签名构建。
- 人工：用一个缺封面的源看首页/搜索，封面应被补上；抓包应只看到一次补图请求。

## 注意

- `count(where:)` 是 Swift 6 标准库新增（运行期需 iOS 18/macOS 15），本项目最低 iOS 15，
  因此用 `filter { … }.count`（代码里已注明，避免以后被「顺手优化」掉）。
- 补图会**替换** `result.list`（与上游 `fillingPictures` 行为一致），`categories`/`filters` 等字段保留。
