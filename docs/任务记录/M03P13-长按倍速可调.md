- 状态：**已实现**（本地静态闸门全绿 + 新单测；上机由 YG 用 Mac 验证）
- 时间：2026-10-10
- 触发：M03P12 把长按临时加速接上时，「加速到多少」先写死成上游默认 2.0x，并把「可调 + 存档」
  列进故意没做；这一批补全（上游 `SpeedSettingPanel.bindLongPressSpeed` / `syncLongPressSpeedSlider`）。
- 依据：`app/src/main/java/com/fongmi/android/tv/setting/SpeedSetting.java`（`LONG_PRESS_MIN` /
  `LONG_PRESS_STEP` / `clampLongPress` / `getLongPress` / `putLongPress`）、
  `app/src/main/java/com/fongmi/android/tv/ui/dialog/SpeedSettingPanel.java`（「长按倍速」滑杆与「重置」）。

## 一、上游口径 → 本项目

| 上游 | 这里 |
| --- | --- |
| `LONG_PRESS = 2.0` / `LONG_PRESS_MIN = 2.0` / `LONG_PRESS_STEP = 0.5` | `SpeedSetting.longPress` / `.longPressMinimum` / `.longPressStep` |
| `clampLongPress(speed) = Math.clamp(speed, 2.0, 5.0)` | `SpeedSetting.clampLongPress(_:)`（NaN 先挡一道回默认 —— 与 `clamp` 同口径） |
| `setupLongPress(slider)`：2.0–5.0、步进 0.5、标签用 `format` | 播放页「播放速度」区里的「长按倍速」滑杆（同一个 Section，排在预设下面） |
| `getLongPress()` / `putLongPress()`（键 `speed_long_press`） | `PlaybackSpeedBook.longPressSpeed()` / `.saveLongPressSpeed(_:)`（键 `yplayer.playbackLongPressSpeed`）；`resetLongPressSpeed()` 对应上游「重置」里的那半 |
| 「重置」一次把长按倍速回 2.0、跳过静音关、速度回 1.0 | 「恢复 2.0x」（只管长按倍速）+ 既有的「恢复 1.0x」各管一条；跳过静音没做 |
| 拖动中即时写存档（比对后 `putLongPress`） | 同：滑杆只有 7 档（2.0–5.0、步进 0.5），不值得再挂一个「松手才落盘」 |

坏存档口径与倍速一致（`PlaybackSpeedBook` 的既定规则）：**非正数 / 非有限值 → 默认 2.0**；
合法越界值（比如存档里是 1.0）→ `clampLongPress` 夹到 2.0（上游同）。

## 二、一条口径：长按倍速**不下发内核**

`setLongPressSpeed` 只改界面状态 + 落盘，**不调 `engine.setRate`** —— 它只影响「下一次长按」。
当前正在播的速度归 `speed`（「播放速度」那条），两条互不干扰：把长按倍速调成 3.0x 时，
正在播的仍是原来的速度，直到你按住画面。

## 三、故意没做

- **跳过静音**（`speed_skip_silence`）：要内核支持，三个内核都没有对应开关（M02P15 起就没做）；
- **上游「重置」的联动**：上游一个按钮同时重置三项，我们两个「恢复」各自管一条 —— 少一点惊喜；
- **把长按倍速混进「预设」那排按钮**：那 8 档是**播放速度**的档位（上游同），不混。

## 四、验证点（Mac）

1. 播放页 →「播放速度」区：把「长按倍速」滑杆拖到 **3.0x**（右边的值跟着变）；
2. 播放中长按画面 → 顶部提示应当是 **3.0x**（不是 2.0x）、声音明显更快；松手回用户那份倍速；
3. 点「恢复 2.0x」→ 长按倍速回 2.0x（按钮随即置灰）；
4. 退出播放页再进（或杀 App 重开）→ 长按倍速仍是上次存的那档；
5. 存档的脏值不用手试，单测已钉（0 / 负数 / NaN → 回 2.0；1.0 → 夹到 2.0）。
