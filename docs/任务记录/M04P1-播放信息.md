# M04P1 播放信息（M4 的前置：先把画质与流畅度量出来）

- 状态：**已实现**（本地静态闸门全绿 + 新单测；真机由 YG 用 Mac 验证）
- 时间：2026-10-09
- 口径：M4 是「主做 HDR 与流畅度」（见 README）。这两件事**都得先能看见** ——
  分辨率 / 编码 / 色彩（SDR 还是 HDR）/ 实际生效的硬解 / 丢帧数。
  屏幕上没有这些，"画质变好了没""流畅了没"就只能靠感觉吵。
- 依据：mpv 的属性（`video-params/*`、`hwdec-current`、丢帧计数），
  与 M03P5 读 `track-list` 是同一条路 —— 走既有的 `MpvSession.propertyString` seam。

## 一、分两层写（为什么这么切）

| 层 | 文件 | 管什么 |
| --- | --- | --- |
| 纯逻辑 | `CatVodPlayer/PlaybackStats.swift` | 原始字符串 → 人话（`3840×2160` / `HDR · PQ (ST2084) · BT.2020` / `硬件解码（VideoToolbox）`）；**有单测** |
| 内核侧 | `MpvEngine.playbackStats()` | **mpv 的属性名**只出现在这里；读一次快照，不做加工 |

界面上要的每一行都来自第一层，所以「拼错了没」能在 CI 上验，不必等真机。

## 二、三条刻意的判断

1. **HDR 只认 gamma**（`pq` / `hlg`），**不拿色域判**：BT.2020 + BT.1886 的 10bit **SDR** 也存在，
   按 primaries 判会把 SDR 说成 HDR —— 那比不显示更坏。单测里专门钉了这条。
2. **读 `hwdec-current` 而不是设置项**：「设置里选了硬解、实际没启用」是最常见的一种假硬解，
   要能一眼看出来。
3. **读不到就不显示那一行**（不是显示"未知"）：本地文件常常没有码率、没起播时没有色彩信息。
   全空则整个「播放信息」块不出现。

## 三、界面

播放页「播放状态」下面多一块 **播放信息**，**只有认 ``PlaybackStatsProviding`` 的内核才显示**
（当前是 MPV；系统内核 `AVPlayer` 给不出这一套，也不为它硬造）—— 与「轨道」同一口径：
拿不到就不显示，不放空行。

- 行：画面 / 编码 / 帧率 / 色彩 / 解码 / 码率 / 丢帧；
- 起播后自动读一次（等 0.8 秒 —— `video-params` 是 `file-loaded` 之后才填上的，立刻读会拿到一排空）；
- 另有一个「刷新」按钮随时重读。

**为什么不接属性观察做实时面板**：这是「按需快照」要回答的问题（这一路是什么、硬解生效没有），
不是逐帧较劲的统计；每帧刷一遍 UI 在手机上本身就是掉帧来源。

## 四、故意没做

- 不做实时曲线 / 平均帧率 / vsync jitter（等真机 4K 有具体问题再按需加，先不加噪音）；
- 不给系统内核造一套「分辨率 / 编码」（AVPlayer 不报这些；真需要时走 `AVAsset` 另说）；
- 不做「HDR 开关」（那是 M4 渲染侧的活；这一步只负责**如实显示**现在是什么）。

## 五、验证点（Mac）

1. 用 MPV 内核播一集：播放页出现「播放信息」，画面 / 编码 / 帧率 / 色彩 / 解码几行有值；
2. 色彩那行：普通剧集是 `SDR · BT.709`；HDR 片源应当是 `HDR · PQ (ST2084) · BT.2020`；
3. 设置里把解码改成软件解码再播：这行应变成「软件解码」（**这行读的是实际生效值**）；
4. 播一会儿点「刷新」：丢帧那行应当还是「无丢帧」（4K 掉帧的话这里会涨）；
5. 切到系统播放器：这一块整个不出现（不是显示一排空的）。
