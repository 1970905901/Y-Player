# M04P10 音频链路（统一 demux + 音频解码 + 音频渲染器）

- 状态：**已实现**（本地静态闸门全绿 + 新单测；Mac 编译与测试待 YG）
- 时间：2026-10-10
- 触发：M04P9 视频闭环通了。这一步把音频链路的**零件**做齐（会话接线在下一片）：
  统一 demux 入口、音频解码（swresample）、音频块封装、音频渲染器。

## 一、五块

| 类型 / 能力 | 内容 |
| --- | --- |
| `LibavInput.nextPacket()` | **统一 demux 入口**：一只借来的包 + `streamIndex`，`isAtEnd` 标 EOF；`firstStreamIndex(of:)` 抽出来给两个解码器共用（`eofCode` 也收成一处） |
| `LibavVideoDecoder.feed(_:)` | 公接口：喂**已按流过滤**的包（多流复用时只能有一个读包的人，那个人是会话）；`decodeFrames` 保留为单流便利（测试用） |
| `LibavAudioDecoder` | open / feed / drain / close；**swresample 上下文 lazy 建**（第一帧才知道源采样格式与声道布局）；输出统一 **Float32 交错**、采样率不重采样 |
| `LibavAudioSampleBuffer` | PCM → `CMSampleBuffer`（纯函数、可单测）；**内存所有权**：成功后归 block buffer，失败自己收 |
| `LibavAudioRenderer` | `AVSampleBufferAudioRenderer` 薄壳，挂会话给的 `AVSampleBufferRenderSynchronizer` —— 音画同步的结构基础 |

测试夹具升级：`TinyMP4Fixture.write(..., audioSeconds:)` 可加一条 AAC 静音音轨
（写静音时复用 `LibavAudioSampleBuffer` 的封装 —— 生产/夹具同一条封装路径）。

## 二、三条口径

1. **音频不挑硬解、不重采样**：解码本来就便宜；输出采样率 = 输入采样率（换采样率是后面的事）；
2. **交错单一 block buffer**：平面式（每声道一个 block）复杂得多，`AVSampleBufferAudioRenderer`
   接受交错 LPCM，先走简单的；
3. **一段读包、两个解码器**：`nextPacket` 是唯一读包的人，按 `streamIndex` 分发 ——
   两线程各读各的会打架（下一次会话接线就按这条路走）。

## 五、续记（2026-10-10，首轮 Mac 验证）

音频块时长全部大了 **1024 倍**（0.0232s 变 23.8s），衔接断言整片红。原因：
`CMSampleBufferCreateReady` 只给**一条** timing entry 时，那条 entry 的 `duration`
是**每个样本**的时长，CMSampleBuffer 按样本数复制并求和 —— 我把「整块时长」填进去了，
于是 1024 个样本每个都拿到 0.0232s，总时长 23.8s。

修法：entry 的时长填 **1/采样率**（时基直接拿采样率当刻度，整数赫兹，避免微秒截断
在 1024 个样本上放大成毫秒漂移）；`durationSeconds` 参数直接删掉（少一个能填错的参数）。
教训写进 `LibavAudioSampleBuffer` 的注释。
