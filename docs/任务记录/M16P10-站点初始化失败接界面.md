# M16P10 站点初始化失败接到界面（`POST /init`）

- 状态：**已实现**（初始化器多给一份失败清单；接口页「Node 宿主」区块列出；新单测）
- 时间：2026-10-10
- 触发：M16P6 留的口子 —— 「init 失败原因目前只在内存（`failureNote(forBaseURL:)`），**未接到界面**。
  若真机出现「某站点动作全失败」，可以先看这里；后续可并入「接口管理 → Node 宿主」的诊断输出。」

## 一、接在哪儿

- `CatSpiderInitializer.failureNotes()`：整份失败清单（`站点URL：原因`），**按站点排序** ——
  界面每次刷新顺序稳定；只给计数看不出是哪个站点，等于还得去调试器里翻；
- `AppModel.siteInitFailures`（`@Published`）+ `refreshSiteInitFailures()`：进「设置 → 源地址」页时刷一次
  （与 `refreshHostHealth()` 同一次 `.task`）；
- `InterfaceManagementView` 的「Node 宿主」区块：清单非空时给一行橙色说明 + 每条一行。

**为什么不阻断、也不重试**：这两条是 M16P6 定的语义（对齐参考实现：失败只记日志、每个实例只 init 一次），
这次只把「记在哪」挪到用户看得见的地方 —— 行为一行没改。

## 二、为什么放「Node 宿主」里

init 是宿主契约的一步（bundle 侧 `x.post("/init", t.init?.bind(t) || $zt)`），
失败原因和宿主状态放在一起看最省事 —— M16P6 当时的建议就是并到这里，没有另开一页。

## 三、测试

- `CatSpiderInitializerTests` +1：两个站点 init 都失败 → 清单有两条、**按站点排序**、
  每条都带站点 URL 与 `/init` 字样（界面就是照这个列）；
- `HostHealthTests` +1（AppModel 级）：还没跑过站点动作时清单是**空的** —— 不编造。

## 四、留口

- 清单是**「进页面时刷一次」**：页面开着时新出现的失败不会自动冒出来（退出重进即刷新）。真机常刷再看要不要定时；
- 清单只在内存（进程内），重启即空 —— 与宿主状态同一生命周期；要跨重启留存得进日志，那是另一件事。
