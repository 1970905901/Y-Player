# M02P7 接口缓存管理

- 状态：待 CI 验证
- 时间：2026-10-07
- 触发问题：「导入的接口，进行缓存管理了吗？」

## 一、结论（先回答问题）

**此前是「有缓存、没管理」。** 落盘行为一直有，但用户既看不见也清不掉：

| 形态 | 原有行为 | 缺口 |
| --- | --- | --- |
| JSON 配置 | 每次联网；失败才回退 `config-<md5(url)>.json`（标记 `usedOfflineFallback`） | 无清理入口、无占用展示 |
| js2p JS 源 | 先取 `.md5` 比对本地摘要，一致则跳过 6 MB 下载；否则下载 + 校验 + 落盘 `config-<md5>.js` + `.md5` | 换接口后旧 bundle **永久残留**（每个 ≈ 6 MB） |
| 内联 JSON | 不落盘 | — |

缺少的是四件事：**看得到占用/时间、清得掉、有上限、能区分「当前接口」与「残留」**。

## 二、实现

| 件 | 说明 |
| --- | --- |
| `SourceCacheStore`（`CatVodSource/Config/`） | 条目枚举（大小/修改时间/是否摘要文件/是否属于当前接口）、概览 `Summary`（条数、总占用、残留占用、最近更新、人类可读大小） |
| `SourceCacheStore+Cleanup` | `remove(fileName:)` / `clear()` / `pruneOrphans(currentURL:)` / `enforceLimit(currentURL:)` |
| `AppModel` | `sourceCache`、`sourceCacheSummary()`、`clearSourceCache()`、`pruneOrphanSourceCaches()`；加载成功后自动 `enforceLimit` |
| `InterfaceManagementView` | 新增「接口缓存」区块：条目 / 占用 / 最近更新 / 当前接口文件数 / 其他接口残留 + 「清理其他接口的缓存」+「清空全部缓存」（带确认弹窗与结果回显） |

### 策略（刻意写死，避免歧义）

1. **容量上限 64 MB**（约 10 个 JS 源 bundle）：超限时按「最近修改时间从旧到新」淘汰，
   **永不淘汰当前接口的缓存**（否则切回旧接口要重下 6 MB）；若只剩当前接口仍超限则保留并停止淘汰。
2. **区分当前与残留**：文件名由 `ConfigLocator` 唯一生成（`config-<md5(url)>.<ext>`），
   `SourceCacheStore.cacheFileNames(for:)` 复用同一规则（单测断言两者一致），不做第二套命名逻辑。
3. **不自动删残留**：换接口后旧缓存保留（用户可能切回去），由用户点「清理其他接口的缓存」显式回收。
4. **清空缓存不影响站点清单与播放设置**，只是下次加载需重新下载 —— 确认弹窗里写清楚了。

## 三、验收

- 单测：`SourceCacheTests`（条目/当前标记/概览/命名来源）+ `SourceCacheCleanupTests`（清空/清残留/容量淘汰/只剩当前接口时不删/目录不存在时安全空返回）。
- CI：`CatVodSource tests` + `CatVodUI (build only)` + 双端未签名构建。
- 人工：接口管理页应显示缓存条目与占用；点「清空全部缓存」后目录为空、再次加载会重新下载。

## 四、未做（明确记录）

- **缓存 TTL / 自动刷新**：JSON 配置目前是「每次联网 + 失败回退」，没有「N 小时内直接用缓存」的策略；
  上游也没有强制要求，等 M6 本地代理/离线场景明确后再定。
- **详情缓存**（`DetailCache`）与接口缓存是两套：前者内存 + TTL（M02P5），后者是落盘文件（本篇）。
- 缓存内容**未加密**：源配置里可能含用户私有接口地址，已落在 App 沙盒的 Application Support 下（不随备份策略额外处理，留给 M8 与 App 数据管理一起看）。
