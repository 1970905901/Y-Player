# M10h 下载：播放页「下载本集」接线 + 前台驱动

- 状态：**已实现**（本地静态闸门全绿 + 新单测；真机由 YG 用 Mac 验证）
- 时间：2026-10-10
- 触发：排查别的问题时逐行读 `PlaybackView` 发现的 —— 两件事都真：

## 一、「下载本集」从来没接线（点了是假成功）

`PlaybackView.onEnqueueDownloads` 这个交回口（M10f 设计：播放页不认识 `AppModel`）
**没有任何调用点传过它**。于是 `enqueueViaUpperLayer` 走 `guard let … else { return -1 }`，
而调用点写着：

```swift
downloadNotice = added == 0 ? "已经在下载列表里了…" : "已加入下载队列 —— 去「设置 → 数据 → 下载管理」看进度。"
```

`-1` 掉进后半个分支 —— **界面上写着「已加入下载队列」，实际一条都没入队**。

修法：

1. 新增 ``DownloadEnqueueOutcome``（`.added(n)` / `.alreadyQueued` / `.unsupported`）替掉
   `-1 / 0 / n` 三个约定值：漏一种含义编译器就拦，不再有「掉进 else 当成功」这种事；
2. 三个入口接线（都拿得到 `AppModel` 与站点）：
   `VodDetailView.destination(for:at:)`、`SitePlayEpisodeView`、`ParsePlaybackView`；
3. 统一走 `AppModel.enqueueDownloadsAndStart(_:siteKey:title:headers:)`：
   **空站点 key 直接 `.unsupported`**（空 key 会让文件名与去重都失去意义）。

## 二、只有停在「下载管理」页才会推进队列

驱动的唯一入口以前是那一页的 `.task`（代码注释也这么写着）。在详情页点「整部下载」、
在播放页点「下载本集」之后转身去看剧 —— 队列一动不动，用户看到的是「点了没反应」。

修法：驱动挂在 `AppModel` 上（``AppModel/startDownloadDriverIfNeeded()``）：

- **入队即启动**（`enqueueDownloadsAndStart` 里启动；「继续/重试」也启动）；
- **回到前台再启动一次**（`RootView` 的 `.task` 与 `scenePhase == .active`：
  先 `synchronizeDownloads()` —— 上次被挂起/杀掉留下的 `running` 会按 M10b 降级成 `waiting` —— 再启动）；
- 单实例（`downloadDriverTask`，重复调用直接返回；`runDownloadQueue` 自己也有防重入）；
- 跑完再看一眼，还有待办就补一轮（最多两轮），避免「刚跑完又有人入队」漏掉；
- **暂停的不算待办**：`hasPendingDownloads` 只认 `waiting` / `running` —— 用户按的暂停不该被驱动偷偷启动。

顺带两处：

- 详情页「整部下载」不再 `await runDownloadQueue()`（原来要把整条队列跑完才轮到界面），改成入队即返回；
- 「下载管理」页不再独占驱动，只负责 `startDownloadDriverIfNeeded()` + 刷新界面。

## 三、故意没做

- **真正的后台下载**（App 不在前台也继续）：要接后台 URLSession / BGTask，是独立的一片；
  这一版仍然只在前台跑，但不再要求用户停在下载页上；
- 不给驱动加「重试次数 / 退避」：`DownloadQueue` 自己的重试额度够用，多一层只会更难排查。

## 四、验证点（Mac）

1. 播放页点「下载本集」→ 提示应当是「**已加入下载队列 1 条**（应用在前台时会自动下）」；
2. 点完**别去下载管理页**，就待在发现页：几十秒后进「设置 → 数据 → 下载管理」，
   那条应当已经在跑或已完成；
3. 详情页点「整部下载」→ 界面立刻能操作（不再卡住），队列在前台自己往下跑；
4. 在下载管理页把一条暂停 → 去别的 Tab 逛一圈再回来：**它必须还是暂停**（驱动不碰它）；
   点「继续」→ 被驱动接手往下跑；
5. 直播页进播放页点「下载本集」→ 应当提示「这个入口不支持下载（直播 / 临时播放没有站点上下文）」，
   而不是假成功。
