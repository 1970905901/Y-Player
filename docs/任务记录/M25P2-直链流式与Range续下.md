# M25P2 直链：流式落盘与 Range 续下

- 状态：**已实现**（Net 加流式取回能力；执行器直链分块写盘 / 字节账目 / HTTP `Range` 续下；新单测）
- 时间：2026-10-10
- 触发：M25P1 的留口 —— 直链一直是「整份进内存 + 一次写完」：
  大文件顶内存、没有中途进度、半途失败只能整份重下（HLS 早在 M10n 就能续）。

## 一、流式取回：Net 加一层可选能力

与 `HTTPDownloadingTransport`（M06b 大文件落盘）同一套做法：**单独一个协议 + `as?` 探测** ——
站点 / 解析链要的仍是内存里的 `Data`，只有下载器那条路需要分块：

| 类型 | 作用 |
| --- | --- |
| `HTTPStreamingTransport.stream(_:)` | 发出请求、拿到响应头，响应体以块交付 |
| `HTTPStream` | `status` / `headers` / `chunks: AsyncThrowingStream<Data, Error>` / `cancel` |

`URLSessionTransport` 用 `URLSession.bytes(for:)` 实现：`StreamPump` 把逐字节的 `AsyncBytes`
攒成 64KB 一块（每块写一次盘、报一次进度），`cancel` 取消迭代任务 —— 暂停 / 放弃剩余时
必须能把生产停掉，否则生产者还在往无界缓冲里灌（流本身没有「停止生产」的接口）。

## 二、直链落盘：边收边写，先看开头再定去路

`DownloadRunner.download()` 探测到流式传输就走 `downloadStreaming`（`DownloadRunner+Direct.swift`）：

1. 打开响应 → **先 peek 开头**：`#EXTM3U`（容忍 BOM / 空行）= 清单，剩下的收进内存走 HLS 那套
   （清单本来就小）；不是 = 直链文件；
2. 文件这条：分块写盘（1MB 报一次进度），收完按 `Content-Length` 对账 —— 对不上就报错；
3. 没有 `Content-Length` 也能下：对账留空，收到流结束为止。

「说好是清单却没有片段」（服务器抽风 / 认错）的兜底：整份当文件写下去，不丢字节。
传输**不支持流式**时（测试替身 / 小响应）原路不变：整份取回来再判断、再写。

**首验踩坑（这两个检查不能删）**：消费任务被取消时，`AsyncThrowingStream` 的 `next()` 会回
nil（**不抛错**）—— 循环于是「正常」退出，写盘那条接着走「字节数对不上」的对账，把取消当
失败报出去：`PartialStop` 根本没抛、回执里 `receivedBytes` 是 0、文件里已经写下的字节白留。
所以**写盘循环与清单收集循环的后面各补一次 `Task.checkCancellation()`**：取消就是取消，
半途的账目照抛（清单那条还防住「半份清单被当成没有片段、写成一个假文件还报成功」）。

## 三、直链的续下账目：字节 + 真总长

| 字段 | 含义 |
| --- | --- |
| `DownloadTask.receivedBytes` | 已经写进文件的字节数（= 文件大小） |
| `DownloadTask.expectedBytes` | 整份总长（`Content-Length` / `Content-Range` 的真值） |

三处对账全过才续：账目字节 > 0、总长 > 0、**文件大小 == 账目字节**。续下请求带
`Range: bytes=N-`；响应必须是 206，且 `Content-Range` 的**起点和总长**都与账目一致
（`matchesResume`）—— 远端换过文件时总长大概率对不上，拿旧前缀硬拼会拼出一个看不出来的错文件。

对不上（416 / 206 不匹配 / 远端不认 Range 直接回 200）的处理：**清掉账目、整份重下一次**
（只重来一次，再不对就报错）。`append` 写之前先 `truncate(atOffset:)` 到账目长度 ——
多出来的尾巴是上次写了一半的块，截掉重写。

HLS 那条路不变（片段数 + 清单前缀指纹）：中途的 `expectedBytes` 仍然传 0（不拿前缀冒充总量）；
直链的 `expectedBytes` 从第一块起就是真值，进度条能显示真百分比。

## 四、测试

- 直链流式：分块写盘、按 `Content-Length` 对账、进度终点带真总量；
- 2MB 大直链：没收完就报进度，分母是真总长；
- 暂停在半途（慢源 + 取消）：回「已暂停」、不吃重试额度、文件与账目都留下（文件大小 == 账目）；
- 断线（2 块后断）→ 重试带 `Range` 从断点续，拼回整份；
- 远端总长变了（206 对不上）→ 整份重下，不硬拼；
- 远端不认 `Range`（整份回 200）→ 账目作废、整份重写；
- 流式传输下的 HLS：清单收进内存、分片逐片取（真传输两条协议都过）；
- Net 端到端：`URLSessionTransport.stream` 从本机服务取回 200KB，块拼起来就是整份。

## 五、留口 / 故意没做

- **块粒度写死 64KB**（Net）、**进度步长写死 1MB**（执行器）：先够用，不做可调；
- **多连接分块下载**（并行 Range）没做 —— 单连接顺序下载；
- **重定向**照旧交给 `URLSession`：Range 跨重定向保持与否由系统行为决定，没有额外处理；
- 后台下载 / 限速仍是留口（M10a 记过）。
