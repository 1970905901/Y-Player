# M16P8 播放失败页可重试

- 状态：**已实现**（本地静态自检过；真机由 YG 用 Mac 验证）
- 时间：2026-10-09
- 触发：撞上宿主 `/play` 500 与网络瞬断时，失败页只有一句红字，只能退出去重进
- 口径：**只给瞬态失败挂重试** —— 宿主、网络、解析这类「再试一次可能就好了」的；
  「站点类型不支持」这种终态失败不挂（点一百次也不会变）

## 一、三处失败页

| 位置 | 失败原因 | 重试动作 |
| --- | --- | --- |
| `SitePlayEpisodeView` | 站点 play 接口失败 / 宿主 500 | `retryLoad()`：清 `errorText` + `parseFallback`，重新 `loadResource()` |
| `ParsePlaybackView` | 解析链失败（JSON / Web 嗅探 / 聚合） | `retryResolve()`：清 `errorText` + `jsonFailure` + `webFailure`，重新 `resolve()` |
| `PlaybackView` 错误区 | 引擎起不来 / 资源加载失败 | `retryPlayback()`：`engine == nil` 就整条 `start()`，否则 `loadActiveResource()` |

清干净上一次的结论是关键：这些状态同时驱动「显示失败页 / 显示进度」，
不清就会闪回旧错误，看起来像没重试。

## 二、排查指引

宿主类失败（`SitePlayEpisodeView`）多一句 `hint`：

> 宿主细节在「设置 → 源地址 → Node 宿主 → 查看宿主输出」；宿主卡住可以在那里重启，回来点「重试」。

`UnsupportedPlaybackView` 因此多了两个参数（都带默认值，老调用点不受影响）：

- `onRetry: (() -> Void)?` —— 给了才显示按钮；
- `hint: String?` —— 给了才多一个「排查」区。

顺手删掉该视图里过期的「相关计划：M5 解析链」文案（M5 早做完了，留在失败页上只会误导）。

## 三、故意没做

- 不做自动重试 / 退避（网络刚断时自动重试会连着打宿主，日志全是噪音；让用户自己决定要不要再试）；
- 不记重试次数、不做「试了 3 次还不行」的降级提示（暂时没这个需求）；
- 「站点类型不支持」失败页保持原样：一个按钮都不给。

## 四、验证点（Mac）

1. 播放页故意制造失败（比如把宿主停了再点某一集）→ 失败页有「重试」按钮 + 排查区；
2. 把宿主重启回来，点「重试」→ 能正常播；
3. 解析类失败（`ParsePlaybackView`）同理，点重试能重走解析；
4. 切到「站点类型不支持」的那种条目 → 失败页**没有**重试按钮。
