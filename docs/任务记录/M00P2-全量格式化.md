## 一、工具与版本一致性（关键）

- CI 用 `brew install swiftformat` → **0.63.0**；本地必须同版本，否则规则集不同、结论不可比。
- 0.63.0 的 release 资产里 **Windows 只有 MSI**（`SwiftFormat.amd64.msi`）。免安装取二进制：
  `msiexec /a SwiftFormat.amd64.msi /qn TARGETDIR=<dir>`
  → 解到 `<dir>/PFiles64/nicklockwood/SwiftFormat/swiftformat.exe`（无需管理员权限）。
- 本地命令见 `Tools/out/sf_run.ps1`（`-mode lint|format`），实质是：
  `swiftformat [--lint] . --config .swiftformat --exclude .build,DerivedData,ThirdParty,Tools,.swiftpm,Packages/*/.build`

## 二、规则决策（逐条给出理由）

**采纳（工具自动修）**：`trailingCommas`、`numberFormatting`、`spaceAroundOperators`、`emptyBraces`、
`blankLinesBetweenImports`、`redundantGroup`、`blankLinesAtStartOfScope`、`linebreaks`、`trim-whitespace`、`indent`。

**关闭（我们的刻意风格，写进 `.swiftformat` 并注明理由）**：

| 规则 | 关闭理由 |
| --- | --- |
| `wrapPropertyBodies` | 刻意用单行计算属性（`var displayName: String { "MPV" }`），展开会显著变胖 |
| `redundantReturn` | 保留显式 `return`：多分支返回值对齐更清楚 |
| `hoistPatternLet` | 保留 `case let .x(y)` 写法 |
| `wrapIfStatementBodies` | 单行 `if x { return }` 在守卫式代码里更紧凑 |
| `conditionalAssignment` | 保留语句式赋值（与 `#available` 分支、注释混排更直观） |
| `opaqueGenericParameters` | 会改公开 API 的泛型形态，属设计决策，不该由格式化工具决定 |
| `docComments` | 有意混用 `///`（公开 API）与 `//`（实现说明） |
| `swiftTestingTestCaseNames` | 测试函数名保持 ASCII 驼峰，便于检索 |

另有 `--ifdef no-indent`：`#if os(...)` / `#available` 块内不额外缩进（见 `docs/UI 规范.md`）。

## 五、教训

1. **格式化工具必须与 CI 同版本**，否则「本地 0、CI 一堆」。
2. **不要用全默认规则集**：`--disable` 逐条写清理由，比事后争论便宜。
3. **核心/协议层代码经得起自动改写**（本次 59 文件全部通过单测与双端构建验证）；
   但**公开 API 形态、文档注释风格**这类「设计决策」要显式排除在工具之外。
4. **格式化会改变测试代码的「宏可编译性」**：见下一节的 `preferKeyPath` 事故。

## 六、全量格式化暴露/踩到的两个坑（已根治）

### 1. SwiftFormat 与 SwiftLint 的规则冲突（必须指定唯一权威）

| 冲突点 | SwiftFormat 默认 | SwiftLint 规则 | 处理 |
| --- | --- | --- | --- |
| 修饰符顺序 | `public nonisolated` | `modifier_order` 要求 `nonisolated` 在 `public` 前 | **权威定为 SwiftLint**：关闭 SwiftFormat 的 `modifierOrder`，并把被翻回的 11 处改回 `nonisolated public` |
| 多行 `if` 的 `{` | 放在**下一行** | `opening_brace` 要求同一行、前置一个空格 | **权威定为 SwiftFormat**：把 `opening_brace` 加入 SwiftLint `disabled_rules`（并注明理由） |

教训：两个工具同时开、又不指定权威，就会出现「改 A 破 B」的循环。**每条冲突必须写清谁说了算**。

### 2. Swift Testing `#expect` 宏 × rethrows/key-path（把测试带崩过一次）

`#expect(...)` 会把裸函数调用展开成 `Testing.__checkFunctionCall(x.self, calling: { $0.method($1) })`。因此：

- **裸调用 + `rethrows`（`allSatisfy`/`filter`/`first(where:)`/`contains(where:)`）+ key-path 参数** → 展开出的闭包变成 throwing，报
  `macro expansion #expect:2:3: error: call can throw, but it is not marked with 'try'`；
- 而 **比较式**（`#expect(lines.map(\.name) == [...])`）不受影响（宏不做 `__checkFunctionCall` 展开）。
- SwiftFormat 的 **`preferKeyPath`** 会把 `{ $0.x }` 自动改成 `\.x`，于是「本来能过的测试」被格式化带崩。

处理：① 这类断言一律**先在宏外算好**再断言（`let ok = xs.allSatisfy(\.x); #expect(ok)`）；
② 关闭 `preferKeyPath`（理由写进 `.swiftformat`），从源头避免复发。
