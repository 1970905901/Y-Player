## 三、差异与取舍

1. **收藏存 `UserDefaults`，不是 GRDB**：上游把收藏放 SQLite（同一张 `Keep` 表还放点播收藏）。
   本项目点播收藏已经有 `FavoriteStore`（GRDB），直播收藏是「几十条以内、只做整表读写」的小数据，
   先按 `LiveKeepBook` 那套存 JSON；等真要做「收藏排序 / 跨设备同步」再迁 GRDB（M08a 的存储层已备好）。
   这条偏离了 M02P14 里「GRDB 留给收藏这类需要查询的数据」的说法，理由与迁移时机写在这里。
2. **钥匙只有频道名**：上游也是（`applyKeepsToGroups` 拿 key 集合去匹配 `channel.getName()`）。
   所以源改了频道名 = 收藏失效，`LiveFavorite.group` / `logo` 只是「清单还没加载」时的显示快照，
   **不参与匹配**。
3. **「收藏」是运行时分组，不进清单**：上游真的往 `List<Group>` 里插了一个组（Java 引用共享频道对象），
   我们的 `LiveSource` 是解析结果的纯值，不去改它，而是现算 `liveFavoriteGroup` + 让
   `selectedLiveGroupObject` 按名字认它。少改一处共享状态，代价是 `selectedLiveGroup` 里可能存着
   「收藏」这个名字（收藏清空后自动回落第一个真分组）。
4. **同名撞车**：源自己就有一个叫「收藏」的组、又不在首位时会出现两行同名 —— 上游有同样的毛病
   （只在第 0 组判断 `isKeep`），不额外发明规则，只把行为记下来。
5. **加密分组两道闸门都在模型里**：不给收藏、不记「上次观看」都写在 `AppModel+Live`，
   界面只管调用 —— 免得以后多一个入口（节目单页、搜索页）就漏一条。
6. **收藏组里的频道用清单那一份**：地址 / header / 时移 / EPG 都随清单刷新；播放页写「上次观看」时
   再按频道名回查它真正的组（`LiveKeep.locate`），所以从收藏组点进去记录的仍是「央视@@@CCTV-1@@@线路」。

## 四、验收

- 本机自检：`Tools/out/check_swift.py`（+ `scan_report.py` 过滤工作区 CRLF 噪音）、
  `Tools/out/check_wrap.py`、`Tools/out/check_fixtures.py`。
- CI：Lint + SwiftPM tests（含 `CatVodUI`/`CatVodUITests`）+ 双端未签名构建。
- 人工（需真机 / Mac）：
  1. 频道行**长按**（iOS）/ **右键**（macOS）→ 出现「收藏」；装完这一条分组条最前面多出「收藏」组；
  2. 「收藏」组里列出刚收藏的频道，**顺序与清单一致**；行尾有小星标；
  3. 再长按选「取消收藏」→ 从收藏组消失；收藏清空后「收藏」这一组整个不见、自动回落第一个真分组；
  4. 加密分组（组名带 `_密码`）里的频道：长按**没有**收藏菜单项可以落地（点了也不生效），
     进去看过也不会出现在「继续观看」（不记 keep）；
  5. 从「收藏」组点一个频道进去看 → 退出后「继续观看」显示的是它**真正**的分组（而不是「收藏」）；
  6. 杀掉进程重开 → 收藏仍在（落 `UserDefaults`）；点按频道行仍然能正常进播放（长按菜单不该抢走点击）。
