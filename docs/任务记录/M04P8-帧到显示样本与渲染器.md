# M04P8 帧 → 显示样本 + 显示层渲染器

- 状态：**已实现**（本地静态闸门全绿 + 新单测；Mac 编译与测试待 YG）
- 时间：2026-10-10
- 触发：M04P7 能解出 `CVPixelBuffer` 了。这一步把「帧 → 显示」之间的基础设施立起来：
  样本转换、画面目标（显示层）、时间轴渲染器。接会话/界面留到下一片。

## 一、三块

| 类型 | 职责 | 可测性 |
| --- | --- | --- |
| `LibavSampleBuffer` | `CVPixelBuffer` → `CMSampleBuffer`（纯函数） | ✅ 手造 pixel buffer 直接验 |
| `FFmpegVideoSurface` | `AVSampleBufferDisplayLayer` 的容器（同 `MpvVideoSurface` 套路） | 编译级 |
| `LibavVideoRenderer` | 喂帧（含转换）+ 背压信号 + 时间轴（play / pause / 倍速 / flush） | 冒烟级 |

三个口径：

1. **presentation 交给系统**（M04P5 记录的首选路径）：demux / 解码我们做，
   HDR/EDR 输出、帧调度、倍速由 synchronizer + 显示层管；
   将来音频挂**同一条** synchronizer（`AVSampleBufferAudioRenderer`）—— 音画同步结构自带。
2. **微秒时基**（不是 600）：每帧 pts 是绝对时间，微秒截断不累积漂移；
   600 对 23.976fps 这类帧率除不尽。
3. **转换失败只跳那一帧**，不炸链路（`enqueue` 返回 false，调用方继续）。

## 二、故意没做

- **宿主视图**（`FFmpegVideoView` / `CatVodUI` 侧）：等会话接线时一起做，
  不然就是一个谁都不用的 UI 空壳；
- 会话接线（`LibavFFmpegSession`）与音频：下一片起；
- HDR 实测：颜色附件由 `CMVideoFormatDescriptionCreateForImageBuffer` 从 pixel buffer 带出，
  真不真得上机用 M04P2 的「色彩 / 输出」两行验。
