# M10e 下载接线与队列驱动

- 状态：`AppModel` 接线（存储 / 状态 / 入队 / 暂停继续删除 / 队列驱动）落地，5 条集成测试；
  **本地地址接管与任务列表未做**
- 时间：2026-10-09
- 依赖：M10a（规则）、M10b（落库）、M10d（执行器）

## 一、库是唯一来源

`downloadTasks` 只是**库的镜像**：任何写入都先落库、再刷新（与收藏 / 播放进度同一套）。
这样界面读到的永远是「库里的样子」，不会出现「界面上有、重启就没了」——
`survivesReopen` 那条测试专门钉这一点（跑完一条 → 用同一份存档重开 → 任务还在、状态还是完成）。

## 二、驱动：一轮一轮跑，不重入

`runDownloadQueue()`：挑 ``DownloadQueue/nextToStart(_:limit:)`` 能启动的 → **并发**跑
（并发上限在那边定义）→ 收结果 → 再看还有没有可启动的，直到没有为止。

- **先落库再开跑**：界面立刻显示「下载中」；万一这时被系统杀掉，库里存着 `running`，
  M10b 的恢复策略下次读出来会把它降级回排队 —— 不会卡住并发位；
- **不重入**：已经在跑就直接返回 0，否则同一批任务会被起两遍；
- **用户中途删掉的那条**：执行结果不再写回，反而把它刚落下的文件删掉 ——
  否则「删除」之后空间占用不动，看着像没删掉。

## 三、测试怎么做到不联网

`AppModel.init` 新增两个注入点：`downloadDirectory` / `downloadTransport`（默认都用真的）。
夹具 `AppModelFixture` 把下载目录放进自己的临时目录、并允许塞一个假传输 ——
于是「入队 → 驱动 → 落盘 → 删除」「暂停不会被驱动启动」「重开模型任务还在」
「HLS 分片拼成一个 `.ts`」这些都能真的跑一遍，不必等真机。

## 五、留口
