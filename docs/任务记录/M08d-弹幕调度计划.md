# M08d 弹幕调度计划（轨道 / 出入场 / 追尾）

- 状态：调度层完整落地并有 8 条单测；**渲染（把计划画到视频上）仍未做**，需要设备或模拟器验证
- 时间：2026-10-09
- 依赖：M08a（弹幕行解析）、M08c（接线，行已经在 `AppModel.danmakuLines` 里）

## 一、为什么先做调度

弹幕链只剩「上屏」。而「上屏」里，**渲染**（覆盖层、字形、描边）在这台机器上验不了；
**调度**（哪条进哪条轨道、什么时候出现、位置怎么随时间变）却能验 —— 而且它是弹幕里唯一
「算错了肉眼也难发现」的部分：两条叠在一起、或一条还没划完就被下一条追尾，
肉眼只看到「有点乱」，说不上哪里错。规则本身是纯几何，所以先把它做掉、钉住。

## 二、规则

`DanmakuPlan.Layout`：屏宽高 / 行高 / 顶部底部各留几条 / 滚动时长 / 停留时长 / 最小间隙。
滚动区轨道数 = 总轨道数 − 2 × 保留数，**至少 1 条**（高度再小也不会算出 0 或负数）。

`WidthProvider`：**文本宽度由渲染层注入** —— Core 里没有字体度量。注入还有第二个好处：
单测给「固定宽度」就能断言几何，结果与字体彻底解耦。

排布是**一次性的**（O(行数 × 轨道数)），规则如下：

1. 前一条的**尾巴完整进场**（留出 `gap`）才允许后一条进同一条轨道；
2. 新的那条**追不上**前一条 —— 时长固定 ⇒ 宽弹幕更快，窄的追宽的是真会发生的事。
   两者的横向间隔只会在「前一条离场」那一刻最小（速度恒定、间隔单调）⇒ 只查那一瞬间。
   加上条件 1 查的是进场那一刻，两个端点都覆盖到了，中间不会更小；
3. 顶部 / 底部只看轨道空不空（停留时长 = 占住这条轨道），不做横向碰撞；
4. 排不下就**丢掉**：宁可少显示，也不要叠着。

两个刻意的实现取向：

- **横向位置是时间的函数**（`scrollX(for:at:layout:)`）而不是存在条目里 —— 否则每帧都要造一堆新条目；
  附带好处：暂停/拖动进度条时，弹幕位置自动跟着播放时间走，不需要额外对齐逻辑；
- 查询是**二分 + 窗口回扫**（计划按 `start` 有序、每条时长不超过 `maxDuration`），
  几万条弹幕也不会每帧全扫。

## 三、测试

`DanmakuPlanTests` 八条：

- 轨道数（含「高度不够时保底 1 条」）；
- 出现 / 退出窗口（开始前、窗口内、结束后）；
- 横向几何：进场时左边缘在屏宽处、离场时整条已滑出左侧、速度 =（屏宽 + 文本宽）/ 时长；
- 同轨道相邻两条：后一条进场时，前一条的尾巴必须已经完整进场（留出间隙）；
- **追尾**：后一条更宽（因此更快）且时间很近时，必须换道；
- 顶部 / 底部：停留期间占住轨道、结束后可复用；
- 顶部 / 底部挤满、滚动区挤满：多出来的丢掉。

## 四、遗留

1. **渲染**：覆盖层（`Canvas` 或 UIKit）每帧取 `items(at: 播放时间)` 并按 placement 画；
   字体度量接进 `WidthProvider`；描边用 `shadowColor`（M08a 已解析）。需要设备/模拟器验证；
2. 弹幕开关的「开关后立刻清屏」语义：现在开关只影响加载，不影响已经排好的计划 ——
   渲染落地时一并理顺（计划丢了、屏上自然就没了）；
3. 真机 smoke：某集弹幕上屏且不叠；暂停时弹幕停住、拖动后弹幕跟着跳。
