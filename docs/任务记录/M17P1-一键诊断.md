## 一、接口管理页：补「缓存大小 / 拉取时间」

原来的「状态」区只显示 `摘要 35dcc10d…`（前 12 位）与缓存文件名。摘要只说明**是哪一份**，
判断新旧要看**什么时候拉的、多大**。现在补两行（`CachedFileFacts`：大小走既有的
`StorageSpace.format`，时间统一 `yyyy-MM-dd HH:mm:ss`）。

> 这一条正是被「导入之后还是 8 月 1 日那版」问住的：当时要是有「拉取时间 = 今天 23:56」，
> 一眼就知道**磁盘是新的**，该往宿主 / 上游那边查，而不是怀疑下载。

## 二、设置 → 数据 → 日志管理：新增「诊断」区 + 复制诊断信息

一段纯文本进系统剪贴板（`PlatformShims.copyToClipboard`：iOS `UIPasteboard` /
macOS `NSPasteboard`，平台差异只在这一个 shim 里）。模拟器与 Mac 剪贴板是通的，
复制完直接在 Mac 上粘贴。

报告分七段：

```
Y-Player 诊断报告
生成时间：2026-10-10 09:12:33
App：0.1.0 (1)
系统：Version 26.5 (Build 23F79)

【接口】类型 / 地址 / 摘要 / 拉取时间 / 缓存大小
【播放】内核 / 解码 / 内核可用性（libmpv、Libavcodec）
【下载】共 N 条：下载中 / 排队 / 暂停 / 完成 / 失败
【宿主】状态 + 最近 12 行输出
【失败记录】本地库等失败信息（没有就写「（无）」）
```

两条硬规矩（都写进代码注释、单测覆盖）：

1. **脱敏**：接口地址只留 `scheme://host[:port]/path`，**查询串整体抹掉**（常带 token）；
   不是 http 地址（内联 JSON 配置）**不给原文**，只写「（非 http 地址，已省略）」——
   宁可少一行，也不把配置正文贴出去；
2. **缺什么写「—」**：不编默认值。报告的价值就在于别让人猜。
   下载那行**只数数、不列任务名**（任务名里是片名）。

渲染是纯函数（`DiagnosticsReport.text`，不碰文件与网络），所以能单测；
采集那一半在 `AppModel.diagnosticsReport(now:)`，`now` 只为测试注入。

## 三、故意没做

- 不做「上传诊断」：不引入任何网络上报，复制粘贴由用户自己决定；
- 不在报告里塞播放信息（分辨率 / HDR / 丢帧）：那是播放页的瞬时状态，
  要进报告得把它提到 `AppModel` 上，属于下一片（M4 真机验证时会更需要）；
- 不导出「网络请求日志」：目前只有宿主日志，网络层的结构化日志还没落地。

1. 「设置 → 数据 → 日志管理」→「诊断」区 → 点「复制诊断信息」→ 下方出现「已复制 N 行到剪贴板」；

## 五、Mac 首验踩的坑（`8e8b87e` 的后续修复）

**`public extension` 里的成员默认是 public —— 报告类型是 internal，编译器直接拦。**

```
AppModel+Diagnostics.swift:12: error: method must be declared internal because its result uses an internal type
```

`DiagnosticsReport` 只给设置页的诊断区用，没必要抬成 public；把 extension 写成普通
`extension AppModel { … }` 就行（成员回到 internal）。**同一类错这轮踩了两次**
（M10h 的 `DownloadEnqueueOutcome`、这次的 `DiagnosticsReport`），两次都是「public 位置 + internal 类型」。

试过在 `Tools/out/check_lint.py` 里加个近似扫描，**当场放弃**：这类判定需要看嵌套类型、
成员可见性、方法体边界，朴素扫描在现有代码上误报 35 处（嵌套 `Kind`、`Entry`、
方法体里的类型全被算进去）。结论不变：**这是编译器错误，本机抓不到 —— 只能靠
`swift test --package-path Packages/CatVodUI` 先跑一遍**（这次就是它拦住的，比 xcodebuild 快得多）。
