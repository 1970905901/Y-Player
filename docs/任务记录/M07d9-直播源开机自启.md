# M07d-9 直播源的开机自启（boot）

- 状态：**已实现**（本地开关 + 启动落「直播」Tab；`LivePassBook` 顺带泛化成两个开关共用；新单测）
- 时间：2026-10-10
- 触发：M07d-1 的留口（「`LiveSetting` 里的其它字段……开机自启 `boot` 的本地开关留到下一步」）。
  上游语义很清楚：`Live.boot` 带这个字段 → 启动时 `ConfigEvent.BOOT` → `HomeActivity` 打开 `LiveActivity`。

## 一、对齐上游

| 上游 | 本仓库 |
| --- | --- |
| `Live.boot`（`bean/Live.java`） | `LiveSource.boot`（M07c 复核字段表时已解析进来） |
| 直播源列表里的自启开关（`Live.boot(boolean)`，图标 `ic_live_boot` / `ic_live_block`） | 「直播设置 → 启动 → 开机自启」开关（M07d-9）；本地覆盖写在 `liveBootOverrides` |
| `ConfigEvent.BOOT` → `HomeActivity` 打开 `LiveActivity` | `RootView` 启动 `.task`：`liveBootEnabled` → `selectedTab = .live` |

## 二、两个决定

1. **本地覆盖而不是改源**：源配置是只读的（与 M07d-5 的 `pass` 同一条），所以「源里写了 `true`、
   用户想关」也能关 —— 覆盖按源名存，两个方向都写得进；
2. **顺带把 `LivePassBook` 泛化成 `LiveSourceFlagBook`**：`pass` 与 `boot` 是同一个数据形状
   （源名 → 显式布尔覆盖），复制一份就成了第二个权威实现；现在两个消费方共用这一份，
   单测也从「pass 专属」改成通用的「布尔覆盖存档」。

## 三、接线

- `LiveSettingsView` 新增「启动」一栏（Toggle 两个方向都写覆盖；没有直播源时置灰）；
- `RootView` 加 `RootTab` + `TabView(selection:)`：启动 `.task` 里**配置加载完之后**判定
  （`loadSavedSourceIfNeeded()` → `if model.liveBootEnabled { selectedTab = .live }`）——
  `boot` 来自配置里的直播源，判早了拿不到。

## 四、测试

- `LiveSourceFlagBookTests`（由 `LivePassBookTests` 更名）：存档 JSON 往返 / 坏存档当空 / 清掉覆盖；
- `LiveBootTests` 3 条：默认跟源的 `boot`、本机覆盖能关掉且**重开还在**（不被源字段盖回来）、
  两个方向都能拨且按源名分桶、源没写就是关（不猜）。

## 五、留口 / 故意没做

- **不自动起播**：只落在「直播」Tab，不自动打开某个频道 —— 进页面就出声是打扰
  （与 M07c-3「继续观看不自动开播」同一条口径）；
- 上游 TV 端还有「设为桌面启动器」那种系统级自启，iOS / macOS 没有对应物，不做。
