# M08f 偏好存储注入（`defaults` 读写都走注入的那个）

- 状态：`AppModel` 的 22 处 `didSet` 全部改走注入的 `defaults`；往返测试已补
- 时间：2026-10-09
- 依赖：M08e（夹具暴露了这个洞）

## 一、怎么发现的

做 M08e 的夹具时顺手看了一眼：`AppModel.init(cacheDirectory:defaults:)` 收得下 `defaults` 注入，
各 `@Published` 的读取也确实走它 —— 但**写入**全是 `UserDefaults.standard.set(...)`，
一共 22 处，全在 `AppModel.swift`。

后果很具体：注入只对**读取**成立。测试里写出去的偏好落到**真存档**里，而它自己再回读又读不到
（回读读的是注入的那个）——所谓「隔离的存档」是假的，夹具也就验不了「写进去 → 重开还在」。

生产上没出问题纯属巧合：默认注入的就是 `.standard`，两边恰好是同一个。**这属于「靠默认值掩盖的
语义不成立」**，一旦有人真的注入别的 store（测试、多用户、以后的分区存储）就会踩。

## 二、改法

1. `defaults` 存成属性：`let defaults: UserDefaults`，`init` 里 `self.defaults = defaults`；
2. 22 处 `UserDefaults.standard.set(` → `defaults.set(`。

第 2 步交给 `Tools/out/fix_defaults_store.py`（带 `--check`，先报数量再改）而不是手工：
**同形替换最怕漏掉一处**，而漏掉的那一处正好就是「某个偏好仍然写进真存档」这个 bug 本身 ——
用脚本 + 数量核对，比「我觉得我改完了」可靠。

改完 `grep UserDefaults.standard` 只剩两处，都在本文件新增的注释文字里（说明为什么不再用它）。

## 四、遗留

1. 其他 UI 文件里若有各自的 `UserDefaults.standard`（如少量独立缓存），口径仍是分散的 ——
   目前没有需要注入的场景，先不动。将来要统一，方向是「AppModel 持有唯一的 store，别的都从它拿」；
2. `keys` 与默认值的表（`StorageKey`）没有集中测试：某个 key 改名而忘了迁移，表现是「设置被重置」。
   现在没有迁移需求（还没发过版），等有版本升级动作时再补；
3. 类体 367 行还在警告区。想真正降下来得把 `@Published` 的存储本身拆出去（存算分离），
   那是结构性改动，不在这一笔里。
