## 二、为支撑这两屏新增的数据

| 件 | 说明 |
| --- | --- |
| `PlaybackEntryMetadata`（CatVodStore） | 播放记录的展示元数据：片名 / 封面 / 站源 / 线路 / 集名 |
| `PlaybackProgressContext`（CatVodStore） | 「键 + 集下标 + 元数据」三件套；`PlaybackView` 由 3 个参数收敛成 1 个 |
| `PlaybackProgress.metadata` | 进度记录带上元数据（并有 `displayName`/`siteName`/… 透传属性）；老记录为空串，界面按空值降级 |
| `Favorite` + `FavoriteStore` + `InMemoryFavoriteStore` | 收藏与进度同一套形态（`PlaybackKey` 同键、`Sendable` + `async`）；M8 换 GRDB 时实现同一协议即可，UI 不改 |
| `AppModel.favoriteStore` / `homeLayout` / `localSyncIdentifier` | 收藏存储、首页展示方式、本机同步标识 |
| 详情页「收藏」 | 工具栏按钮写入/取消收藏，条目带元数据；换源后自动刷新收藏状态 |

**为什么把元数据记在进度里**：参考图的历史行要显示站源/线路/集名/封面，这些只在播放时刻最可靠；
记下来后「追剧」列表**不发任何网络请求**就能渲染（离线可用）。跨线路/跨站的集身份对齐仍是 M8 的事。

## 三、明确未做（诚实记录）

1. **落库**：收藏与历史现在是内存实现（杀进程即丢），GRDB 在 M8 —— 两个空态文案都写明了这一点。
2. **iCloud 同步**：开关只是入口占位（置灰 + 说明），跨设备同步属后置里程碑。
3. **下载管理 / 日志管理（除宿主输出外）**：未落地，页内写明缺什么与依赖的里程碑。
4. **弹幕渲染与解析执行**：`parses` 只做展示；执行链在 M5、渲染在 M8。
5. **播放页设置**：系统原生播放器没有可配置项，M3/M4 之后才会有。
6. 首页「自定义首页区块」不做：`首页内容` 只是如实描述当前形态的静态行。

**CI 抓到的两个真问题**（都记在这里，避免复发）：

1. `0..<n` 必须写成 `0 ..< n` —— 本仓库 `.swiftformat` 未改该默认，SwiftFormat 的 `spaceAroundOperators` 会判失败（M00P2 已记录此约定）。
2. **`EditMode` / `\.editMode` 是 iOS/tvOS 专有，macOS 不可用**：首次提交的「多选」用了它，macOS 侧 `swift build` 直接报
   `'EditMode' is unavailable in macOS`。已改成平台无关实现（自有 `isSelecting` + 行内 `SelectionMark` + 工具栏删除），
   这也符合 `docs/UI 规范.md`「业务视图不写平台分支」。
