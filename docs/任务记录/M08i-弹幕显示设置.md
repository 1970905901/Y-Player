# M08i 弹幕显示设置（字号 / 透明度 / 速度 / 显示区域）

- 状态：设置页与持久化落地，9 条单测 + 偏好往返测试；**屏上观感待真机确认**
- 时间：2026-10-09
- 依赖：M08h（上屏）、M08f（偏好存储：所有读写都走注入的 `defaults`）

## 一、为什么现在做

M08h 把弹幕画上去了，但那四个参数是写死的默认值 —— 而「字号 / 透明度 / 速度 / 显示区域」
是这类东西**必须**能调的：屏幕大小、视力、片子有没有字幕，人人不同。上游那套
（`DanmakuSetting`）也有这几项。

## 二、四档取值都取「可解释的值」

| 设置 | 类型 | 取值 | 落到哪 |
| --- | --- | --- | --- |
| 字号 | `Double` | 0.5×…1.6×（默认 0.8） | `DanmakuDisplayStyle.fontScale` |
| 透明度 | `Double` | 10%…100%（默认 100%） | `opacity` |
| 速度 | `DanmakuSpeed` | 慢 13 秒 / 中 9 秒 / 快 6 秒（默认「中」） | `scrollDuration` |
| 显示区域 | `DanmakuArea` | 1/4 屏 / 半屏 / 3/4 屏 / 全屏（默认全屏） | `areaFraction` |

速度给的是**真实秒数**而不是「倍率」：倍率还得再乘一个基准，两处都能改就等于没有唯一口径。
设置页的 footer 把这些秒数直接写出来，用户看得见自己在调什么。

## 三、显示区域是「排版时就裁」，不是「画好了再裁」

`areaFraction` 只做一件事：把交给 `DanmakuPlan.Layout` 的 `screenHeight` 乘上这个比例。
于是轨道数、底部弹幕的位置**全都跟着区域走**，而 `DanmakuOverlayGeometry` 一行都不用改
（它本来就以「版面高度」为准）。顺带三个决定：

- **字号不跟着区域缩**：区域是「裁出多少地方放弹幕」，不是「把画面缩小」；
- 区域从**顶部**算：目的是避开画面下方与字幕 —— 这才是要这个开关的理由；
- 比例有下限 0.25，计划里还有一道 `max(1, …)`：极端值下也不会算出 0 条轨道。

## 四、默认值 = M08h 的行为（单测钉住）

`DanmakuDisplayConfig()` 与 `DanmakuDisplayStyle()` 的默认值**逐项相等**，单测直接断言这一点。
默认值在这里不是「随手定的」而是回归基线：哪天要改，必须是有意的。

## 五、持久化

- 形态：`字号|透明度|速度|区域`，与 `DanmakuAPIConfig` 同一套竖线拼接（值里不会出现竖线，
  读的时候不必处理解码失败分支）；
- 数值用 `String(Double)` 而不是 `String(format:)`：locale 无关，往返能精确相等；
- **格式不对整体回落默认**：宁可回到基线，也不要「字号生效了一半、速度没生效」；
- 写入走 `AppModel.danmakuDisplay` 的 `didSet` → 注入的 `defaults`（M08f 的规矩）；
- `AppModelIntegrationTests.preferencesRoundTrip` 已把这项加进去：改完 → 用**同一份存档**新建模型
  → 读回来还在。这是本项目对「新偏好」的验收方式。

越界与 `NaN` 在 `init` 与 `decode` 两处都夹（`NaN` 落下限、±∞ 按大小夹）：
手改 plist 不该把界面搞成「字号 0」。

## 六、界面

「设置 → 播放 → 弹幕显示」：四项 + 一行**预览**（用同一份显示参数写出的真字 ——
字号与透明度光看数字判断不了合不合适）。入口行摘要显示「1.3× · 快 · 半屏」，一眼看出改过没有。

播放中改设置**立刻生效**：改一次写一次 `UserDefaults`，播放页重排计划时读到，不需要退出重进
（计划的重排键里已带上 `danmakuDisplay.persistenceValue`）。

## 七、没做（留口）

- 弹幕**描边宽度**没做（固定 0.8 半径的阴影，见 M08h）；
- 「仅滚动 / 屏蔽关键词 / 屏蔽某用户」这类过滤项没做 —— 那属于取用链之外的新功能，不是显示参数；
- 屏上观感（字号缩放合不合手、四档够不够用）要真机看一眼再调：改档位只动
  `DanmakuSpeed` 与 `DanmakuArea` 两处。
