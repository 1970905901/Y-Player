# M02P16 发现页底部 Tab 栏收放（上滑隐藏 / 触碰展开）

- 状态：实现与单测落地，视图效果待真机确认（本地无 Swift 工具链）
- 时间：2026-10-09
- 依赖：M02P13（发现页对齐参考视频）、M07c6（底部 Tab 的成型）

## 一、规格：按原话实现

> 发现页向上滑动列表时底部 tab 要收起来隐藏，只要用手指没有离开屏幕就隐藏，离开后也隐藏，
> 再次触碰屏幕会显示出来，滑动再隐藏。

拆成四条判定规则（每条都有单测）：

| # | 规则 | 为什么 |
| --- | --- | --- |
| 1 | 只有**触碰**能展开，往下滑不展开 | 原话里「再次触碰屏幕会显示出来」是唯一的展开入口；收起因此是**单向**动作，松手不回弹 |
| 2 | 同一次触摸内**不再展开** | 「只要用手指没有离开屏幕就隐藏」—— 中途反向滑回来也得保持收起 |
| 3 | 触屏先展开，滑过**阈值**才收 | 不做的话手指一碰就收，想点顶部工具栏会闪一下 |
| 4 | 判定要**以竖直为主** | 横向展示里每段轮播都是内层横滑，横着划会有几 pt 竖直漂移，不排除掉就会「滑轮播把 Tab 栏也收起来」 |

## 二、实现：三层，各管一件事

1. **`DiscoverTabBarVisibility`**（`DiscoverLayout.swift`，纯逻辑 + 11 条单测）—— 状态机。
   - `touchDown()` 展开、`dragChanged(x:y:)` 上滑超阈值收起、`touchEnded()` **刻意不改状态**
     （这正是「离开后也隐藏」）、`reveal()` 强制展开（离开发现页用）；
   - `isUpwardScroll(translationX:translationY:)` 是纯函数，阈值 `hideThreshold = 8pt`：
     取小是故意的（要跟手），但零不行。
2. **`HomeView` 的旁听手势**（挂在内容区 `ScrollView` 上）—— 两个 `simultaneousGesture`：
   - 零时长长按（成功即触屏）→ 触屏信号；
   - 零距离拖动 → 位移信号（方向判定）。
   - 都用 `simultaneousGesture`：**只旁听、不抢**，滚动与翻页逻辑一行没改
     （换成 `.gesture` 会把滚动抢走）。两路信号互为兜底：任一路没来，最坏结果是「不收起」，
     而不是「收起后展不开」——后者会把用户困在页面上。
3. **`adaptiveTabBarHidden(_:)`**（`Platform/AdaptiveTabBar.swift`）—— 把布尔值翻成当前系统的原生 API。
   状态与调用点都在 `HomeView` 内，因此只影响发现页这一个 Tab。

## 三、为什么不读滚动偏移

`GeometryReader` 量偏移只能回答「滚到哪了」，回答不了「手指还在不在屏幕上」；
而规则 1、2（没离开就保持收起、离开后也保持收起）恰恰只能由**触摸本身**判定。
能直接给 `isDragging` 的 `onScrollPhaseChange` 是 iOS 18 起才有，够不着。

## 四、已知缺口：iOS 15 不收起

`.toolbar(_, for: .tabBar)` 是 **iOS 16** 起才有的 API，iOS 15 的 SwiftUI 没有「按视图隐藏 Tab 栏」
的原生等价物。按 [`UI 规范.md`](../UI%20规范.md) 的「不做跨版本仿制 / 不自绘系统控件」，
`adaptiveTabBarHidden` 在 iOS 15 上**明着是空操作**，而不是去摸 `UITabBarController` 自控系统控件。
规范里的能力表已同步标注这一格为「不支持」。

## 五、没做（留口）

- 其它页面（搜索 / 追剧 / 直播 / 设置）不收起 Tab 栏 —— 这次只按原话改发现页；若要推广，
  把状态机与两个旁听手势提到公共容器即可，状态机本身与页面无关；
- ~~进详情页不隐藏 Tab 栏（现状如此，也没要求）~~ → **已改**：沉浸页（详情 / 播放……）经
  `ImmersiveTabBarState` 收起本 Tab 的底部栏（`Platform/AdaptiveTabBar.swift` 的
  `ImmersiveTabBarPageModifier`，「沉浸视图」那个需求落地时做的）。
