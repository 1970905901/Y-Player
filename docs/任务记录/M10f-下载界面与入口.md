# M10f 下载界面与入口（「下载管理」真列表 + 播放页下载）

- 状态：下载管理页的任务列表 / 进度 / 暂停继续删除清空、播放页的「下载本集」入口落地；
  **本地地址接管未做**
- 时间：2026-10-09
- 依赖：M10e（接线与驱动）

## 一、这一轮让下载可见

M10a–M10e 都是「看不见的层」：规则、库、清单展开、执行器、接线。这一轮把界面接上，
整条链第一次能在真机上点着走一遍：

**播放页 →「离线下载」→「下载本集」→ 设置 → 数据 → 下载管理 → 列表里的进度 / 暂停 / 继续 / 删除**

## 二、页面上的四个决定

- **进度有两种形态**：知道总量画确定进度条，不知道画不确定态 —— 这正是 M10a 把 `progress`
  做成可选值的原因（写 `0` 会让人以为「卡在开头」）；
- **一条任务一个主操作**：排队中 / 下载中 → 「暂停」，暂停 / 失败 → 「继续」，已完成 → 不给按钮
  （要重下就是新任务，见 M10a 的状态机）；
- **删除连文件一起删**，「清空下载」同理 —— 否则空间占用不动，看着像没删掉；
- **进页面就跑一轮队列**（`.task` 里 `runDownloadQueue`）：这一版没有后台下载（M10a 的留口），
  所以「看得见的时候」才推进；页头的「正在下载…」就是这个状态。

## 三、入口为什么先放在播放页

播放页手上有三样东西正好够建一条任务：`resource`（地址 + 请求头）、`progressContext`（站点 key）、
`danmaku`（上层拼好的片名 + 集名 —— 比播放页标题准，标题常带「 · 线路」后缀，写进文件名很难看）。

详情页的「整部下载」（一次入队一条线路的全部集）留到下一步：那要先读一遍详情页的选集结构，
比这里更容易改坏。

## 四、剩下的（两步）

1. **本地地址接管**：已下载的集改成播本地文件。⚠️ 一个**已知风险**要真机验：拼接出来的 `.ts`
   能不能被 `AVPlayer` 直接播还没有结论（fMP4 的 `.mp4` 没问题）。若播不了，出路是
   「保留分片 + 本地改写过的清单」，而不是硬塞一个它不认的容器；
2. 详情页的「整部下载」入口。

## 五、留口

- 下载列表按创建时间升序（与队列一致），没有排序 / 筛选；
- ~~列表里「已完成」的条目还没有播放入口~~ → **已补**（M10g 同批的小改动）：已完成且本地文件在的
  条目行上有「播放」，直接进播放页。
