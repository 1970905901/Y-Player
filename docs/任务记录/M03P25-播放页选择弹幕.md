# M03P25 播放页「选择弹幕」（对齐上游 DanmakuDialog / DanmakuSearchDialog）

- 状态：**已实现**（本地四闸门全绿 + 新单测；Mac 编译 / 测试 / 上机待 YG）
- 时间：2026-10-10
- 触发：接手时记下的留口 ——「弹幕**选择 / 搜索**（上游 `DanmakuDialog`：列候选项 + 按名字搜）」。
  在此之前：搜索接口返回的**一批候选**被 `DanmakuSourceSelection.preferred` 静默取第一条，
  第一条没内容就只能吃一句「没搜到」—— 用户没有任何办法换一条。
- 依据（上游）：`ui/dialog/DanmakuDialog.java`（bottom sheet 列 `player.getDanmakus()`，
  点一条 `player.toggleDanmaku(item)`；右上「搜索」→ `DanmakuSearchDialog`、「设置」→ `DanmakuSettingDialog`）、
  `ui/dialog/DanmakuSearchDialog.java`（关键词框预填片名 + 结果列表 → `player.setDanmaku(item)`）、
  `player/media/PlaySpec.java`（候选列表 `danmakus` + `selected` 标记：**活在本次播放里**）、
  `player/PlayerManager.java`（`haveDanmaku()` = 有选中的来源，是那颗按钮的显示条件）。

## 一、上游口径 → 本项目

| 上游 | 这里 |
| --- | --- |
| `DanmakuDialog` 列这一集的候选（`PlaySpec.danmakus`），点一条换过去 | `PlaybackDanmakuPicker` 半屏面板：第一条是「自动」，其余是候选；点一条走 `selectDanmaku(_:)` |
| 点**已选中**的那条 = `toggleDanmaku` 取消选择（没有选中的来源 = 这一集不显示） | **不一样**：点已选中那条仍是「就选它」；回自动点第一条「自动」，关弹幕用「显示弹幕」开关 —— 两件事不混在一起 |
| 「搜索」→ 关键词框（预填片名）+ 结果 → `setDanmaku(item)` | 面板里「重新搜索」区：片名 / 集名两个框（预填**这一集**原本搜的）+ 搜索；搜到的**接进候选**，不动正在播的那份 |
| 选择活在 `PlaySpec`（本次播放）里，退出播放页就没了 | 同：`danmakuPick` 只在会话里；**换集清掉**，同一集重新载入（换线路）保留 |
| 那颗弹幕按钮只在 `haveDanmaku()`（有选中的来源）时露出来 | 「选择弹幕…」只要**有候选**就露（包括「自动挑的那条没内容」这个最需要它的场景）—— 这里刻意比上游宽一格 |
| 「文件是空的」与「根本没搜到」共用一句提示 | **分开**：`DanmakuStatus.emptySource`（换一条试试）vs `.empty`（去换 API 地址）—— 下一步动作不一样 |

## 二、口径与取舍

- **候选 = 站点自带 + 搜索到的**（`PlaybackDanmakuSwitcher.candidates`，**纯函数有单测**）：
  自带的排前面（它跟片源对得上），按 `id`（名字 + 地址）去重；
- **一个值一个回写口**：`PlaybackDanmakuSwitcher` 把「候选 / 当前选中 / 状态行 + 换一条 / 重搜」
  包成一个值，宿主（详情页那三处）只传 `model.playbackDanmakuSwitcher` 一行 ——
  与 `PlaybackLineSwitcher` / `playbackInfoRows` 同一套做法，播放页仍然不认识 `AppModel`；
- **状态行复用 `danmakuStatus.text`**：面板顶部那一行与设置页看到的是同一句话（不另写一份文案）；
- 「自动」是**显式的一行**（不是「取消选择」）：我们的自动选择（站点自带 → 搜索第一条）是上游
  `isSpiderFirst` 那套语义，而「取消选择」在语义上是另一件事 —— 拆成两行，用户不用猜。

## 三、故意没做

- **把选择落盘记住**（按片 / 按集）：上游也没做（选择活在 `PlaySpec` 里），而且接口给的弹幕地址
  可能带时效 —— 存下来下次多半是「加载失败」，反而更费解。真要做得连「哪些接口会过期」一起想；
- 上游的「从本地文件选一份弹幕」（`FileChooser` + `Danmaku.from(uri)`）：iOS 上要走文件选择器
  与安全作用域书签，是另一件事；
- 候选分页 / 超长列表虚拟化：候选一般几条到几十条，普通 `List` 够用。

## 四、验证点（Mac）

1. `swift test --package-path Packages/CatVodUI`：新 5 条（候选拼法 2 条 + 状态文案 1 条 +
   选弹幕接线 2 条）。**新增了源文件与测试文件**，跑之前先 `rm -rf Packages/*/.build`；
2. 全包测试 + App 编译照旧（Mac 命令块见交接文档第六节）；
3. **上机**（有弹幕源的一集）：
   - 播放页 →「选择弹幕…」：列出候选，当前那条带勾；点另一条 → 屏上弹幕**当场换**；
   - 「自动挑的那条是空的」时：状态行说「xx 里没有弹幕（换一条试试）」，换一条就有；
   - 「重新搜索」：改个名字（比如去掉「第 x 季」）→ 搜索 → 候选里多出新条目，点它就能用；
   - 换集：手动选的那条不再算数（回到自动）；同一集换线路：选择**保留**。

## 五、教训

- 「一批候选取第一条」这种**静默取舍**要在文档里写清，否则没人知道还能换 —— 这次补的就是它；
- 顺手把闸门补了一条：`Scripts/check_visibility.py` 原来只看「声明类型的那个文件」里的 private 成员，
  而这次 `danmakuSection` 的 private 写在**扩展文件**、被主文件引用 —— 正好是坑列表第 15 条记的
  那个盲区（M25P2 同款）。现在它按「类型名 + 仓库命名约定（`X.swift` / `X+yy.swift`）」把主文件与
  各扩展文件**互相**查，并且实测过「改回 private 就报」。
