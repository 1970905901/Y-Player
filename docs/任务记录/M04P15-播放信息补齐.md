# M04P15 自研内核的播放信息补齐（帧率 / 源色彩 / 输出 / 丢帧）

- 状态：**已实现**（本地静态闸门全绿 + 新单测；Mac 编译 / 测试待 YG）
- 时间：2026-10-10
- 触发：M04P2 的现场验收（「源是 HDR，输出还是不是 HDR」）得先有那几行 —— 自研内核此前只报
  「画面 / 编码 / 容器 / 音频 / 解码」，帧率、色彩、输出、丢帧全是空的。

## 一、做法

1. **读的时候一次读全**（`LibavInput.mediaInfo()`）：`StreamInfo` 加 `fps` / `primaries` / `gamma` ——
   来自流的 `avg_frame_rate`（den = 0 时退化 `r_frame_rate`）与 `codecpar.color_primaries` / `color_trc`。
2. **翻译成人话**（纯函数，可单测）：`LibavInput.fps(numerator:denominator:)`、`colorPrimariesName`、
   `colorTransferName` —— 只翻**能确证**的枚举值，认不出给**空串**（播放信息那边「空就不显示」；
   这一行是要当证据用的，不能猜）。
3. **输出侧看实测**（`stats()`）：第一帧的 `CVPixelBuffer` 像素格式写进 `video-out-params/pixelformat`
   （硬解是 VT 的 buffer、软解是我们转的 BGRA）；「解码」那行的机制同 M04P14。
4. **丢帧**：解码侧计数（转换不出来的帧）写 `decoder-frame-drop-count`；
   显示侧我们没有读法 —— 为此把 `PlaybackStats.dropText` 改成**哪侧读到写哪侧**
   （以前缺一侧就替它写 0，那是假话）。
5. 这些快照都走会话那把锁（解码线程写、控制路径读），与 M04P14 的「解码」同一套。

## 二、口径与已知取舍

- **源**色彩按 ffmpeg 的参数如实翻，沿用 mpv 那套键名（`video-params/*`）—— 界面一行不用改。
- **输出**只写我们真正交出去的像素格式；`video-out-params/primaries|gamma` 先空着：硬解那条路的
  VT buffer 色彩附件（`kCVImageBuffer*`）还没读，等 M04P2 拿 HDR 片子上机时一起补（顺便验「带没带、对不对」）。
- 色彩名词与 mpv 不完全一致（mpv 把多数 SDR 的 gamma 叫 `bt.1886`，我们按 ffmpeg 的 TRC 叫 `bt.709` 等）——
  同一套键、各自的说法；界面要回答的是「HDR 还是 SDR、是什么」，够用。

## 三、故意没做

- 硬解 buffer 的色彩附件读取（`video-out-params/primaries|gamma`）——M04P2 现场做；
- ~~显示侧丢帧计数（`AVSampleBufferDisplayLayer` 没有这种计数可读）~~：→ **M04P22 补上自己的口径** ——
  「帧没能进显示层（转样本失败）」的次数（层自己不报丢帧；迟到帧不算丢帧）。
- 音轨切换、字幕。

## 四、验证点（Mac）

1. `swift test --package-path Packages/CatVodPlayer`：
   - 「Libav 输入层」+1：帧率与色彩翻译（含「认不出给空串」）；
   - 「播放信息」+1：只有一侧丢帧计数时只写那一侧；
   - 「FFmpeg 真会话」两条补断言：硬解那条帧率 ≈30、输出格式非空；软解那条输出 = `BGRA`；
2. 全包测试 + App 编译照旧；
3. **上机**：播放信息的「帧率 / 色彩 / 输出 / 丢帧」四行对自研内核不再是空的
   （模拟器软解：输出写 `BGRA`；HDR 片源的「色彩」行应写 HDR）。

## 五、留给 M04P2 的问题

- 硬解 buffer 的色彩附件到底带不带（决定「输出」行能不能写 HDR）；
- 4K 60fps 的丢帧口径（显示侧没有计数，只能看解码侧 + 主观流畅度）。
