# M06k 「跳过广告」提示

- 状态：统计、接线、播放页提示都已实装并有单测；**「每集单独计数」**与真机 smoke 是遗留（见第四节）
- 时间：2026-10-09
- 依赖：M06d（清理器已经把统计算好了）、M06h（开关）、M06i（内置规则包）

## 一、为什么

`HLSManifestCleaner.Result` 从 M06d 起就带着完整统计：删了几段、共多少秒、每一段的时间与原因。
但**没有任何地方读它** —— 于是广告被清掉了，用户完全不知道：

- 分不清「这个源本来就没广告」和「规则没配好/没开」；
- 也没法判断某条规则是不是误杀（少了一小段正片，但界面什么都没说）。

这与 M06h 之前的 `HLSAdRuleState` 是同一种半成品：**能力齐了，没人用**。

## 二、统计盒子（`AdSkipRecorder`）

清理发生在**本机服务的线程池**里，提示要显示在**主线程**的界面上 —— 直接共享可变状态就是数据竞争。
做法与 `StorageFailureRecorder` 同一套路：`NSLock` 保护的盒子 + `@Sendable` 回调。

两条刻意的设计：

1. **只有真删过东西才回调**。一个片子几十个清单，每个都弹一次提示就是噪音；
   「处理过几个清单」照样在统计里累加，但不会惊动界面；
2. **「处理过几个清单」与「其中几个真清了」是两个数**。混在一起的话，
   提示会把「走了清理器但没什么可删」也算成跳过广告 —— 虚报比不报更糟。

## 三、界面

- `AdSkipNotice.text(for:)`：文案是纯函数（`已跳过广告 N 段，约 X 秒`）——
  0 段返回空串（界面据此不显示这一行）；时长四舍五入后不足 1 秒就**不提秒数**，
  免得写出「约 0 秒」；
- AppModel：`adSkipNotice`（`@Published`）与 `playbackNotice` 分开 ——
  那个是「为什么这样播」（内核/解码这类常驻说明），这个是「刚刚发生了什么」；
  init 末尾把监听器接回主线程（捕获 `self` 必须等所有存储属性就位）；
- 播放页设置区显示一行带剪刀图标的提示。

## 四、测试与遗留

- `AdSkipRecorderTests`：真删才回调、处理数与清理数分开、`reset` 与摘监听；
- `LocalM3U8RouteTests` 的清理用例补 4 条统计断言（那条 fixture 删了 1 段 7 秒）；
- `AdSkipNoticeTests`：三种文案（空、不足 1 秒、正常）。
- 遗留：
  1. **统计按「换接口」归零，不是按「换一集」**：`PlaybackView` 目前只接
     `resource/title/settings`、不持有 `AppModel`，要做「每集单独计数」得先给它一个回传口
     （一处小改动，但会牵动 6 个调用点，值得单独一轮）；
  2. 提示只写「累计多少段」，不区分是哪条规则删的 —— 逐段明细（`removedSegmentDetails`）
     已经在 `Result` 里，等真有人要「这条规则是不是误杀」的诊断再说；
  3. 真机 smoke：打开一条规则 → 播放页出现提示、关掉规则 → 提示不再出现。
