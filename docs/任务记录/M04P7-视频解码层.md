# M04P7 视频解码层 —— VideoToolbox 硬解出帧

- 状态：**已实现**（本地静态闸门全绿 + 新单测；Mac 编译与测试待 YG）
- 时间：2026-10-10
- 触发：M04P6 输入层把「打开流 / 读流信息」打通了；这一步把**包 → 帧**这一段接上。

## 一、做法

新增 `LibavVideoDecoder`（第二个碰 libav 的文件）：

| 方法 | 说明 |
| --- | --- |
| `open(input:)` | 挑第一条视频流 → 建 VT 设备（`av_hwdevice_ctx_create`）→ `avcodec_open2` |
| `decodeFrames(n)` | 取包（只喂视频流）→ `avcodec_send_packet` / `avcodec_receive_frame` → 至多 n 帧 |
| `close()` | 幂等；不碰借来的 `formatContext` |

**路径选择：VideoToolbox 硬解，不设软解回退**：

1. M4 的口径是「HDR 与流畅度」，硬解是这两件事的地基；
2. VT 解出来的帧**本身就是 `CVPixelBuffer`**（`AVFrame.data[3]` 里就是 `CVPixelBufferRef`）——
   不需要 sws 转换，也不会把 10bit / HDR 压成 8bit BGRA。软解 → BGRA 那条路会丢；
3. 设备建不出来 / 没有解码器 / 没有视频流：**明确报错**，而不是悄悄降级（同 MPV 的可用性纪律）。

三个细节：

- **EAGAIN 标准用法**：发送返回 `-EAGAIN`（解码器满）时先收帧腾位置再重发；收帧负值
  （EAGAIN / EOF / 出错）对调用方语义相同——「这次没得收」，一律停手不抛错。
- **时间戳自己算**（`pts × num/den`）而不引 `av_q2d`：一个除法的事，少一个互操作面；
  无效 pts（`AV_NOPTS_VALUE` = Int64 最小值）给 0。
- **retain 那一下**：`data[3]` 只是借给我们的（帧一还回解码器 buffer 就没了），
  `Unmanaged.retain().takeRetainedValue()` 之后才交给调用方。

## 二、故意没做

- **软解回退**：等「硬解 / 软解」这个设置项真的有引擎去消费时再说；
- **seek / 音频 / 渲染**：各自成片；
- `LibavInput.rawFormatContext` 是给本层开的**借用口**（文档写明：句柄仍归输入层，
  借的人不许关）。
