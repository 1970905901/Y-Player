# M10j 整部下载（逐集换地址那一半）

- 状态：**已实现**（本地闸门全绿 + 新单测；攒着下次上机验）
- 时间：2026-10-10
- 承接 M10i：那一片只排「**现在就能直接播**」的集，界面上写着
  「另有 N 集要逐集向站点换地址，暂不支持整部下载」。对 `type=3`（js2p/Spider）站点来说，
  **几乎所有集都在那 N 里** —— 于是「整部下载」对这类站点等于没有。这一片把它补上。

## 一、做法：复用「播放页换集」那条路，不另造一套

- 第二批集（``VodDetailView/siteDownloadEpisodes``）的判定与「能不能换地址」**完全一致**：
  `makeResource(for:) == nil && (isSpiderPlayable(site) || requiresSitePlay(site, episode:))`；
  换地址用**已有的** ``VodDetailView/siteResource(site:episode:)``（播放页自动连播换集走的就是它）。
  不另立一套规则 —— 免得「按钮说能下、换出来是空的」。
- 点了以后**串行**换：一集一集来，换到一集立刻 `enqueueDownloadsAndStart` 入队并开跑。
  串行不是为了省事：宿主是单进程的（内嵌 node），站点 `/play` 也共享同一条连接，
  换来的是「进度可读、失败能归因」，比省几秒重要。
- 进度与结果都写在按钮下面：`正在换地址 3/12：第 3 集` → 跑完换成 ``SiteDownloadSummary`` 的结果文案。
- 剩下那批（要走解析链 / 没地址的）**不排**，也把条数写出来。

## 二、结果文案要报三样（`SiteDownloadSummary`，纯函数有单测）

只写「已排 N 集」会把失败盖住，而失败恰恰是用户决定「那几集怎么办」的依据：

| 情况 | 文案 |
| --- | --- |
| 全部排上 | `已排 3 集。` |
| 有本来就在队列里的 | `已排 2 集，1 集本来就在队列里。` |
| 有换不到地址的 | `已排 1 集，2 集换不到地址。换不到的多半是要走解析链：先单独播一次那几集，再用播放页的「下载本集」。` |

失败时给的是**可执行的下一步**，不是一句「失败」。

## 三、顺带：把「下载入口」一簇拆进 `VodDetailView+Downloads.swift`

查了一下 CI 日志：lint 是 success（`type_body_length` 不算注释行，当前非注释 339 行 < 450）。
但这一片往类型体里又塞了约 40 行，余量不多 —— 顺手把
`directDownloadEpisodes` / `siteDownloadEpisodes` / `wholeLineDownloadsRow` 搬进扩展文件
（与 `+Data.swift` / `+Emby.swift` 同一个做法）。**扩展不计入类型体**，余量回到 100+ 行。

## 四、故意没做

- 不做并发换地址：见上（宿主单进程）；
- 不做「换地址失败自动重试」：失败多半是「这一集要靠解析链」，重试也一样；
- 不给这一批做「暂停/继续」：整批就是一次点击一件事，跑完给结果即可（单集下载本来就有暂停）。

## 五、验证点（Mac，和下一批一起跑）

用一个 `type=3`（js2p）站点的详情页：

1. 「整部下载（N 集）」按钮下面应多出一个「**整部下载（逐集换地址，M 集）**」；
2. 点它 → 按钮置灰，下面一行开始滚动「正在换地址 i/M：集名」；
3. 跑完：文案应报清「已排 / 本来就在 / 换不到」三样；进「设置 → 数据 → 下载管理」，
   排上的那些应已经在跑或已完成；
4. 站点一个地址都换不出来时（例如宿主停了）：文案应写「0 集换不到地址」以外的实话
   （M 集全部计入「换不到」），并给出「先单独播一次」的指路。
