# M03P8 轨道显示语言与标题

- 状态：**已实现**（本地静态闸门全绿 + 单测改断言；Mac 编译 / 测试 / 上机待 YG）
- 时间：2026-10-10
- 触发：播放页的「音轨 / 字幕」下拉框一直只有「音轨 2」「字幕 3」这种**数字** ——
  三个内核其实都能给出人话的名字（mpv 的 `title` / `lang`、系统内核的
  `AVMediaSelectionOption.displayName`、自研 FFmpeg 的流元数据 `title` / `language`），
  只是上报事件里只有 id。多轨片源（Emby 那类）里选错轨全靠猜。

## 一、做法

1. **事件载荷带标签**：新增 `PlayerTrack { id, label? }`（`PlayerEngine.swift`），
   `PlayerEvent.tracksChanged` 与 `FFmpegSessionEvent.tracks` 的载荷从 `[Int]` 换成 `[PlayerTrack]`。
   `id` 的语义不变（送回来选轨道用的那个数字），`label` 是给人看的名字，**读不到就是 nil**。
2. **三种内核各自填**：
   - mpv（`MpvEventMapping.tracks(fromTrackListJSON:)`）：`title` 优先、`lang` 兜底；
   - 系统内核（`SystemPlayerEngine+Tracks.trackList()`）：`AVMediaSelectionOption.displayName`；
   - 自研 FFmpeg（`LibavFFmpegSession.playerTrack(_:)`）：`LibavInput` 读流元数据的
     `title` / `language`（`av_dict_get`，大小写不敏感）。
3. **界面兜底**：`PlaybackView` 的 picker 显示 `label ?? "音轨 <id>"` ——
   没有名字的轨道与以前一模一样，不编假名字（与播放信息同一套「读不到就不显示」的口径）。

## 二、口径与取舍

- **`label` 不做翻译 / 不加装饰**：内核给什么显示什么（`zh`、`简体`、`英语` 混着来就混着来）——
  翻译表是另一个坑，先不挖；
- **id 的含义各内核自洽**：mpv 是轨道 id、系统内核是 `group.options` 的下标 —— 与以前一致，
  界面只是把 label 贴在旁边；
- **系统内核**的 `displayName` 由系统按当前语言给（可能是「英语」也可能是 `English`）——
  那是系统的口径，不替它改。

## 三、故意没做

- 轨道语言的正规化（`zh` / `chi` / `zho` → 「中文」）：要一张映射表 + 大小写/变体处理，
  等有人真被绕晕了再说；
- 默认轨的显示（哪个是容器标的 default）：那是选择语义不是展示，界面有「自动」这一项就够了；
- 字幕轨的多语言排序：播放入口不替用户排序，报什么列什么。

## 四、验证点（Mac）

1. `swift test --package-path Packages/CatVodPlayer`：`MpvEventMapping` 的解析用例改成带标签
   （`title` 优先于 `lang`、封面图仍不算画面轨）；两个引擎的 `tracksChanged` 断言带标签；
   系统内核边界用例改名 `trackList()`；自研会话的换轨用例改用 `track.id`；
2. 全包测试 + App 编译照旧（**新增无文件**，这次不用清 `.build`）；
3. **上机**：放一个**多音轨 / 内嵌字幕**的本地片（Emby 那类），播放页「轨道」那两个下拉框里
   应显示语言 / 标题（如 `zh` / `简体`），不再是纯数字；没有元数据的片源照旧显示「音轨 2」。

## 五、教训（写给下一次）

- 改公共事件载荷（`PlayerEvent`）会顺着 `FFmpegSessionEvent`、三个内核、界面、断言一路传下去 ——
  这次一共 10 个文件；先把「谁在产、谁在消费」列全再动手，比改到一半发现漏点省事；
- `PlayerTrack` 的 `label` 用**可选**表达「读不到」：给空串会让界面分不清「没名字」和「名字是空的」，
  与 `PlaybackStats` 那套「空就不显示」的口径对齐。
