# M04P3 播放信息补「容器 / 音频」

- 状态：**已实现**（本地静态闸门全绿 + 新单测；和 M04P2 一起攒着下次上机验）
- 时间：2026-10-10
- 承接 M04P1 / M04P2：那一组回答「画质是什么样」，这组回答「**这一路到底是什么**」——
  容器是哪种、音频是什么编码几个声道。「没声音」「放的是哪一版」这类问题，先看这两行。

## 一、加了什么（同一套机制，只是多读三个属性）

```
file-format                  → 容器（mpv 原样给的，如 matroska,webm / mov,mp4,m4a,3gp,3g2,mj2）
audio-codec                  → 音频编码（aac / ac3 / opus…）
audio-params/channel-count   → 声道数
audio-params/samplerate      → 采样率
```

界面上两行：

```
容器：matroska,webm
音频：aac · 48 kHz · 2 声道
```

- 容器**不做美化**：mpv 说有哪几个解复用器就写哪几个 —— 裁成 `mp4` 反而会误导；
- 采样率整千写 `48 kHz`，不是整千照实写 `44100 Hz`（不四舍五入）；
- 音频那行三样分开判：缺哪样不显示哪样，**不编默认值**；都没读到整行不出现；
- 诊断报告的「最近播放」段同步多这两行。

## 二、故意没做

- 不读 `audio-params/format`（样本格式 pcm/f32 之类）：对普通用户是噪音，
  真排查音频问题时再加；
- 不做「音频轨道切换」的增强：M03P5 已经能选轨，这一片只负责**显示**。

## 三、验证点（Mac，和下一批一起跑）

1. 用 MPV 播一集：播放页「播放信息」里应有「容器」与「音频」两行；
2. 音频那行应与实际相符（比如 `aac · 48 kHz · 2 声道`）；
3. 复制诊断信息 →「【最近播放】」段里也能看到这两行。
