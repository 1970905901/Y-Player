# M04P23 逐帧步进 + 音频增益（播放器零碎之二）

- 状态：**已实现**（本地四闸门全绿 + 新单测；Mac 编译 / 测试 / 上机待 YG）
- 时间：2026-10-10
- 触发：M04P22 同批的「播放器零碎」—— 逐帧步进 / 音频增益（M04P13 / M04P14 都留过口）。
- 依据（上游/参照）：mpv 的 `frame-step`（**播放中调它会先暂停再走一帧**）与 `volume-max`
  （mpv 的「放大」就是 volume > 100）；上游 FongMi 的音频那一套（`MpvAudioEffectFilter` 的
  boost / preamp + `AudioLimiter`）是滤镜链的活，本片不做 —— 只做「在用户音量之上再乘一个倍数」。

## 一、做了什么

### 1）逐帧步进（三个内核都支持）

- 口径：暂停态往前走**一帧**；播放中调 = **先暂停再走一帧**（mpv 的语义，三个内核统一）；
- 系统内核（`AVPlayerEngine`）：`AVPlayerItem.step(byCount:)` —— 这个 API 要求暂停态，
  所以先 `pause()`；`canStepForward` 为假时什么都不做（不假装走了）；
- MPV（`MpvEngine`）：`frame-step` 命令，状态跟着报 `.paused`（别让界面还以为在播）；
- 自研 FFmpeg（`LibavFFmpegSession` + `LibavVideoRenderer`）：**不重新解码** —— 解码线程本来就
  一直解在前头（显示层里排着队），步进要的是「队首的下一帧」：渲染器记一份「已喂进层的 pts」台账
  （`stepToNextFrame`），把时间轴挪到「比当前显示位置晚、最近的那一帧」上；队里没有下一帧就停在原地；
- 界面：自绘控制条上一个按钮（播放 / 暂停旁边，`forward.frame`），播放中点它 = 先停下再走一帧；
  系统内核那条路用 Apple 的 `VideoPlayer`（我们不自绘控制条），所以引擎接口虽实现、那条路上暂时点不到
  —— 与「系统内核不摆音量增益滑杆」同一套「界面上只摆真能点的」；

### 2）音频增益（MPV 与自研 FFmpeg；系统内核做不到）

- 口径：**1.0 = 原声，最高 2.0**（再高只剩削波）—— 上下限 / 夹紧 / 展示文本只有一份（`AudioGain`），
  引擎、会话、播放页滑杆都用它，别在各自那层再写一遍数字；
- MPV：`volume`（用户音量）与增益**分开记**，写的时候乘起来（mpv 只有一只 `volume` 旋钮）；
  `volume-max` 放到 200（mpv 默认 130，不放会把增益削掉一半）；
- 自研 FFmpeg：会话只记账（控制线程），解码线程在循环顶部把它抄给 `LibavAudioDecoder.gain`
  （`gain` 由解码线程读，写也只能同一条线写）；增益乘在 **swr 转换后的 Float32 交错样本**上、
  逐样本夹到 ±1（超满刻度会绕回去，那是破音里最难听的一种）；换轨新建的解码器下一轮自动带上
  （抄写以解码器自己那份为准，不做第二份账）；
- 系统内核：`AVPlayer.volume` 上限就是 1，放大不了 —— 空实现，界面按
  `PlayerEngineKind.supportsAudioGain` 不摆那个滑杆（与画面比例 / 解码方式同一套「拿不到就不摆」）；
- 界面：播放页信息区「音量增益」区（滑杆 1.0–2.0、步进 0.1、恢复 1.0x）；**页面内偏好、不落盘**
  （与画面比例 v1 同一口径：「这一次播放」的听感偏好，不该把下一部片也放大；要按片记忆另开一片）。

## 二、口径与取舍

- 步进**不重新解码**：解码线程本来就在解前头，显示层里排着队 —— 重解一帧要么跳到队尾（假步进）、
  要么得先 seek 回当前帧（要重解一个 GOP）；把时间轴在队列里挪一格才是「下一帧」的正解；
- 台账记的是**喂过的 pts**：迟到帧被显示层自己丢掉的那些算不进来（最多差一格，不会乱跳）；
- 增益只做「乘一个倍数」：限幅 / 动态归一不做（削波就削了，只夹不绕）；
- 增益不落盘：与画面比例 v1 同一条理由（按片记忆要动进度记录，另开一片）。

## 三、故意没做

- 「逐帧后退」（`stepToPreviousFrame`）：要回头就得 seek + 重解，另开一片；
- 增益的限幅器 / 动态归一 / EQ（上游那套滤镜链）；
- 增益落盘 / 按片记忆；
- 系统内核的增益（做不到，见上）。

## 四、验证点（Mac）

1. `swift test --package-path Packages/CatVodPlayer`：新 5 条 ——
   - 增益（解码器）：同一份源解两遍（`gain` 1 vs 1.5）峰值恰是 1.5 倍；纯函数夹到 ±1；
   - 增益（会话）：写了 2 倍之后喂进音频渲染器的样本峰值 > 0.85（源的 0.5 乘 2 夹到 1）；
   - 步进（会话）：播放中调 = 先报暂停 + 渲染器收到步进；没有下一帧也如实报暂停；
   - 步进（渲染器）：时间轴停在「当前之后最近的一帧」，队空回 false、flush 之后不乱走；
   - 命令下发：FFmpeg / MPV 两个假会话的命令用例各补了增益与步进的断言；
2. 全包测试 + App 编译照旧；
3. **上机**（MPV 或自研 FFmpeg 内核）：
   - 暂停 → 控制条点「逐帧」→ 画面一格一格往前走；播放中点它 = 先停下再走一帧；
   - 播放信息上方「音量增益」滑杆拖到 1.5x → 声音当场变大；「恢复 1.0x」回到原声；
   - 系统内核：信息区**没有**这一区（放大不了就不摆）。

## 五、教训

- **别把「解一帧」当步进**：显示层里已经排着队，再解一帧是「跳到队尾」——留口时写清
  「队列就是帧队列」这句话，实现时才不会走错路；
- **一个数字只留一份账**：增益的上限 / 夹紧原先想在引擎、会话、界面各挡一道，
  收进 `AudioGain` 之后三处同名同值 —— 与「一个旗标别兼两个身份」（M04P22）是同一条规矩的两面。
