# M21P1 本地闸门进版本库（`Tools/out/` → `Scripts/`）

- 状态：**已实现**（脚本搬进版本库 + README 记录；Mac 上可直接跑）
- 时间：2026-10-10
- 触发：三条自检脚本（`check_braces` / `check_lint` / `audit_duplicate_types`）一直住在 `Tools/out/` ——
  而 `Tools/out/` 在 `.gitignore` 里：**新克隆的机器根本没有它们**，而且路径写死成 Windows 的
  `d:\worka\1`，**Mac 上跑不了**（YG 那边一直是「本机没法跑闸门、只能等编译」）。

## 一、改了什么

| 动作 | 说明 |
| --- | --- |
| 搬到 `Scripts/` | `check_braces.py` / `check_lint.py` / `audit_duplicate_types.py`：进版本库，与 `check_app_icons.py` 同处 |
| 根目录按脚本位置推 | `ROOT = dirname(dirname(abspath(__file__)))` —— 在**任意目录**下调用都对（以前靠 cwd + 写死盘符） |
| 输出与退出码 | 统一打到 stdout（不再往 `Tools/out/` 写报告文件）；**有问题退出码 1**，可以直接当闸门接在 `&&` 后面 |
| 新增 `Scripts/check.sh` | 一条命令跑全：三条 Python 检查 + （装了的话）`swiftformat --lint`；没装的工具会明确说「跳过」而不是假装通过 |
| README | 「工具」一节补了闸门表与用法，并写明**闸门抓不到编译错误** |
| 旧的 `Tools/out/*.py` | 挪到 `Tools/out/retired/`，避免两份规则互相漂移 |

## 二、为什么这件事值得单独一片

它不改任何产品代码，但把**「本地能验到什么」**从「一台 Windows 开发机」变成「任何一台克隆了仓库的机器」：
Mac 上现在可以 `bash Scripts/check.sh` 先过一遍，再 `swift test` 过编译，最后才 xcodebuild ——
本轮踩的三次坑（public 位置 + internal 类型 ×2、测试缺 import）里，
**后两类只要跑了 `swift test` 就能第一时间看到**，而结构类错误（括号/重复类型/明显 lint 违规）
现在 Mac 自己也能扫。

## 三、故意没做

- **不把闸门塞进 CI**：CI 那边已经有真的 SwiftLint / SwiftFormat 与完整编译，再加一层近似扫描只会重复；
- 不把 `Tools/out/` 里那几个一次性脚本（`fix_*` / `rename_local_stub` 之类）也搬进去：它们是事故现场的临时工具，
  进版本库只会变成没人维护的噪音（README 里那几个长期用的 `Tools/*.py` 本来就已在版本库）；
- 不给 `check.sh` 加参数解析：它就该是「跑全套、有错就说」。

## 四、验证点（Mac）

```bash
bash Scripts/check.sh
```

1. 应依次打印三条检查的结果，最后一行是 `✅ 本地闸门全过`；
2. 装了 `swiftformat` 的话会多一段格式检查；没装会明说「跳过格式检查」；
3. 故意改坏一个文件（比如删掉一个 `}`）再跑，应当报出来并以退出码 1 结束。
