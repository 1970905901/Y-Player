# M03P15 版本分支收进基础件（并把这条加进本地闸门）

- 状态：**已实现**（本地静态闸门全绿；纯搬家，不改行为，无新单测）
- 时间：2026-10-10
- 触发：M03P14 的双指缩放在 `PlaybackView+Gestures.swift` 里写了
  `if #available(iOS 17.0, macOS 14.0, *)` —— 这违反 `docs/UI 规范.md` 第二节
  「版本分支只允许出现在基础件里」。修它的同时把这条规则**做成闸门**，以后不用靠人记。

## 一、做法

1. **新基础件 `Platform/AdaptiveZoom.swift`**：`adaptiveMagnificationGesture(onChanged:onEnded:)` ——
   iOS 17 / macOS 14 起用 `MagnifyGesture`，更早的版本用 `MagnificationGesture`（该版本唯一的原生等价物）。
   业务视图只调它，`#available` 收在这一件里（与 `AdaptiveNavigation` 的版本分支同一套做法）；
2. **`PlatformShims.swift` 挪进 `Platform/`**：它本来就是基础件（剪贴板 / 屏幕亮度 / 输入法行为的三平台 shim），
   留在根目录会让「`Platform/` 之外不许有版本分支」这条规则多一个例外；
3. **`PlaybackView+Gestures.swift` 去掉 `zoomable(_:)`**：`interactiveLayer` 直接
   `.adaptiveMagnificationGesture(...)` —— 行为逐字不变，只是不再有分支；
4. **`Scripts/check_lint.py` 加 `platform_branch` 规则**：`CatVodUI/Sources/CatVodUI/` 下、
   `Platform/` 之外出现 `#available(` / `#if os(` / `#elseif os(` 就判失败（行首注释不算）。
   `#if canImport(...)` **不查** —— 那是「可选原生依赖」的能力探测，规范里有例外说明。
   加规则时先跑了一遍：命中 9 处（`PlatformShims.swift` 8 + `PlaybackView+Gestures.swift` 1），
   改完 0 处 —— 规则真的会咬，不是摆设。

## 二、口径

- 这轮**不改任何行为**：缩放的两条版本分支与之前逐字一致，只是住进了基础件；
- 老的 `MagnificationGesture` 仍是**故意保留的弃用警告**：iOS 15 上它没有替代品 ——
  三类故意保留的警告清单在 `M03P11-会话锁收进同步临界区.md` 第三节（这次补上第三类）；
- `#if canImport(...)`（`WebSniffWebView`、`CatVodPlayer` 的 libmpv / libav 探测）不查：
  它是「可选原生依赖」的能力探测，不是 UI 版本分支。

## 三、验证点

1. `python -X utf8 Scripts/check_lint.py`：hits=0（加规则时是 9 —— 规则确实会咬）；
2. 全包测试 / App 编译照旧（**文件搬家了**，跑之前 `rm -rf Packages/*/.build`）；
3. Mac 上顺手确认弃用警告是不是三类：`grep -E "was deprecated" /tmp/yp-build.log | sort -u` ——
   预期 `NavigationLink(isActive:)` / `mediaSelectionGroup` / `MagnificationGesture` 三类（多了少了都发我）。
