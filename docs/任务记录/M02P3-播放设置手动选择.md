# M02P3 播放设置：手动选内核与硬解/软解（取消自动降级）

- 状态：进行中（等待 CI 验证）
- 时间：2026-10-07
- 需求：**设置中手动选播放器和硬解/软解，不要自动降级**

## 决策（策略变更）

1. **内核由用户手动选择**：`设置 → 播放设置 → 播放内核`（系统播放器 / MPV / 自研 FFmpeg）。
2. **解码方式由用户手动选择**：`硬件解码 / 软件解码`，写入播放设置并持久化。
3. **取消自动降级**：所选内核不可用时**不切换**到其它内核，而是明确提示原因并引导用户改设置。
   - 旧行为（已删除）：`preferred → mpv → ffmpeg → system` 的自动兜底链。
   - 理由：自动切换会让“设置不生效”，并带来画质/兼容性的意外变化；用户明确选择应当被严格尊重。
4. **解码方式的适用性如实标注**：系统播放器（`AVPlayer`）**不提供**强制硬解/软解开关，
   该选项对 `.system` 无效；UI 显示提示，切到 MPV / 自研 FFmpeg 内核后生效。

## 实现

| 件 | 变更 |
| --- | --- |
| `DecoderMode` | 新增枚举（`hardware` / `software`）+ `isSupported(by:)` |
| `PlaybackSettings` | 新增（`engine` + `decoderMode`）+ `isDecoderModeEffective` |
| `PlayerEngineResolution` | 新增（`.ready(kind)` / `.unavailable(kind, reason)`） |
| `PlayerCoordinator` | 删除 `fallbackOrder`/`select`/`makePreferredEngine`；改为 `resolve(settings:)`（严格）+ `makeEngine(kind:decoderMode:)` |
| `AppModel` | 持久化 `preferredEngine` + `decoderMode`；`resolvePlayback()`；`playbackNotice` 说明不可用/无效原因 |
| `InterfaceManagementView` | 播放设置区：内核 Picker（标注“未接入”）+ 解码方式 Picker + 严格状态与提示 |
| `PlaybackView` | 按设置创建内核；不可用/未实现直接报错，**不换内核** |

## CI 抓出的兼容性问题（已修）

iOS App 构建失败：iOS 18 / macOS 15 SDK 起 `AVPlayer` 标注为 `@MainActor`，
原先用普通 `actor` 实现的内核在 Xcode 构建（严格并发）下报错：
`mutation of this property is only permitted within the actor`。
→ 系统内核改为 **`@MainActor final class AVPlayerEngine`**（`kind` / `events` 为 `nonisolated` 以满足协议），
既符合 SDK 约束也符合 AVFoundation 线程模型；`swift test`（macOS）当时仅报警告，只有 Xcode 构建暴露了该问题。

## 验收

- `CatVodPlayer`：`PlayerSettingsTests` 覆盖「不可用时不降级」「系统内核可用」「未接入内核不创建」「解码方式有效性」「生命周期」。
- CI：5 包单测 + iOS/macOS 未签名构建通过。
- 人工：设置里选择 MPV → 播放页应显示“MPV 内核尚未接入本构建（计划 M3）”，**不应**自动改用系统播放器。

## 回滚

恢复 `PlayerCoordinator` 的兜底链与 `Selection` 类型，并把 `AppModel`/两处界面改回旧 API 即可；
`DecoderMode` 与 `PlaybackSettings` 可保留（不依赖降级逻辑）。
