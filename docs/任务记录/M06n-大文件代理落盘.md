# M06n 大文件代理：落盘转发（不再 502）

- 状态：**已实现**（本地静态闸门全绿 + 新单测；Mac 编译 / 测试 / 上机待 YG）
- 时间：2026-10-10
- 触发：M06a / M06b 的**明确未做**第一条 ——「流式转发（超大文件）：超过 32MB 会 502」。
  缓冲式转发对 HLS 分片 / 密钥 / 清单够用（都在几 MB 以内），但 `/proxy` 搬的是**媒体文件**：
  几十 GB 的电影一撞上限，播放器看到的就是一个 502。

## 一、做法

1. **传输层加一个可选能力**（`HTTPDownloadingTransport`，与 `HTTPTransport` 同文件）：
   `download(_:to:) -> HTTPDownloadedResponse` —— 响应体直接写进文件，内存里不堆整份。
   单独一个协议 + `as?` 探测，不塞进 `HTTPTransport`：站点 / 解析链要的是内存里的 `Data`，
   只有 `/proxy` 这条路需要落盘，别的实现与测试替身不受影响。
2. **真实现走 `URLSession.download`**（`URLSessionTransport`）：系统把响应体写进临时文件，
   再搬到暂存目录。广告拦截与 header 注入跟 `send(_:)` 共用同一个 `prepare(_:)` —— 规则只有一处。
3. **`/proxy` 的 GET 改走落盘**（`LocalProxyHandler`）：响应体落文件 → `HTTPBodySequence(file:)`
   交给 FlyingFox 流给播放器；`Content-Length` 由本机服务按**实际字节**重算
   （`ProxyForwardingPolicy` 的响应白名单本来就不放 `Content-Length` / `Content-Encoding` 过去）。
   HEAD 仍是缓冲那条 —— 没有响应体，不值得写盘。
4. **`/m3u8` 不动**：清单 / 分片 / 密钥还是缓冲式、还是受 32MB 上限保护 ——
   HLS 那条流量走 `/m3u8`、媒体文件那条走 `/proxy`，分流即分策略。
5. **清盘**（`LocalProxyTempFiles`）：FlyingFox 的响应体没有「发完了」回调，所以用「定期 + 宽限期」——
   每次新请求顺手清一遍超过 15 分钟的旧文件；上一次进程留下的残渣也会被顺手清掉。
   敢用宽限期的理由：文件是**下载完成后**才开始发（写的时候没人读），发送走回环，再大也在一两分钟内发完。

## 二、口径与取舍

- **落盘文件放系统临时目录**（`<tmp>/YPlayerProxy`）：不占用户可见空间；
- **不做 range 切片转发**：上游的 Range 响应体原样落盘、原样发回 —— 切片是上游的事，本机只搬字节；
- **失败语义不变**：落盘失败 / 上游失败都是 502 + 可读原因（与缓冲那条一致）；
- 不支持落盘的传输实现（测试替身 / 将来的别的实现）自动退回缓冲版，行为与 M06b 完全一致。

## 三、故意没做

- 边下边发（上游还在写就开流）：要自己管连接生命周期与断点，收益只有「首字节早一点」；
  `/proxy` 本来就是给播放器做 Range 请求用的，先落完再发更简单也更稳；
- 落盘文件池 / 复用：一次请求一个 UUID 文件，清掉即回收；
- 磁盘配额：宽限期 + 每次清扫已经把稳态占用压到「最近一两分钟取过的数据量」，真出事再说。

## 四、验证点（Mac）

1. `swift test --package-path Packages/CatVodNet`：新两条 ——
   「落盘转发：传输层带落盘能力时，超过缓冲上限的响应照常回」（上限压到 1KB、响应 4KB，仍 200 全量）
   与「落盘文件清扫：超过宽限期的清掉、新的留着」；
2. 全包测试 + App 编译照旧（**新增了文件**，跑之前 `rm -rf Packages/*/.build`）；
3. **上机**：播一个**带 header 的大文件直链**（>32MB，走 `/proxy`）—— 以前会在 32MB 处 502，
   现在应该能一直播下去；HLS 源（走 `/m3u8`）行为不变。

## 五、教训（写给下一次）

- 「可选能力用单独协议 + `as?`」是这次的省事点：不用给所有 `HTTPTransport` 实现添方法，
  也不破坏既有测试替身；代价是运行时探测（探测不到就退回旧行为，语义仍正确）；
- `URLSession.download` 的临时文件是**系统拥有**的：要 `moveItem` 搬到自己的目录，
  别原地引用（系统会在任务结束后回收它）。
