# M16P7 配置中心（网页条目）可点击

- 状态：**已实现**（本地静态自检过；真机由 YG 用 Mac 验证）
- 时间：2026-10-09
- 触发：用户截图 —— 「配置|中心」站点那一页的卡片点不动（点进去是详情页，里面什么都没有）
- 依据：Mac 上对**运行中的宿主**实测（curl），返回体是（原文照抄）：

```json
{
    "class": [{"type_id": "setting", "type_name": "http://127.0.0.1:9988/website"}],
    "filters": {},
    "list": [{
        "vod_id": "config-center",
        "vod_name": "扫码配置",
        "vod_pic": "http://127.0.0.1:9988/website/api/config/qr?url=http%3A%2F%2F192.168.110.68%3A9988%2Fwebsite",
        "vod_remarks": "点击打开配置中心"
    }]
}
```

读出来三件事：

1. **分类名就是配置中心地址**（`type_name = http://127.0.0.1:<port>/website`）—— 所以发现页顶部那行大字是分类名；
2. 卡片是「**按钮**」：`vod_id = config-center` 既不是线路也不是 vodID，详情接口里没内容；
3. QR 是宿主自己的接口（`GET /website/api/config/qr`，路由表见 `Tools/out/bundle-routes.txt`），
   扫码得到的是**局域网**地址（给手机用），App 内要开的是**回环**地址。

## 一、规则（`WebEntryRules`，纯逻辑 + 单测）

`webURL(for:site:)` 返回非 nil 就当网页条目：

1. `vod_id` 本身是 `http(s)` 地址 → 直接用它（上游存在「条目即网页」的写法）；
2. `vod_id == "config-center"` → 用**站点 api 的 scheme + host + port** 拼 `/website`
   （与 bundle 自己给的地址一致；**不去解析分类名** —— 那个字段是给人看的，不是给程序读的）。

其余条目照旧走详情页。

## 二、界面

- `HomeView` 里两处海报（纵向网格、横向分区）共用一个 `posterLink`：
  网页条目是「点开 sheet」，普通条目还是 `NavigationLink` → 详情页；
- 落点是 `WebPageSheet`（`CatVodUI/Platform`）：App 内 `WKWebView` + ✕ 关闭（与「筛选站源」同一个头部形态）。
  **不用外部浏览器**：宿主就在 App 进程里（`127.0.0.1`），跳出去就回不来了。

## 三、故意没做

- 不做「网页首页」那种整站 WebHome 宿主（矩阵里那条决定不变）：这次只处理**单个网页条目**；
- 不解析 `type_name` 里的地址（分类名可能是任何东西，凭它猜地址迟早出错）；
- 不做前进/后退按钮（WKWebView 的侧滑返回已经够用；真需要再加）。

## 四、验证点（Mac）

1. 发现页切到「配置|中心」：卡片还在（QR + 「点击打开配置中心」）；
2. **点卡片** → App 内弹出配置中心网页（不是跳 Safari、也不是进详情页空白）；
3. 网页能滚动、能操作，✕ 关闭后回到发现页。

## 五、没接的另外一半（记着）

宿主 `/website` 是给**手机浏览器**用的完整配置页；App 内 WKWebView 打开后，
「扫码配置」那张 QR 是给**另一台设备**看的 —— 本机上其实直接点开就行。
