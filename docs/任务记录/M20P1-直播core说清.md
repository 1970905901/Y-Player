# M20P1 直播 `core`（tvbus）：看出它、说清不支持

- 状态：**已实现**（本地静态闸门全绿 + 新单测；攒着下次上机验）
- 时间：2026-10-10
- 触发：`LiveSource` 的 `CodingKeys` 里**没有 `core`** —— 内核注入源（tvbus 等）的标识被静默丢掉，
  于是 App 会把它当普通清单源去拉 `url`，最后抛一个看不懂的「取清单失败 / 非 2xx」，
  用户只会以为「这个源坏了」，而不是「本平台没有这个引擎」。

## 一、做到哪一步

**只做到「说清」，不做引擎**（tvbus 要握手与解密，属内核阶段 —— 矩阵里也是这么记的）：

1. `LiveSource` 解出 `core`（`AnyJSONValue`，认不出的形状不猜）+ 三个派生：
   `coreEngine`（`core.type`，如 `tvbus`）、`requiresCoreEngine`、`coreUnsupportedReason`
   （原因文案**只此一份**，界面与错误共用）；
2. `LiveRepository.load`：`core.type` 非空**先拒绝**再抛 `unsupported`，**一次请求都不发**
   （与「Spider 源（api 非空）」同一条口径）；
3. 直播源列表那一行：直接写「清单（…）· **不支持 core 内核（tvbus）**」——
   点进去才发现是最差的一种设计；
4. 矩阵里那一行从「⏳ 内核阶段」改成「❌ 明确不支持（M20P1）」并写清降级行为。

## 二、故意没做

- **不做 tvbus 引擎**：那要复刻它的握手与解密流程，属内核阶段；
- 不解析 `core` 里的 `auth`/`broker`/`sign` 等参数：用不上就不解（解了只会让人以为快支持了）；
- 不把这种源从列表里藏起来：藏掉用户就不知道为什么配置里的源少了一个 —— **写出来**才是对的做法。

## 三、验证点（Mac，和下一批一起跑）

「设置 → 源地址」里先加载一份带这种源的配置（内联即可）：

```json
{"lives":[{"name":"TVBus源","type":0,"url":"https://live.example.com/x","core":{"type":"tvbus"}}]}
```

1. 「直播 → 设置 → 直播源」那一行应写着「… · **不支持 core 内核（tvbus）**」；
2. 选中它加载：应立刻报「该直播源用 `core` 内核（tvbus），本平台没有对应引擎，取不到清单」，
   而不是 404 / 解析失败那种无头绪的错；
3. 别的普通源（没有 `core`）行为不变。
