## 一、长按临时加速

上游的路线：长按画面（不在边缘、不是多指、没在缩放）→ `PlaybackAction.startSpeedPress` 把速度设成
`SpeedSetting.getLongPress()`（默认 `LONG_PRESS = 2.0`，存 `speed_long_press`）；松手 `onSpeedEnd`
把速度设回 `SpeedSetting.getPlayback()`（用户存档的那份）。按住期间 `changeSpeed = true`，
`onScroll` 直接 `return` —— 手指抖一下也不会变成拖进度。

| 上游 | 这里 |
| --- | --- |
| `SpeedSetting.LONG_PRESS = 2.0` | `SpeedSetting.longPress`（**可调 + 存档已在 M03P13 接上**：播放页「长按倍速」滑杆，键 `yplayer.playbackLongPressSpeed`） |
| `if (!player().isPlaying()) return;` | `canStartSpeedBoost(isPlaying:isBoosting:)`（纯函数，有单测） |
| 按住期间提示常亮（`play_speed_hint` 用 `SpeedSetting.format`） | 手势提示条显示 `2.0x`（与进度 / 音量 / 亮度共用同一条） |
| `changeSpeed` 期间 `onScroll` 不做事 | `isSpeedBoostHolding` 期间整条 `DragGesture` 不做事（不在播时也一样：手势接管，但不加速） |

两处不得不那么写的地方：

- `LongPressGesture` 自己的 `onEnded` 在**识别成功**时就发（按住够 0.5 秒那一刻），拿不到「松手」——
  所以用 `.sequenced(before: DragGesture(minimumDistance: 0))` 串一个零距离拖动，让整个序列跟着手指结束；
  `onChanged` 里拿到 `.first(true)` 才开加速；
- 长按那条用 `simultaneousGesture` 挂（与点按**同时**识别）：**不能用 `exclusively`** —— 那会把正常单击
  一起赔进去（长按失败时才轮到点按，而那时 touch-up 早过去了）。代价是 SwiftUI 的 `TapGesture` 没有
  「按多久算点按」的上限，长按松手会补发一次单击 —— 用 `shouldSwallowTap()` 吞掉
  （长按这次触摸期间 / 松手 0.5 秒内）。「长按已识别」与「真加速了」是两件事实：
  `isSpeedBoostHolding`（手势接管，含不在播时）与 `isSpeedBoosting`（速度真被切过，松手要回）。

## 二、左半屏亮度 / 右半屏音量

上游 `CustomKeyDown`：纵向拖时按**手指所在的外侧四分之一屏**分派（左外 1/4 → 亮度、右外 1/4 → 音量，
中间 1/2 的纵向拖不做事）；横向主导 → 进度。

| 上游 | 这里 |
| --- | --- |
| 纵向拖按外侧 1/4 分派 | **按起点分左右半屏**（左亮度 / 右音量，中线算右半屏）—— M03P6 留口原文就是「左半屏 / 右半屏」，这也是主流播放器的分法 |
| 按**当前**点判（拖过中线会换项） | 按**起点**判一次，这次拖动中途不换（横向拖到一半拐弯也不会跳成调音量） |
| 亮度写 activity 窗口属性（App 内亮度） | iOS 只有**系统亮度**（`screen.brightness`，没有「App 内亮度」这回事）；`UIScreen.main` 从 iOS 16 起被弃用，走前台窗口场景的 `screen` |
| 音量 = 系统媒体音量（`AudioManager`） | App 内相对音量（`engine.setVolume`，与 M03P6 一致；系统音量归硬件键） |
| 拖动中即时生效 | 亮度即时生效（系统状态，没有「提交」一说）；音量**松手才下发**（一次内核调用，几十个中间值没必要逐个发） |

- 换算共用「纵向 200pt 走满量程」（`verticalPointsForFullRange`）；
- **macOS 没有公开的屏幕亮度 API**：`PlatformShims.screenBrightness()` 给 `nil`，这种拖动
  **整次不做事**（连提示都没有）—— 不摆一个「拖了没反应」的假手势（「不写假话」）；
- 亮度的效果是**系统级**的：调完退出 App 亮度保持（上游退出播放页窗口亮度就没了，这是平台差异）。

## 四、验证点（Mac）

1. 内核 = MPV 或自研 FFmpeg，播放中：**按住画面 0.5 秒** → 顶部出现 `2.0x`、声音明显变快；
   **松手** → 回到用户那份倍速（先把「播放速度」设成 1.5x 再试：松手应该回 1.5x，不是 1.0x）；
   按住期间横 / 纵拖不改变进度 / 音量；
2. 暂停状态下长按 → 不加速（上游同款守卫）；松手时控制条**不该**闪一下（吞点按生效）；
3. **左半屏**纵向拖 → 「亮度 N%」，屏幕真的变亮 / 变暗；**右半屏**纵向拖 → 「音量 N%」，松手声音变；
4. 正常**单击**（切换控制条）/ **双击**（播放暂停）照旧 —— 长按那条不该把它们吃掉；
5. 横向拖进度照旧：拖动中预览 `目标 / 总时长`、松手才 seek。

## 五、教训

- `PlaybackView.swift` 的行数又顶到 `file_length` error（800）门口：这次把**手势整块**拆去
  `PlaybackView+Gestures.swift`（与 `+Overlays` / `+Stats` / `+Download` 同一套做法，拆完 732 行）——
  顺带把换算的纯函数收进一个文件，好读好测；
- `@State` **只能声明在主声明里**（扩展里不行）：新状态（亮度基准 / 这次拖动调什么 / 长按加速）
  加在主文件；跨文件用到的成员一律去 `private`（`check_visibility.py` 只管两个方向，这种要人记）。
