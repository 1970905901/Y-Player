# M06j 代理会话池与代理认证

- 状态：代理选择已接进传输层（HTTP / SOCKS 会话池 + 代理认证 + 传输按接口缓存）；**顺序失败切换**与
  **SOCKS 认证**是有意不做的两项（平台限制 / 范围取舍，见第四节）
- 时间：2026-10-09
- 依赖：`Core` 里早已就位的 `ProxyRule` / `ProxyEndpoint` / `ProxyRuleResolver`（对齐上游 `bean.Proxy` 与 `OkProxySelector`）

## 一、欠的是什么

矩阵那一格长期写着「选择已就绪；真正走代理的会话池未做」—— 说得很准：

- Core 把「按 host 选哪条代理」算得清清楚楚（`ProxyRuleResolver.selection(forHost:)`：
  非通配优先、本地地址直连、命中但解析不出地址回落直连、`user:pass` 也解析好了）；
- 但 `URLSessionTransport` 压根没碰它，所有请求一律直连 —— 也就是「规则都懂了，就是没用」。

## 二、会话池：为什么必须按端点缓存

代理是**会话级**的：`URLSessionConfiguration.connectionProxyDictionary` 在 session 建好之后不能改。
而「用哪条代理」取决于**目标 host**，所以一个 session 打天下是不行的。做法：

- `Configuration.proxyResolver` 是个闭包 `(host) -> ProxyEndpoint?`，传输层每次请求问一次；
- 问到端点就去 `proxiedSessions[endpoint]` 取；没有就**用基础配置 `copy()` 一份**、塞进代理字典、
  建一个新 session 存进池子。同一个代理只建一次 —— 否则每个请求都要重建连接、cookie、内存。

顺带一个必须一起修的问题：`AppModel.transportForConfiguration()` 原来**每次调用都新建传输**。
池子和 cookie 都挂在传输内部的 `URLSession` 上，每次动作新建一个传输等于把两者一起丢掉。
现在按「接口换没换」缓存（`load()` 里清掉），换接口必然重建、同一个接口内复用。

## 三、一个回调里的两种认证

`URLSession` 把「代理要认证」和「站点要认证」塞进**同一个** `didReceive challenge`，只能靠
`protectionSpace.proxyType` 区分（代理的保护空间才有它）。分不清的后果很实在：

- 拿代理的用户名密码去答站点的 401 —— 凭据泄漏给站点，而且照样登不上；
- 反过来，代理要认证时答「默认处理」—— 代理连不上，用户只看到「什么都加载不出来」。

所以 `ProxyAuthDelegate` 只答代理那一侧，其余一律 `.performDefaultHandling`。
判断被抽成纯函数 `shouldAnswer(proxyType:hasCredential:)`：真的代理挑战在测试里造不出来
（`proxyType` 只有系统生成的保护空间才有值），那就把判断本身拿出来测，delegate 只负责调用它。

## 四、两处「不做」，都是明说的

1. **SOCKS 认证不支持**：`connectionProxyDictionary` 里 SOCKS 只有 `SOCKSEnable` / `SOCKSProxy` / `SOCKSPort`
   三个键，没有用户名密码的位置 —— 系统层面就不给。带凭据的 SOCKS 代理在这里会连不上，
   这是平台限制，不是漏了（凭据仍然解析得出来，只是没处用）；
2. **顺序失败切换没做**：上游 OkHttp 的 proxy 列表语义是「第一条连不上换第二条」，
   本项目当前只取 `endpoints.first`。要做对得在 `send` 里按「连接级错误 + 幂等方法（GET/HEAD）」重试，
   而不是见错就换 —— 否则 POST 可能被发两次（这是有意留给后续的，记在这里免得被当成疏忽）。

HTTP 代理的字典里 **`HTTP` 与 `HTTPS` 两套键都给**：只给 HTTPS 的话，明文 HTTP 请求会绕过代理 ——
那正是「以为走了代理、其实漏了一半」的经典坑，也是这一节里唯一必须写对的细节。

## 五、测试

`ProxySupportTests`（Net）：

- 两套键的映射（HTTP 给 `HTTP`+`HTTPS`、SOCKS 只给一套且不带凭据）；
- **配了代理确实走代理**：把代理指向本机一个必定连不上的端口（`127.0.0.1:9`），请求因此失败 ——
  只要失败就证明走的是代理（直连的话它会去连真站点，CI 上未必有网，测不了）；
- 解析器返回 `nil` 时直连，且**解析器确实被问到过**（用一个线程安全的标记闭包断言）；
- 认证只答代理那一侧（`shouldAnswer` 四组取值）。

## 六、遗留

1. 代理列表的顺序失败切换（第四节第 2 条）；
2. SOCKS 认证（平台限制，做不了）；
3. `doh` 仍是另一件事（矩阵里单独一格：自定义 `URLProtocol` 未做）—— 与本轮无关，别混在一起；
4. 真机验证：配一个真代理 → 站点走代理加载 —— 只有单测层面的证据。
