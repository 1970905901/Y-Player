# M08e AppModel 集成夹具（内联配置 + 隔离存档）

- 状态：夹具 + 8 条集成测试落地；本地只能验格式与解析，**用例要在 CI 上首跑**
- 时间：2026-10-09
- 依赖：M06e–M06l（站点面板与广告线）、M08c（弹幕接线）—— 那些笔记里都写着「没有单测」

## 一、为什么值得专门做

M06l 与 M08c 的记录里都有一句老实话：**接线没有单测，因为测试里构造不出完整 AppModel**。
这话站不住：

- `AppModel.init(cacheDirectory:defaults:)` 本来就允许注入临时目录与隔离的 `UserDefaults`；
- **内联配置**（`{…}` 那种）由 `ConfigLocator` 直接当本地配置处理，**不需要网络**；
- `ensureLocalServer()` 只在 `RootView` 出现时调用，**不在 `init`** —— 所以夹具不会占端口。

也就是说「只能在调用点审查」的那类胶水代码，其实是可以真的跑起来验的。
这套测试的价值不在「再测一遍纯逻辑」（那些各自有单测），而在验**接起来了没有**：
改名有没有真的换掉分组标签、开关规则有没有立刻反映到 `siteGroups`、统计归零有没有落到提示上。

## 二、夹具

`AppModelFixture`（`Packages/CatVodUI/Tests/CatVodUITests/AppModelFixture.swift`）：

- 临时目录（缓存与数据库都在这里）+ 隔离的 `UserDefaults(suiteName:)`，`tearDown()` 把两者都清掉；
- 默认内联配置：两个站点，名字里带 `[主力]` 与 `|4K`，所以分组条一定是 `[主力, 4K, 首页]`；
- `reopenedModel()`：用**同一份存档**再起一个模型（配合 M08f 验落盘往返）。

## 三、测试

`AppModelIntegrationTests` 八条：

1. 内联配置载入：站点与分组条都对；
2. 改名（M06f）：显示名换掉、旧标签跟着消失、恢复原名能回去；
3. 内置规则开关（M06g）：关掉竖线规则 → `4K` 立刻消失，再打开又回来；
4. 自建规则（M06g）：加一条进分组条；同一条不重复加、正则编不出来不存；
   删掉时**连它的开关记录一起清**（否则「恢复默认」会永久失效）；
5. 分组上移（M06e）：落进存档，重排后站点集合不变；
6. 跳过广告（M06k/M06l）：统计落到提示文案上，归零时提示也清；
7. **HLS 规则接线（M06d/M06h）**：载入带 `hlsRules` 的配置后规则进了 `adRuleStore`
   （`/m3u8` 每请求现读的那个盒子）；本地关掉开关 → 列表与 store 同时变空；`nil` = 恢复默认；
8. 弹幕守卫（M08c）：开关关着 / 没填地址时**不发请求**且不显示状态行
   （只测守卫路径 —— 真发请求那条线属于网络，测试里不碰）；
9. 落盘往返（M08f）：见 `M08f-偏好存储注入.md`。

## 四、顺手修的一处矩阵口径

`subs` / `danmaku` 那行原写「字幕：模型」，但 Core 里连字幕模型都没有
（grep 只匹配到无关的 `Substring` / `subscript`）—— 已改为如实说明：本项目**没有**字幕模型/解析/渲染，
也没有做计划；上游那套（`player/exo/ass/*`、`player/exo/subtitle/*`）是 ExoPlayer + 原生 ASS 库的
Android 路径，iOS 上要么等 MPV 渲染路径（libmpv 自带 ASS），要么给系统内核另写外挂字幕渲染。
**写错的原因**正是这一整天在防的那件事：照着「应该是这样」的旧描述抄，而不是去看代码。

## 五、遗留

1. **视图层的触发点仍无法测**：`PlaybackView` 的 `onStart` / `onDanmaku` 是闭包回传，
   要验的是「视图真的调了它们」——需要 UI 测试或设备，本地与 CI 都做不到；
2. 这套是**集成测试**，CI 首跑要盯：若某些环境（无 GRDB 文件权限、临时目录受限）跑不动，
   降级方案是「只保留不碰存储的那几条」，而不是把夹具删掉；
3. 弹幕真发请求那条线（地址填对了、源返回 200 条）没测，属于 M08c 的遗留，同样需要网络桩。
