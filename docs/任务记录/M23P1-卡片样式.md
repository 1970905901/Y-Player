# M23P1 卡片样式（`style`）：配置说要横幅就横幅、要圆的就圆的

- 状态：**已实现**（本地闸门全绿 + 新单测；攒着下次上机验）
- 时间：2026-10-10
- 触发：做「有没有谁声明了却没人用」的普查时发现 —— `CardStyle` / `CardStyleResolver` /
  `VodItem.style` / `Site.style` 全在，`resolvedStyle` 也算得出来，
  但 **`CatVodUI` 里一次都没用过**：首页网格永远 2:3 竖幅 + 圆角矩形。
  而作者那套 JSON 配置里 **9 个站点**都写着 `"style":{"type":"rect","ratio":1.433}`（横幅卡）——
  也就是说配置提的要求，我们从来没照做过。

## 一、做法

1. `PosterCardLayout`（纯换算 + 单测）：`CardStyle` → 网格里实际用的两个数（宽高比、是不是圆）；
2. `DiscoverPosterCard` 多一个 `var style: CardStyle? = nil`：
   - **声明了才照做**：没写样式的配置**保持参考视频那个 2:3**（不跟 `CardStyle.resolvedRatio`
     的兜底值 0.75 走 —— 那会让所有配置突然变版式）；
   - `oval` / `circle=1` → 圆形卡（`Circle()` 裁剪，比例按 1:1）；
   - iOS 15 没有 `AnyShape`，圆与圆角矩形**分成两个分支各画各的**；
3. `HomeView` 两处网格（纵向 3 列、横向分区）都传 **站点级**样式 `selectedSite?.style`。

## 二、一个刻意的取舍：条目级样式不接

协议上的优先级是「条目样式 > 站点样式」（`CardStyleResolver` 里已实现），但**网格里逐卡不同比例
会排成锯齿**（同一行高矮不一），所以这一轮只用站点级。这是**排版取舍，不是漏接**：
- 作者那套配置就是在**站点**上声明样式（9 个站点），站点级已经覆盖真实用法；
- 真要支持条目级，正确做法是整屏统一取一个比例（比如取该页第一个条目的），而不是每张卡各自为政。

## 三、故意没做

- 不接 `type: "list"`（协议里是「列表行」形态）：我们的首页只有网格与横滑两种版式，
  没有列表行布局 —— 现在按 `resolvedRatio` 当普通卡片画（1.0），要真做是另一片；
- 不改搜索海报墙（`AggregateSearchWall`）：那些卡来自多个站点，没有单一站点样式可用，
  保持默认 2:3；
- 不给设置里加「忽略配置样式」的开关：配置说什么就画什么，用户真要改，改接口配置更直接。

## 四、验证点（Mac）

1. 用带 `"style":{"type":"rect","ratio":1.433}` 的站点（作者那套 JSON 配置里很多）进发现页：
   卡片应变成**横幅**（宽 > 高），不再是 2:3 竖幅；
2. 换一个**没写 style** 的站点（例如你自己的内联配置）：卡片应仍是原来的 2:3 竖幅 ——
   这是「声明了才照做」的关键验证；
3. 找一个写了 `"style":{"type":"oval"}` 或 `"circle":1` 的站点：卡片应是**圆形**；
4. 横向展示（分区横滑）与纵向展示（3 列网格）两种版式都要看一眼。
