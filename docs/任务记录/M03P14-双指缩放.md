## 一、上游口径 → 本项目

| 上游 | 这里 |
| --- | --- |
| `scale *= getScaleFactor()`，`Math.clamp(scale, 1.0f, 5.0f)` | `PlaybackView.zoomValue(base:magnification:)`（纯函数，有单测）+ `zoomMaximum = 5` |
| pivot 用捏合焦点（`detector.getFocusX/Y`） | **锚点是画面中心**：拿不到捏合焦点 —— `MagnificationGesture` 只给倍数（iOS 17 的 `MagnifyGesture` 才有 `startAnchor`），而我们要留 iOS 15 那条 |
| `videoView.setScaleX/Y`（画面层缩放，控制条不跟着放大） | `.scaleEffect(zoomScale)` 只作用在画面层上，再 `.clipped()`；弹幕 / 字幕 / 控制条不放大 |
| `resetScale()`：进 / 退全屏、换画面比例、点「画面比例」按钮时归位 | **换画面比例时归位**（`scaleBinding` 里 `zoomScale = 1`）—— 我们没有全屏切换这回事 |
| 捏合期间 `onScroll` / `onTouchEvent` 不做事（`changeScale`） | `isZooming` 期间整条 `DragGesture` 不做事（捏合时两根手指也在挪，别串成调音量） |

两个 API 的版本分支：`MagnifyGesture`（iOS 17 / macOS 14 起）与 `MagnificationGesture`（老的、从 iOS 17
起被弃用）—— 部署目标是 iOS 15 / macOS 13，所以 `zoomable(_:)` 里两条都留（`@ViewBuilder` 分支，
与 `AdaptiveNavigation` 同一套做法）。这样**不多一类「故意的弃用警告」**。

## 二、口径

- 缩放是**一次性的「看细节」放大**，不落盘、不跨页面（退出播放页就回 1.0）；
- 没有「平移」：放大后不能拖动画面（上游也没有）—— 要换看哪一块，先捏回去再重新捏；
- 缩放不碰内核：`setScaleMode`（画面比例）与它是两回事，前者归引擎、后者是显示层的 `scaleEffect`。

## 三、故意没做

- **上滑 / 下滑切集**（上游 `onFlingUp` / `onFlingDown` → 下一集 / 上一集，`LiveSetting.isInvert()` 还能翻转方向）：
  SwiftUI 的 `DragGesture` **拿不到「这一甩多快」**（只有位移与预测终点），而纵向拖已经被音量 / 亮度占着 ——
  按位移阈值去猜「甩」会在调音量时误切集。要做得换成 UIKit 的 `UISwipeGestureRecognizer`（挂在画面层宿主上），
  得先把「UIKit 手势与 SwiftUI 手势竞技场谁先谁后」想清楚，留给后面的批次。
- **捏合焦点的 pivot**：见上表（iOS 15 那条 API 没这个信息）；
- **缩放比例的提示美化**：与其它手势共用一条提示（「缩放 2.0x」）。
