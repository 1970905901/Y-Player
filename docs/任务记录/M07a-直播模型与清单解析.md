## 三、设计取舍

1. **模型是值类型、解析是纯函数**：上游到处 `mutate` 单例（`LiveConfig.get()`），难以测试；
   这里 `parse(_:into:) -> LiveSource` 进出都是值，测试直接构造输入、断言输出。
2. **`LivePlaylistSettings` 独立成类型**：m3u 与 txt 共用同一套设置项与「累积 → 应用到频道」的时序，
   拆开后两条路径都不会各自演化。
3. **元信息频道过滤**：`更新时间…`/`update time…` 这类行是源里的说明文本，不是频道（上游 `isMetaChannel`）。
4. **编号规则照搬**：只有没写 `tvg-chno` 的频道才参与自动编号，且按**遍历顺序**连续编号（跨分组）。
5. **刻意保留的差异**（都写进代码注释）：txt 路径每条地址后不 `clear` 设置（与上游一致，是上游的行为不是 bug）；
   分组同名匹配只看名字；EPG 拆分用 `contains("xml")/contains("gz")` 的原始判断。

## 四、明确未做

1. **DRM / ClearKey**（`license_key` / `license_type` / `drm_legacy` / `forceKey`）：解析器识别但不解析，
   播放侧也没有 Widevine/PlayReady（README 已声明不支持）。
2. **EPG**：`epg` 字段的接口/文件拆分已做，拉取 XML/GZ、节目单覆盖与时移时间选择属 M07b。
3. **js2p / Spider 的 `liveContent`**：`api`/`jar` 非空时清单由 Spider 提供，接 Spider 通道属后续。
4. **界面与播放接线**：直播页（分组/频道列表、线路切换、时移入口）、播放时的 header 注入
   （直接复用 M6 的 `/proxy` 与 `/m3u8`）属 M07c。
5. **收藏（keep）与「上次观看」恢复**：`LiveSource.keep` 字段已在模型里，读写流程属 M07c。
