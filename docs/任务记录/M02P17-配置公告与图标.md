# M02P17 配置公告与图标（`SourceConfig.notice` / `.logo`）

- 状态：**已实现**（本地静态闸门全绿 + 新集成测试；真机由 YG 用 Mac 验证）
- 时间：2026-10-09
- 触发：矩阵里那行 ⚠️ —— 这两个字段**一直解析进来就丢**（`SourceConfig` 里有，全仓没有消费方）
- 为什么这件事不算小：公告是配置作者给用户的话（「本站已更换域名」「旧接口将于 X 日失效」），
  丢掉的后果是**用户直到接口失效都不知道**

## 一、公告（`notice`）

**发现页顶部一条横幅**（在滚动区里，不钉在屏幕上 —— 该页是整屏滑动，不为公告常驻一条栏）：

- 两行截断，**点文字展开全文**（`lineLimit(nil)`），再点收回去；
- ✕ 关掉就不再出现；
- 关掉的判据是**文字本身**（`AppModel.dismissedConfigNotice`，落盘）：同一条不重复弹，
  配置换了新公告（文字变了）会再出现一次 —— 不做指纹、不做 TTL，公告的作用就是让人看见；
- **关掉的只是横幅**：接口管理页（「设置 → 源地址」）里那一块照旧显示全文，
  「看过了」不等于「再也找不到」。

## 二、图标（`logo`）

接在接口管理页的「配置」区：小图标 + 一行「配置图标」。

- **只认带 scheme 的完整地址**：上游 `logo` 也可能是相对路径，App 里没有基准地址可拼 ——
  宁可整块不显示，也不画一个破图框；
- 不做「用配置图标换 App 图标」：iOS 不允许运行时改 App 图标（那是打包资源），
  这一点别再被提一次。

## 三、落点（两个视图 + 一层偏好）

| 位置 | 文件 | 做什么 |
| --- | --- | --- |
| 横幅 | `HomeView.noticeBanner` | 显示/展开/关掉 |
| 全文与图标 | `InterfaceManagementView.configInfoSection` | 只读展示 |
| 取数与偏好 | `AppModel+ConfigNotice.swift` + `AppModel` 的 `dismissedConfigNotice` | 从 `state.loadedSource?.config` 取，关掉的状态 `@Published` + 落盘 |

`dismissedConfigNotice` 走的是本仓既有的偏好写法（`@Published` + `didSet` 落盘 + `init` 时装载），
不是计算属性 —— 计算属性不会触发 `objectWillChange`，点了 ✕ 横幅不会消失。

## 四、故意没做

- 不做跑马灯（参考实现那种横向滚动）：一条可展开的文字更省事，也更好读；
- 不做「公告弹窗」：打断式弹窗比横幅烦人，公告多半是「有空看一下」的信息；
- 不按配置地址分桶记「已读」：公告是给人看的文字，换了内容就该再看一遍，按地址分桶反而会漏。

## 五、验证点（Mac）

在「设置 → 源地址」的地址框里贴一份**内联 JSON**（不联网也能验，`{` 开头的地址由 `ConfigLocator` 当本地配置处理）：

```json
{"sites":[{"key":"a","name":"甲站","type":3,"api":"http://127.0.0.1:9988/spider/a"}],
 "notice":"本站已更换域名，请到 xxx 获取最新配置","logo":"https://example.com/logo.png"}
```

1. 点「加载」→ 回发现页：顶部出现一条橙色横幅（喇叭图标 + 公告）；
2. 点文字 → 展开全文；再点 → 收起；
3. 点 ✕ → 横幅消失；切走再回来 / 重启 App → **仍然不出现**；
4. 把内联 JSON 里的公告改几个字再「加载」→ 横幅**再出现一次**；
5. 「设置 → 源地址」里：配置区有图标（能加载出来就是对的）与公告全文。
