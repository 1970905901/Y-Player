# M03P6 MPV 播放页手势（双击 / 横拖进度 / 纵拖音量）

- 状态：**已实现**（本地静态自检过；真机由 YG 用 Mac 验证）
- 时间：2026-10-09
- 起因：A 第二块 —— MPV 的画面是一层 metal，**没有系统播放器那套手势**；
  第一版只给了自绘控制条（能点能拖），但看片最常用的「双击暂停」「横向滑调进度」都还没有。

## 一、手势约定

| 手势 | 行为 | 关键点 |
| --- | --- | --- |
| 双击 | 播放 / 暂停 | |
| 横向拖 | 调进度 | 拖动中只显示预览（`目标 / 总时长`），**松手才 seek** —— 一次拖动几十个中间值，逐个 seek 会打爆内核 |
| 纵向拖 | 音量 | 向上加、向下减；200pt 满量程；松手下发；拖动中显示百分比 |

换算：横向「拖满一屏宽 ≈ 120 秒」（`PlaybackView.seekSecondsPerScreen`），结果夹在 `0...总时长`。

**手势只挂在 MPV 上**：系统内核的画面是 `VideoPlayer`，它自带一整套手势，我们再叠一层只会互相打架
（与 M02P15「长按临时加速不做」同一条理由）。

## 二、协议新增：`PlayerEngine.setVolume(_:)`

| 内核 | 落点 |
| --- | --- |
| `AVPlayerEngine` | `AVPlayer.volume`（App 内相对音量；系统音量仍归硬件键） |
| `MpvEngine` | `set volume <0–100>`（mpv 的 `volume` 是 0–100，做换算） |

单测：MPV 侧断言命令串 `["set", "volume", "50.000"]`；系统内核断言 0...1 夹紧后写进 `AVPlayer`。

## 三、故意没做

- **单击显隐控制条**：单/双击判定要靠手势竞技场，做不好会出现「双击时控制条先闪一下」；
  控制条现在常驻（半透明、只占底部一条），真嫌挡画面再加；
- **左半屏亮度 / 右半屏音量**那种分区手势：亮度要动 `UIScreen.brightness`，和 App 内音量混着做容易乱；
- **手势提示的美化**（大号图标、动画）：先把功能跑通。

## 四、验证点（Mac）

1. 内核 = MPV，播放中：
   - **双击画面** → 暂停 / 继续（底部控制条图标跟着变）；
   - **横向拖** → 顶部出现「mm:ss / mm:ss」预览，松手跳到那个位置；
   - **纵向拖** → 顶部出现「音量 N%」，松手声音真的变了；
2. 内核 = 系统播放器：上面三种手势**不该**生效（`VideoPlayer` 自己的手势照旧）。
