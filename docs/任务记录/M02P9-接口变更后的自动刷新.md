# M02P9 接口变更后的自动刷新（+ 冷启动自动恢复）

- 状态：CI 已通过（2026-10-07，随 `e8d3bbf` 一并验证；见 `M02P11-设置页与追剧页.md` 的「验证记录」）
- 时间：2026-10-07
- 症状：在「接口」页加载/更换接口后，首页还是旧内容（或空白），要**杀进程冷启动**才刷新；
  而冷启动之后，首页同样得先去「接口」页手动点一次「加载」才有站点
- 影响面：`CatVodUI`（`AppModel` / `RootView` / `HomeView` / `SearchView`），不涉及协议、网络与宿主实现

## 一、根因（三条，互相独立）

| 现象 | 根因 |
| --- | --- |
| 换接口后首页不刷新 | `HomeView` 只在 `.task`（视图出现时）里加载首屏，而 `.task` / `onAppear` 在**回到已存在的 Tab 时并不保证重跑**；更要紧的是：**即使重跑**，`loadHome()` 也会因为 `result.categories` 非空而直接返回。于是 `selectedSiteKey` 与 `result` 一直指着上一个接口，**只有进程重启把 `@State` 全部丢掉才会真正重新加载** —— 这就是「必须冷启动」的来源 |
| 首页对接口变更毫无感知 | `AppModel` 发布的是 `state` / `hostSites`，而 `sites` 是**计算属性**：接口换了只会让 `body` 重算（站点菜单里的条目变了），**不会触发任何加载** |
| 冷启动要手动点「加载」 | `AppModel.init` 只把 `configURL` 从 `UserDefaults` 读回输入框，**从不发起加载**；`RootView` / `InterfaceManagementView` 也没有启动时加载 —— 持久化的地址只填满了输入框，首页永远从空态开始 |

## 二、修复

| 文件 | 改动 |
| --- | --- |
| `AppModel.swift` | 新增 `@Published private(set) var siteCatalogRevision`；`load(forceRefresh:)`（含地址为空与失败分支）、`restartHost()`、`stopHost()` 结束后 `bumpSiteCatalogRevision()`；新增 `loadSavedSourceIfNeeded()`（仅 `state == .idle` 时自动加载一次） |
| `RootView.swift` | `.task { await model.loadSavedSourceIfNeeded() }`：冷启动恢复上次保存的接口 |
| `HomeView.swift` | 新增 `@State loadedCatalogRevision`；`.task` 改走 `syncHomeWithInterface()`；新增 `.onChange(of: model.siteCatalogRevision)`；`.onChange(of: selectedSiteKey)` 改为先 `invalidateContent()`（旧代码只清分类/筛选/翻页，**不清列表**）；空态说明在接口加载失败时显示失败原因（不再显示自相矛盾的「请先加载配置」） |
| `HomeView+Data.swift` | 新增 `syncHomeWithInterface()` 与 `invalidateContent()` |
| `SearchView.swift` | 新增 `.onChange(of: model.siteCatalogRevision)`：旧站点与旧结果作废，选中的站点已消失时改选首个；空态说明同首页 |

### 关键设计取舍

| 取舍 | 决定 | 理由 |
| --- | --- | --- |
| 用什么当「接口换了」的信号 | 显式版本号 `siteCatalogRevision`，而不是比较 `model.sites` | ① `Site` 值相等不代表「这份清单是新拉下来的」；② **同一接口强制刷新**时站点清单可能一模一样，比较值会漏掉这次刷新；③ 版本号是自解释的状态，界面不用猜 |
| 版本号的自增点 | 加载 / 宿主重启 / 宿主停止各一处，**多调一次是安全的** | 界面按「版本号是否变化」去重（`loadedCatalogRevision`），所以嵌套调用点（`load()` 内部会走 `stopHost()`）不必精心安排顺序 |
| 监听后怎么发起加载 | `Task { … }`（非结构化），而不是 `.task` | `.task` 与视图生命周期绑定，离开首页 Tab 就被取消；而「接口换了」与用户此刻在看哪个 Tab 无关 |
| 换站点后的加载路径 | 统一交给 `.onChange(of: selectedSiteKey)`；`syncHomeWithInterface()` 只负责**改选站点**然后返回 | 否则一次切换会发两次首屏请求。顺带修掉了旧代码在「首页首次出现且有站点」时的重复请求（`.task` 里先改选站点、又自己 `loadHome()`，两次都真的发出去了） |
| 冷启动恢复的触发条件 | 只在 `state == .idle` 时恢复 | 冷启动时状态必然是 `.idle`；用户手动点过「加载」或刚失败过就不再插手（不覆盖操作、不自动重试） |
| 恢复走哪条路径 | `loadSavedSourceIfNeeded()` → `load()` | 复用增量校验（JS 源只多取一次 `index.js.md5`）与 JSON 源的离线回退，不新增第二套缓存/失败逻辑 |

## 三、验收

- CI：`CatVodUI (build only)` 编译通过 + Lint 0 违规 + 双端未签名构建通过。
- 人工（macOS / 模拟器 / 真机）：
  1. 「接口」页加载一个 CMS 源 → **不重启、不手动刷新**，切到「首页」应直接出现分类与内容；
  2. 再换另一个接口 → 首页自动换成新接口的站点与内容，且不再残留上一个接口的分类/列表；
  3. 填一个错地址加载失败 → 首页回到空态说明，而不是继续显示上一个接口的内容；
  4. 杀掉进程冷启动 → 首页自动加载上次的接口（不必先去「接口」页点「加载」）；
  5. JS 源额外看「接口管理 → Node 宿主」：点「重启宿主」后首页应自动换成新宿主站点。

## 四、未做（明确记录）

1. **已入栈的详情页/播放页不感知接口变更**：`VodDetailView` / `PlaybackView` 在入栈时持有 `site`，
   接口换了以后它们的请求仍会打到旧站点；正确做法是把「接口版本」带进详情页并在栈顶提示（属 M9 导航重构范围）。
2. **首页不做自动重试**：接口加载失败后只清空，不轮询（不在后台自发发请求）。
3. **不区分「前后台恢复」**：`loadSavedSourceIfNeeded()` 只是根视图出现时的一次性调用，M2 无后台任务语义。
4. **首页首屏仍会重复请求一次分类（既存问题，本次未动）**：`loadHome()` 里设置 `selectedCategoryID`
   会触发 `.onChange(of: selectedCategoryID)` 的 `loadCategory()`，而它随后又直接调用
   `loadCategory(categoryID:site:)` —— 同一分类同一页会发两个请求。要在不误伤「应用筛选」的前提下修，
   需要引入「同一分类正在飞」的去重状态；与「接口变更」无关，单独做更安全（本次只去掉了另一处重复请求：
   首页首次出现时 `.task` 与 `.onChange(of: selectedSiteKey)` 各发一次首屏请求）。

## 五、回滚

三处互相独立，可分别回退：

- `RootView` 的 `.task`（冷启动恢复）——删掉即回到「必须手动点一次加载」；
- `HomeView` / `SearchView` 的 `.onChange(of: model.siteCatalogRevision)`（自动刷新）——删掉即回到「必须冷启动」；
- `AppModel.siteCatalogRevision` 及其自增点——删除后其余改动无编译依赖（`HomeView.loadedCatalogRevision` 一并删除即可）。
