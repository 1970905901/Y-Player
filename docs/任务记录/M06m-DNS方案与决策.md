# M06m `doh` / `hosts`：平台缺口与三个方案（**待 YG 拍板**）

- 状态：**本轮已落地「如实上报」**（不生效就说出来）；**真正支持未做，等你选方案**
- 时间：2026-10-09
- 依赖：无（这一笔先止损，不引入新传输）

## 一、事实（已核对，不是猜的）

`SourceConfig` 里 `doh: [DohConfig]` 与 `hosts: [String]` **都被认真解析**（`init(from:)` 里逐个
`lenientArray` / `lenientStringArray`）—— 但**全仓没有一个消费方**，字段读进来、规则一条不生效。

这是「能读、没人用」的**属性级**版本（M08g 的审计脚本只看类型，正好漏这一类），而且更隐蔽：
配置作者写了 `hosts` 覆盖，行为与没写一模一样，没人会知道。

上游能做到是因为它跑在 **OkHttp** 上，OkHttp 暴露了 `Dns` 接口（换解析器 ≈ 十几行）；
**Apple 侧的 `URLSession` 没有对应钩子** —— 这是平台差异，不是偷懒。

## 二、本轮做了什么（止损，不需要你决定）

1. `ConfigCoverage`（Core）：`ignored(in:)` 挑出**有值**的不生效字段（`doh` / `hosts`）与原因；
2. 接进 `SourceConfig.validationWarnings` → `LoadedSource.warnings` → `AppModel.warnings`
   → 「接口管理 → 告警」。**界面一行没改**，因为告警区本来就读这份数据；
3. 三处过期注释改为实话（`URLSessionTransport` / `HTTPTransport` / `CatVodNet.Package.swift`
   原来都写着「DoH / hosts 在 M6 补上」，代理补了、这两项没补）。

测试：`ConfigCoverageTests`（有值才报 / 顺序 / 进告警）+ 夹具集成测试
（内联配置带 `hosts` + `doh` → `model.warnings` 里两条）。

## 二之二、顺带查出的四个字段（同一类问题，成因不同）

用同一个脚本（`Tools/out/audit_config_fields.py`，按「`SourceConfig` 的字段有没有被 `.字段名` 读过」
统计）扫出另外四个**只在测试里被读**的字段，一并纳入了上报：

| 字段 | 上游怎么用 | 我们的状态 |
| --- | --- | --- |
| `flags` | 播放页的 flag 选择菜单（配套 `FlagSelectionListener.java`） | 没有这个菜单；**站点详情自带的 flag 可正常切换**，配置里这份列表不生效 |
| `wallpaper` | 首页壁纸（`VodConfig` 里叫 `wall`，`getWall()`） | 首页还没接，属视图层 |
| `logo` | 配置图标 | 未使用 |
| `notice` | —（FongMi 的 `VodConfig` 里**没有**这个字段） | 未显示 |

后三个与 `doh`/`hosts` 的差别值得记一笔：**它们不是做不到，是还没接**。
所以矩阵里没有写成「平台缺口」，而是写成「解析得进模型但无消费方」——
将来接上（首页壁纸、公告栏）时，把对应条目从 `ConfigCoverage` 里去掉即可，那条告警会自己消失。

**这一节的由来**：矩阵原来把 `flags` / `wallpaper` / `logo` / `notice` 一起标成 ✅。
那是对着旧描述抄的，实际读一下代码就知道没人用。查证方式与结论都留在上面，便于复核。

## 三、三个方案（要真支持 `doh` / `hosts` 的话）

| 方案 | 覆盖范围 | 代价 | 风险 |
| --- | --- | --- | --- |
| **C：不做**（现状 + 如实上报） | — | 已付 | 无。用户至少知道「写了不生效」 |
| **B：只做 `hosts`，只对 `http://` 目标** | 明文站点能覆盖；`https://` 目标照旧不生效（如实说） | 低：在传输实现里按 hosts 表把主机换成 IP + 补 `Host` 头 | 明文目标无证书问题；要小心重定向到别的主机时不能再改写 |
| **A：自建连接层**（`Network.framework`） | `hosts` + `doh` 全覆盖，`https://` 也能覆盖 | 中高：自己保证 HTTP/1.1 语义（分块 / 压缩 / 重定向 / 超时） | **安全性不降**：连的是 IP，但 TLS 用 `sec_protocol_options_set_tls_server_name(hostname)`，证书仍按**主机名**校验 |

## 四、我的建议

**先按 C 收口（已完成）**，把「要不要真支持」当成一个独立需求来决定：

- 若你只是想让配置里的 `hosts` 生效来救几个被 DNS 污染/墙掉的站点 → 选 **A**，
  但分两步走：**A1** 先用自建连接覆盖 `http://`（能救一批），**A2** 再补 TLS 与 `https://`；
- 若你要的是「能连上某个只在特定 IP 上服务的站」→ **B** 就够，代价小得多；
- 若是「配置里有就顺手支持」→ **C** 已经做到了该做的部分：不生效，但说出来。

`HTTPTransport` 这条缝很适合做 A：所有出网请求（站点、JS `req()`、本机代理的上游）都走它，
且装配点只有 `transportForConfiguration()` 一处 —— **换一个传输实现，一次覆盖所有路径**。

## 五、验收标准（做 A 时按这个验）

1. 一条 `hosts` 用例：改写生效，且**证书仍按主机名校验通过**；
2. 一条 `doh` 用例：自签/错误证书必须被拒绝（证明安全性没降）；
3. 代理（`proxy`）、按 host 注入 header（`headers[]`）、广告拦截（`ads[]`）在这些请求上行为不变；
4. 告警里那两条**消失**（因为已经生效了）—— `ConfigCoverage` 是同一份真话的另一个方向。
