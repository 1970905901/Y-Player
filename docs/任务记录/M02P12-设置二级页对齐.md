## 三、真实生效的路径（逐条可追）

1. **源缓存时间**：`AppModel.load(forceRefresh:)` → `loadSource(target:forceRefresh:repository:)` 先问
   `repository.loadCached(configURL:maxAge:)`；命中就用缓存（不联网），过期或「刷新接口」才走网络。
2. **首页缓存时间**：`HomeView+Data.loadHomeResult(site:force:)` 与 `loadCategory(...)` 先查
   `model.cachedHomeResult(key)`，命中直接渲染、不发请求；`force: true`（工具栏刷新）绕过。
3. **三个清空**：源缓存 → `clearSourceCache()`；首页缓存 → `clearHomeCache()`；全部 → `clearAllCaches()`。
   「全部缓存」大小 = 两处之和（下载占用与本地库不算缓存，页内写明）。
4. **下载管理**：`StorageSpace.snapshot(downloadDirectory: AppModel.downloadDirectory)`；离线下载未接入，
   所以「下载 0B / 暂无下载内容」是真实状态，卡片下方写明缺什么。
5. **弹幕 API**：4 个地址真实保存（`DanmakuAPIConfig` 往返已单测）；执行链属于 M8，页内如实标注。
6. **显示视图**：`VodDetailView.content` 按 `model.playbackPageLayout` 在 `compactLayout` / `embyLayout` 之间切换，
   两者共用同一份数据与同一套工具（收藏 / 换源 / 续播）。
7. **自动播放**：`.task` 里 `loadDetail → loadProgress → loadFavorite → scheduleAutoPlayIfNeeded()`；
   有观看记录时不触发（留给「上次看到」），一次进入只触发一次。
8. **日志开关**：`AppModel.isEngineLogEnabled` → `applyLogPreferenceToHost()` /
   `refreshHost` 里的 `service.setLogPersistence(_:)` → `NodeRuntimeLaunching.setPersistsHostOutput(_:)`
   → `NodeMobileRuntime.persistIfNeeded(_:)` 追加落盘。
9. **导出**：`fileExporter` + `EngineLogDocument`；导出优先落盘日志，没有落盘时退回内存里的最近输出。

## 四、明确未做（诚实记录）

1. **弹幕的取回与渲染**：属于 M8；地址只是被可靠地存下来。
2. **离线下载**：只有空间条与空态，没有任务队列（分片下载 / 地址接管仍未开始）。
3. **Emby 服务端协议、KPlayer 这类第三方内核**：本项目没有对应实现，因此播放器页的
   「播放界面 / 播放控制」是内核专属设置的位置，当前如实写明「系统播放器不自绘控件，M3/M4 后才有」。
4. **macOS 进程方式的日志落盘**：`NodeRuntimeLaunching.setPersistsHostOutput` 的默认实现是空
   （进程输出的重定向由调用方决定），所以日志开关的落盘效果目前体现在内嵌 node（iOS）上。
5. **参考图里没有、我们额外保留的**：缓存管理页的「本地存储」（M08b 的落库路径与失败留痕）
   与「回收」（其他接口残留，M02P7 的能力）—— 只在真的有内容时出现，不占主结构。
