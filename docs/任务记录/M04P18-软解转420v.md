# M04P18 软解转 420v（NV12）

- 状态：**已实现**（本地静态闸门全绿 + 测试改断言；Mac 编译 / 测试 / 上机待 YG）
- 时间：2026-10-10
- 触发：M04P14 的软解那条路每帧要「YUV→RGB 换算 + 4 字节/像素的整帧拷贝」，而这条正是
  模拟器上跑的那条（模拟器没有 VT 硬解）—— 先把它的每帧成本降一档。

## 一、做法

1. sws 的输出格式 **BGRA → NV12**：`sws_scale_frame` 的目标帧两个平面，libswscale 只做尺寸 / 排布
   上的事，不再做 YUV→RGB 的色彩换算。
2. 自建 `CVPixelBuffer` 用 `kCVPixelFormatType_420YpCbCr8BiPlanarVideoRange`（4:2:0 双平面、
   video range）；新增 `copyPlane` 一个出口，两个平面各拷各的（Y = `height` 行、
   CbCr 交织 = `ceil(height / 2)` 行），行宽取两边小的那个。
3. **为什么是 420v**：显示层原生吃它 —— VT 硬解出来的帧本来就是 420v，软硬两条路交出去的
   东西长得一样；而且带宽从 4 字节/像素降到 1.5。
4. 播放信息的「输出」行随之写 `420v`（测试同步改）。

## 二、口径与已知取舍

- 仍然是 **8bit**：10bit / HDR 在软解这条路上会被压下去（HDR 靠硬解那条，没变）；
- 色彩矩阵还是「猜」的（sws 按尺寸猜、CoreVideo 按像素格式猜）—— 软解的色彩管理留到
  M04P2 拿 HDR 片子上机一起定；
- 4:2:0 对奇数尺寸按 `ceil` 取色度行数（CoreVideo 也是这么算的，两边一致）。

## 三、故意没做

- 10bit 软解（P010 → x420 直通）；
- 给 buffer 显式挂色彩附件（`kCVImageBuffer*`）——要等 M04P2 决定「以源为准还是以输出为准」；
- 内嵌字幕（M04 线最后一个功能缺口）。

## 四、验证点（Mac）

1. `swift test --package-path Packages/CatVodPlayer`：
   - 「Libav 视频解码」软解那条：像素格式 = `kCVPixelFormatType_420YpCbCr8BiPlanarVideoRange`、
     平面数 = 2、尺寸 / 时间戳照旧；
   - 「FFmpeg 真会话」软解那条：播放信息「输出」= `420v`；
2. 全包测试 + App 编译照旧；
3. 上机（模拟器走软解）：播放信息的「输出」行应写 **420v**；同一片源应比 BGRA 那版更省
   （帧率更稳、发热更低）。
