## 一、接线内容（逐条对齐 Demo）

| 项 | 值 | 在哪 |
| --- | --- | --- |
| `wid` | CAMetalLayer 的指针数值 | `LibmpvSession.applyVideoOutputOptions()` |
| `vo` | `gpu-next` | 同上 |
| `gpu-api` | `vulkan` | 同上 |
| `gpu-context` | `moltenvk` | 同上 |
| 画面层 | `MpvVideoSurface.layer`（`CatVodPlayer`，只依赖 QuartzCore） | 引擎持有它、界面挂进视图层级 |
| 宿主视图 | `MpvVideoView`（iOS `UIViewRepresentable` / macOS `NSViewRepresentable`） | `CatVodUI/Platform/MpvVideoView.swift` |
| 控制条 | MPV 没有系统控件 → 自绘「播放 / 暂停 + 进度 + 时间」 | `PlaybackView.mpvControls` |

**顺序要求（最容易踩）**：四个选项都必须在 `mpv_initialize` **之前**设 —— 它们是启动期固定项。
所以画面层要**先于引擎**创建（`PlaybackView.start()` 里 `settings.engine == .mpv` 时先建 `MpvVideoSurface`）。

## 二、可用性的口径变化

- `MpvAvailability.isVideoOutputReady`：false → **true**（路径已定并接线）；
- 于是 `PlayerEngineKind.mpv.isAvailable == true`：设置页可以选 MPV，不再显示「不可用」；
- `PlayerCoordinator.makeEngine(.mpv, ...)` 支持了，但**没给画面层仍返回 nil** ——
  宁可说不可用，也不给一个没有画面的播放器。

## 三、故意没做

- **HDR / 色彩管理**：Demo 提到 `target-colorspace-hint` 与「Metal API Validation 要关掉，否则放 HDR 会崩」
  （MoltenVK #2226）—— 第一版不碰，等基础画面确认了再说；
- **前后台切换的黑屏修法**（Demo 在 background 时设 `vid=no`）：先不抄，真机真再现了再按需加；
- **音频输出选项**：沿用 libmpv 默认（Demo 也没设 `ao`）；
- **拖动时的预览帧**：拖动只改界面位置、松手才 seek（够用）。

## 四、验证点（Mac / 模拟器）

1. 设置 → 播放 → 播放内核 = **MPV**；
2. 进任意一集播放：
   - **有画面**（不黑屏、不闪退）—— 这是第 3 步唯一必须真机确认的事实；
   - 自绘控制条能暂停 / 继续、能拖动进度；
   - 信息区「内核」显示 MPV；
3. 若黑屏 / 闪退：把 Xcode 控制台里 `mpv` / `MoltenVK` 开头的行发我 ——
   真出问题只改 `LibmpvSession` 的渲染选项，引擎与 seam 不动（这正是当初分层的意义）。
