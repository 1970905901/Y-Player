# M10n 断点续下（半途停下，下次接着下）

- 状态：**已实现**（账目 + 清单前缀指纹在 Core；执行器从账目续；库 v3 迁移；暂停时账目并进任务）
- 时间：2026-10-10
- 依赖：M10d（执行器）、M10b（落库）、M10l（范围片段）、M10m（暂停真的会停在半路）

## 一、为什么

M10m 之后，暂停会**真的停在半路**（分片之间 / 请求被打断）—— 可「继续」还是从第 0 片重下：
一集下到 90% 暂停，继续时前面 90% 白下。M10d 起就记着这个留口（「等真有需求再给任务加
`completedSegments`」），现在需求到了。

## 二、账目长什么样

| 字段 | 含义 |
| --- | --- |
| `DownloadTask.completedSegments` | 已经**完整**写进文件的片段数（含 fMP4 的 init 片） |
| `DownloadTask.resumeFingerprint` | 这前 N 片的**清单前缀指纹**（`HLSManifest.segmentFingerprint(prefix:)`，FNV-1a 64） |

指纹按**前缀**算而不是整份清单：续下只关心已经写进文件的那几片没变 —— 清单在后面长出新片段
不该害得整份重下。四道对账（`DownloadRunner.resumeStart`），任何一条不过就**从头下**：
没有账目 / 文件没了或比账目短 / 账目片数比清单多 / 前缀指纹对不上。

**文件按账目字节数对账**：文件比账目长 → 尾巴是上次写了一半的片段（进程被杀 / 写失败），
截到账目长度再续；比账目短 → 字节丢了，整份重下。

## 三、停下的两条路，账目都回得来

- **失败**：账目包在 `PartialStop` 里抛出来（写入进度是 `writeSegments` 的局部变量，
  抛错是唯一能带出来的通道），`run` 把它并进回执 → 队列按重试规则落库 → 重试 / 手动继续
  都从账目那一片接着下；
- **暂停**：取消结果**不落库**（M10m 的教训），所以 `AppModel.pauseDownload` 先写「已暂停」、
  再取消句柄、**等执行器停下**，把它交回的账目并进那条任务（`mergeDownloadLedger` ——
  只动账目、不动状态：用户在这中间点「继续」也不会被盖回去）。

完成时账目清零（续下只在半途有意义）。**直链不做续下**（一整块一次写，账目无处可对）——
重试 / 继续都是整份重下。

## 四、测试

- Core：指纹（同前缀稳定 / 前缀变了就变 / 后面长片段不影响前缀 / 范围不同指纹不同）；
- 库：账目字段往返无损（v3 迁移 + 列映射）；
- 执行器：失败留半成品记账目 → 修好后重试只取剩下的片；四道对账各一条（正常续 / 指纹变了整份重下 /
  文件短了整份重下 / 尾巴截掉续写）；
- 接线：暂停（HLS，第 2 片挂住）→ 账目 = 1 片；继续 → 第 1 片不再取，文件是三片拼起来的全部内容。

## 五、留口

- **SAMPLE-AES** 仍如实拒绝（要 CENC 取样解密）；
- **直链续下**（HTTP `Range` 按字节续）没做 —— 直链要另立账目（字节偏移），是另一件事；
- 后台下载 / 限速没做（M10a 记过）。
