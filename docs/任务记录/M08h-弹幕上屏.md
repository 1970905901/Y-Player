## 一、这一步补的是最后一环

弹幕链此前是「解析 → 取用 → 调度」都齐、**只差画到视频上**（M08d 的遗留 1）。
本轮把它接上，顺带把遗留 2（开关后立刻清屏）一并理顺 —— 后者其实**不需要专门写**：

## 二、三件事，各自单一

| 件 | 在哪 | 为什么单独拿出来 |
| --- | --- | --- |
| `PlaybackClock` | `PlaybackClock.swift`（M09f 起单独成文件，字幕也用；原名 `DanmakuClock`） | 引擎**每秒**才报一次位置，直接用会「一秒跳一格」；外推是纯算术，可测 |
| `DanmakuOverlayGeometry` | 同上 | 轨道 → 像素位置的几何，算错只会「看着有点乱」，真机上极难定位；纯函数，可测 |
| `DanmakuOverlay` | 同上 | `Canvas` 逐帧画 —— 这一件只能靠眼睛验 |

### 时间为什么必须外推

`SystemPlayerEngine+Monitoring.swift` 里 `addPeriodicTimeObserver(..., forInterval: 1s)`。
25 号字一格能跳十几个字宽 —— 直接喂 `latestPosition` 就是「一秒一格跳着走」。
`PlaybackClock` 记「引擎报的位置」+「什么时候报的」，两点之间按倍速线性外推，逐帧取时间。

两个细节是**为了不跳**：

- 改速率时**先外推再改**（`setRate`）：暂停发生在两次上报之间，直接换速率会丢掉那一段走过的距离，
  弹幕往回跳一下；
- 只在 `playing` 时走表：暂停 / 缓冲 / 结束 / 失败都停住 —— 否则「缓冲时弹幕还在划」会让人
  以为卡的是弹幕而不是网。

### 字号与行高按画面尺寸解出来

同一份 25 号弹幕，iPhone 竖屏的 16:9 视频区（高约 220pt）与 Mac 窗口（可能 700pt 高）
用同一个字号的话，小屏刚好、大屏就小得看不清。所以 `DanmakuDisplayStyle.resolved(width:height:)`
按「参考高度」缩放字号（夹在 0.45…1.6），**并且**用同一个比例算轨道高度 ——
宽度度量与轨道高度必须同源，否则会出现「按 20 号字量宽度、按 28 点排轨道」这种看不出来的错位。

## 三、接线（`PlaybackView`）

- 弹幕层挂在 `VideoPlayer` 之上（`ZStack`），只在有计划时才存在；`.allowsHitTesting(false)`，
  触摸留给系统控件；
- 计划在 `.task(id:)` 里排，键是「行数 + 首末时间 + 画面尺寸」—— 只在变化时重排。
  它是 O(行数 × 轨道数) 外加一次全量文本度量（几万条在设备上是几十毫秒量级），每帧重排会把播放拖垮；
- 行内容用「条数 + 首末时间」代表整份数组：比较几万条是 O(n)，而这个键每帧都要算。

## 四、已知粗糙处（都记在代码注释里）

1. **弹幕会从系统控制条上划过去**：控制条由 `VideoPlayer` 自己画，它在覆盖层下面。
   换自绘控制层（M3/M4 的 MPV / FFmpeg 内核）后自然消失，先不为它绕路；
2. ~~显示参数还是固定默认值~~ → **已做**：设置页在 M08i（`DanmakuDisplayConfig` → `DanmakuDisplayStyle`），
   字号 / 透明度 / 速度 / 显示区域都能调；
3. 单条弹幕自带超大字号时会顶到相邻轨道一点：轨道高度按「典型字号 25」算，
   而弹幕文件允许每条自带字号。比让所有弹幕挤在一起轻得多。
4. 孤儿审计（M08g）会把 `DanmakuOverlayGeometry` / `DanmakuResolvedStyle` 报成「只在测试里出现」：
   它们确实只被**同文件**的 `DanmakuOverlay` 用（外加单测），而审计口径会扣掉声明文件自己的引用。
   按 M08g 记的判法（本文件自用 ≥ 1 ⇒ 误报）忽略即可。

## 五、真机要看什么

1. 弹幕**是否连续滑动**（一秒一跳就是外推没生效）；
2. 暂停 / 缓冲时**弹幕是否停住**，继续播放后位置对不对（不跳、不落后）；
3. 2 倍速下弹幕速度是否跟着变；
4. 顶部 / 底部弹幕是否居中、滚动弹幕是否不叠（叠了是调度的问题，M08d 已钉过，
   但轨道到像素这一步是本轮新增的）；
5. 大窗口（Mac / iPad）上字号是否合适。
