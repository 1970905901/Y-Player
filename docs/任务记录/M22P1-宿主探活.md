# M22P1 宿主探活：把「现在这一刻还活着吗」接上界面

- 状态：**已实现**（本地闸门全绿 + 新单测；攒着下次上机验）
- 时间：2026-10-10
- 触发：`JS2PHostService.health()`（`GET /health`）与 `HostSiteCatalog.health(baseURL:)` **早就写好了**，
  注释还写着「宿主就绪后进程可能崩掉，界面据此提示」—— 但全仓**没有任何调用点**。
  于是宿主半路崩掉时，「设置 → 源地址」里照样写着「宿主运行中：…」，
  用户看到的是「明明显示运行中，站点却打不开」。

## 一、分工：`hostStatus` vs `hostHealth`

| | 含义 | 什么时候更新 |
| --- | --- | --- |
| `hostStatus`（已有） | **最近一次**刷新站点清单的结论（含端口、站点数） | 加载接口 / 重启宿主 / 停止宿主 |
| `hostHealth`（新增） | **现探**的一次答案：现在还在不在 | 进「源地址」页探一次；拿到清单时直接置 `online`（省一次请求）；点「检测宿主」再探 |

- 没有宿主时给 `.unknown`（不是 `offline`）——「当前接口不需要宿主」不等于「宿主挂了」；
- 离线文案带下一步：「离线 —— 宿主可能崩了，点「重启宿主」」（只报状态不给动作是半句话）。

## 二、改动

- 新增 `HostHealth`（三态 + 一句话文案，`public`：它出现在 `AppModel` 的 `@Published` 上）；
- `AppModel.hostHealth` + `refreshHostHealth()`（在 `AppModel+Host.swift`）；
- `refreshHost` 成功拿到清单后直接置 `.online`；`stopHost()` 置 `.unknown`；
- 「设置 → 源地址 → Node 宿主」区：加一行「探活」+ 一个「检测宿主」按钮；
  进页面时自动探一次（`.task`）。

## 三、故意没做

- **不做自动重启**：宿主崩了自动拉起听起来很美，但会把「站点自己 502」也当成宿主问题反复重启 ——
  先把状态说清楚，重启按钮一直在那儿（一键的事，用户按一下更可控）；
- 不做定时轮询：进页面探一次 + 手动检测已经覆盖「我要用之前确认一下」这个真实需求，轮询只是耗电；
- 不把探活结果塞进诊断报告：报告里已经有宿主状态与最近输出；真要加，等有人反馈「报告里看不出来」再说。

## 四、验证点（Mac）

用 JS 源（js2p）接口：

1. 「设置 → 源地址」→ Node 宿主区应多出「探活」一行，进页面后很快变成「在线（刚探过）」；
2. 点「检测宿主」→ 仍是「在线」；
3. **杀掉宿主**（终端里 `pkill -f "index.js"`，或从宿主输出那边找 PID）→ 回页面点「检测宿主」→
   应变成「离线 —— 宿主可能崩了，点「重启宿主」」；
4. 点「重启宿主」→ 状态回到运行中，探活回到「在线」；
5. 换回 JSON 接口：探活那行应是「尚未检测」（不需要宿主）。
