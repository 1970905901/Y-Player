## 一、为什么这两件事要一起做

M06e 把分组条接上了，但站点名还有两种状态没处理，而且它们共用同一个概念 —— **生效名**：

| 站点名的来源 | 优先级 | 谁在用 |
| --- | --- | --- |
| 用户自定义名 | 最高 | 面板行、工具栏、分组标签、搜索 |
| 配置里的原始名 | 次之 | 同上（没改名时） |
| 站点 `key` | 兜底（名字为空时） | 同上 |

所以「改名」不是换个显示字符串这么简单：**分组标签必须跟着重抽**。上游 `SiteNameRules.groups(rawName, customName)`
吃的是 `effectiveName`，本项目 M06e 的 `DiscoverSiteList.tags` 当初就按这个口径写好了输入（当时注释写着「我们还没有自定义名」）——
这一轮补上自定义名，那条注释里的口径直接生效。

搜索则只有一条规则，但它查**三个字段**（生效名 / 原始名 / key）：改过名的站点要能被原名搜到
（用户未必记得自己改成了什么），`csp_xxx` 这种 key 也要能被搜到（面板上看见的名字可能是空的）。

## 二、改名语义（逐条对齐 `SiteNameRulesTest`）

- `effectiveName(rawName, customName)`：自定义名去空白后非空就用它，否则用原始名；
- `displayName(rawName, customName, key)`：生效名为空时回落 `key`（上游 `SiteNameStore.getDisplayName`）；
- `customNameForStorage(rawName, inputName)`：输入去空白后**与原始名相同就返回空串** ——
  即「填成原名 = 恢复原名」。这一条看着琐碎，但少了它，用户点「还原」之后存档里会留下一条
  「看起来一样的自定义名」，于是「还原」这个动作永远消失（还原后仍然显示为已改名）；
- `groups(rawName, customName)`：对**生效名**跑 `GroupRuleConfig.extract` ——
  改名成 `我的站`（不带标签）之后，原来的 `[荐]` 标签也不再出现（改名是整套替换，不是叠加）；
- `matchesSearch(rawName, customName, key, keyword)`：关键词去空白 + 小写；空关键词**一律命中**（不过滤）；
  否则生效名 / 原始名 / key 任一包含即命中。

## 三、存储与桶键

- `SiteNameBook`：`{接口摘要: {站点 key: 自定义名}}`，JSON 落 `UserDefaults`（键 `yplayer.siteNames`），
  与上游 `site_names` 同款形状；坏数据当空、空桶与空名字丢掉；
- **桶键是接口地址的摘要**（`ConfigIdentity.key(for:)` = `cfg:` + MD5 前 16 位），不是明文地址 ——
  地址常带 token，而这是要落盘的东西。这与 `HLSAdRuleState` 的「源标识摘要」是同一口径；
- 顺带把 M06e 的 `SiteGroupOrderBook` 桶键也从明文地址换成同一个摘要（同一类数据，不该两套做法）。

## 四、界面

- 面板顶部一条搜索框（放大镜 + 有一键清空）——上游把搜索放在同一个面板里，这里保持一致：
  面板本来就是「找站点」的地方，再套一层弹窗只是多一次跳转；
- 站点行长按 → 「重命名」；已经有自定义名时多一项「恢复原名」；分组胶囊的长按菜单仍是「上移 / 下移」（M06e）；
- 重命名弹窗里输入框**预填当前生效名**（上游 `getEditableName` 同款），按钮是「保存 / 取消」，
  说明文字写明「填成原名（或清空）即为恢复；分组标签按新名字重抽」——
  这条交互不写出来，用户不会知道改名还能影响分组条；
- 工具栏的站点名改用 `siteDisplayName`，避免「面板显示新名、工具栏还是旧名」；
- 抽标签要跑正则，所以面板把标签缓存起来，但 `.task(id: names)` 盯着自定义名 —— **改完名立刻重抽**。
