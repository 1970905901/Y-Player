## 一、产出

| 件 | 说明 |
| --- | --- |
| `AppModel`（新增属性） | `isLocalProxyEnabled`（落 `UserDefaults`，**默认开**）、`localProxyPort`（同步可读的端口副本）、`localProxyNotice`（端口 / 失败原因如实展示）、`localServer` |
| `AppModel+LocalProxy.swift` | `ensureLocalServer()`（幂等启动，失败原因走 `userFacingMessage`）、`stopLocalServer()`、`proxiedMediaResource(_:)`（同步判定） |
| `RootView` | 冷启动 `.task` 里启动本机服务：同步判定不能 `await`，所以端口必须先就绪 |
| `PlaybackSettingsSection` | 设置 → 播放：新增「本地代理注入 header」开关 + 本机服务状态行（与内核设置同一处，两个入口共用） |
| `VodDetailView+Data` / `SpiderEpisodePlaybackView` / `ParsePlaybackView` | 三处 `MediaResource` 构造点统一经过 `proxiedMediaResource(_:)` |
| `CatVodUI/Package.swift` | 显式声明 `CatVodNet` 依赖（此前靠 `CatVodPlayer → CatVodNet` 传递） |

**判定规则**（`proxiedMediaResource`）：开关开 且 header 非空 且 端口就绪 → 改走 `/proxy`，
并把资源上的 header **清空**；任一条件不满足则原样返回（行为退回 M2 的 `AVURLAssetHTTPHeaderFieldsKey`）。

## 二、逐条对齐与取舍

1. 上游 `Server.getAddress()` / `Proxy.getPort()` 就是「本机地址 + 端口」再拼播放地址，本项目同构：
   `LocalProxyURLBuilder(port:).proxyURL(for:headers:)`。
2. 上游 `/proxy` 的语义入口是 JS 代理器（`BaseLoader.proxy(params)`）；本项目这一层是**播放侧 header 注入**，
   端点契约与差异已在 M06a 文档写明（`url` + `h` 两个参数）。
3. **为什么在资源构造点改，而不是在播放页里改**：`MediaResource` 是播放的唯一输入，三处构造点覆盖了
   「直链 / Spider / 解析链」全部通路；播放页只负责展示，地址改写留在构造点，
   播放页也因此能如实显示「当前其实走的是本机代理」。
4. **为什么走代理时要清空 header**：header 由本机服务统一注入，播放器再带一份只会重复，
   并可能在子请求上把注入值覆盖回去（这正是要解决的问题本身）。
5. **为什么开关默认开**：不注入 header 的 HLS 源经常在分片请求上直接 403；而开启只在「有 header」时改变行为，
   风险低。关掉即完全回到 M2 行为，便于对照排查。

## 四、验收

- CI：Lint + SwiftPM tests + iOS/macOS 未签名构建（编译期覆盖三处接线与设置页改动）。
- 人工（Mac / 真机）：
  1. 设置 → 播放：开关存在，下面显示「本机服务运行中：127.0.0.1:9978」；
  2. 播一个**必须带 `Referer`** 的 HLS 源：能出画面；
  3. 关掉开关后再播同一个源：应当立刻失败 —— 这正好证明 header 是本机服务注入的，而不是播放器自带。
