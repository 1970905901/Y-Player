## 一、上游口径 → 本项目

| 上游 | 这里 |
| --- | --- |
| 半屏 bottom sheet（`getMaxHeight() = 屏高 / 2`） | `.adaptiveHalfSheet()`（与选集抽屉同一形态；iOS 15 回落整页） |
| 四个分页（外观 / 时间 / 密度 / 显示）、几十个旋钮 | **一页**：我们那份配置只有五项（显示 / 字号 / 透明度 / 速度 / 区域）—— 上游的阴影 / 描边 / 颜色 / 字体 / 时间偏移 / 同屏上限 / 行距……在渲染层没有对应实现，不摆假旋钮 |
| 改一项当场 `setDanmakuConfig` | 面板改的是**同一份配置**（宿主给的绑定 → `AppModel.danmakuDisplay`）：播放页当场重排计划，屏上立刻变 |
| 每页「恢复默认」（长按全恢复） | 一颗「恢复默认」：把**显示参数**（字号 / 透明度 / 速度 / 区域）拉回出厂值 —— 总开关不动（上游分页恢复也不碰它，它归控制条那颗按钮管） |
| 弹幕按钮只在 `haveDanmaku()` 时露出来 | 「弹幕设置…」只在**这一集真有弹幕**且上层给了回写口时才出现（与 M03P18 的开关同一道门） |

## 二、口径与取舍

- **控件共用，不各写一份**：字号 / 透明度 / 速度 / 区域那四条（含范围、步进、档位标题、写回时再夹一次）
  抽成 ``DanmakuDisplayBindings`` + ``DanmakuDisplayControls``，设置页「弹幕显示」与播放页面板
  **用的是同一组**（与 `PlaybackSettingsSection` 当年抽出来同一个理由）—— 设置页那份现在只剩
  「说明 + 这组控件」；
- **一个回写口**：`PlaybackView` 的参数从 `onToggleDanmaku: ((Bool) -> Void)?` 放宽成
  `onDanmakuDisplayChanged: ((DanmakuDisplayConfig) -> Void)?`（一份配置一个出口，别开两个），
  宿主侧对应 `AppModel.setDanmakuVisible(_:)` → `setDanmakuDisplay(_:)`。**改名是有意的**：
  三个宿主调用点都会被编译器点名，不会留下「参数改了、没人传」那种断线（M03P18 的教训）；
- 面板**不认 `AppModel`**：播放页把宿主给的绑定（读 `danmakuDisplay`、写回 `onDanmakuDisplayChanged`）
  递进去，与这页其它回写口同一套做法；
- 半屏面板不写解释文字（`showsExplanations: false`）：地方不够，带说明的那份在设置页。

## 三、故意没做

- 上游那几十个旋钮（阴影 / 描边 / 投影 / 字体 / 时间偏移 / 同屏上限 / 滚动间距 / 行数上限……）：
  渲染层（`DanmakuPlan` / `DanmakuOverlay`）没有对应实现，摆上去就是假旋钮；
- 弹幕**选择 / 搜索**（上游 `DanmakuDialog`：列候选项 + 按名字搜）：那是另一件事（取哪一份弹幕），
  要动取用链，留给后面的批次；
- 分页结构 / 长按全恢复（上游的 tab 形态）：五项不配四页，一颗「恢复默认」就是全恢复。

3. **上机**：有弹幕的那一集 →「弹幕设置…」开半屏面板：
   - 拖字号 / 透明度：屏上的弹幕**当场**跟着变；速度 / 区域同理；
   - 「恢复默认」：四项回默认，**弹幕仍然开着**（总开关没被重置）；
   - 「完成」关掉面板；回「设置 → 播放 → 弹幕显示」：数值与刚才调的一样（同一份配置）；
   - 没有弹幕的那一集：这一块（含按钮）不出现。

## 五、教训

- 「两个面同一份配置」最省事的做法不是「两边各改一遍」，而是**把控件本身抽出来** ——
  这次顺手把设置页那四条控件的规则（范围 / 夹紧 / 标题）也收进共用件，以后再加第三个入口不用再抄；
- 改参数名（`onToggleDanmaku` → `onDanmakuDisplayChanged`）比新增参数安全：
  编译器会把调用点一个个点出来，M03P22 那种「漏传一处」的事不会发生。
