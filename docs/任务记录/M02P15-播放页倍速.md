# M02P15 播放页倍速（对齐上游 SpeedSetting）

- 状态：已提交、待 CI 验证
- 时间：2026-10-08
- 触发问题：`PlayerEngine.setRate` 从 M2 起就有实现（系统内核写 `player.rate`、MpvEngine 下 `set speed`），
  但**界面上零调用点** —— 用户根本设不了倍速。查这个窟窿时又发现一个真 bug：
  `AVPlayerEngine.play()` 会把它写回 1.0（「设 1.5x → 暂停 → 继续」就退回正常速度）。
- 依赖：M02P3（播放设置手动选择）、上游 FongMi/TV
  `app/src/main/java/com/fongmi/android/tv/setting/SpeedSetting.java`、
  `ui/dialog/SpeedSettingDialog.java`、`ui/dialog/SpeedSettingPanel.java`

## 一、上游契约（逐条对齐，值都来自源码而非推测）

| 上游 | 这里 |
| --- | --- |
| `MIN = 0.1f` / `MAX = 5.0f` / `STEP = 0.1f` | `SpeedSetting.minimum` / `.maximum` / `.step` |
| `NORMAL = 1.0f` | `SpeedSetting.normal` |
| `PRESETS = {0.5, 0.8, 1.0, 1.2, 1.5, 2.0, 3.0, 5.0}` | `SpeedSetting.presets` |
| `clamp(speed) = Math.clamp(speed, MIN, MAX)` | `SpeedSetting.clamp(_:)` |
| `format = formatValue + "x"`；`value*10` 是整数就一位小数，否则两位（`EPSILON = 0.001`） | `SpeedSetting.format(_:)` / `formatValue(_:)` |
| 面板：滑杆 + 预设 + 「重置」+ 长按倍速滑杆 + 跳过静音开关 | 播放页「播放速度」区：滑杆 + 预设 + 「恢复 1.0x」 |
| `putPlayback` / `getPlayback`（键 `speed_playback`，读取时夹紧） | `PlaybackSpeedBook`（键 `yplayer.playbackSpeed`，读取时夹紧） |
| `getLongPress` / `speed_long_press`、`speed_skip_silence` | **不做**（见第三节） |

## 二、本项目做法

| 件 | 说明 |
| --- | --- |
| `CatVodPlayer/SpeedSetting.swift` | 纯逻辑（范围 / 步进 / 预设 / 夹紧 / 显示格式 / 同档比较）。**不碰 UserDefaults** —— 与 Core 层保持纯净，落盘在 UI 层 |
| `CatVodUI/PlaybackSpeedBook.swift` | 存档：`UserDefaults` 键 `yplayer.playbackSpeed`；写前夹紧、读后校验（坏值回正常速度） |
| `PlaybackView`「播放速度」区 | 当前值 + 滑杆（拖动即时生效、松手才落盘）+ 8 个预设 + 「恢复 1.0x」。只在引擎建起来之后显示 |
| `AVPlayerEngine.requestedRate` | **bug 修复**：引擎记住用户请求的倍速，`play()` 按它恢复（`AVPlayer.play()` 等价于把 rate 置 1） |

两条刻意的语义：

1. **倍速不跨资源记忆**：`AVPlayerEngine.load()` 把倍速重置为正常速度，由上层（播放页）在加载后套用存档 ——
   否则换台/换集会继承上一部的倍速，用户只会在「怎么这么慢」里发现；
2. **拖动中即时生效、松手才落盘**：一次拖动会产生几十个中间值，没必要写几十次 `UserDefaults`。

## 三、明确未做（各带原因，不是遗漏）

1. **长按屏幕临时加速**（上游 `PlaybackAction.startSpeedPress` + `SpeedSetting.getLongPress`）：
   要接管手势，而画面用的是系统原生 `VideoPlayer`（它自带手势），硬叠会互相打架 —— 属 M3/M4 接管渲染后才谈；
2. **跳过静音**（`speed_skip_silence`）：要内核支持（ExoPlayer 的能力），AVPlayer 上没有对应开关；
3. **上游的 12 个预设按钮位**：上游布局有 12 个槽、实际只填 8 个（其余 `GONE`），我们按 8 个做；
4. **与上游的一处差异（有意）**：上游存档里读到 `0` 会夹成 `0.1`（几乎是卡住），我们把**非正数当坏存档回正常速度**；
5. **直播页也会落盘**：上游直播页调 `SpeedSettingDialog` 时不传 `save=true`（直播不存），我们只有一个全局键，
   点播与直播共用一份 —— 差异记在这里，等真机上确认哪种更顺手再定。

## 四、验收

- 单测：`SpeedSettingTests`（常量与预设、夹紧含 NaN/±∞、显示格式含一位/两位小数、同档比较）、
  `SystemPlayerRateTests`（加载后回正常速度、暂停再播不丢倍速、`setRate` 下发 `speedChanged`）、
  `PlaybackSpeedBookTests`（空存档、写读夹紧、坏存档回默认、重置）。
- 为什么单测里不断言 `AVPlayer.rate`：CI 上拿不到 ready 的 `AVPlayerItem`，AVFoundation 会在没就绪时把 rate 自己推回 0，
  断言它只会偶发红 —— 钉住引擎自己那份状态（`requestedRate`）更稳。
- 人工（模拟器/真机）：放一段视频，拖到 2.0x 听声音、暂停再继续确认仍是 2.0x、退出重进确认存档生效。
