# M04P14 软解兜底（sws → BGRA）

- 状态：**已实现**（本地静态闸门全绿 + 新单测；Mac 编译 / 测试 / 上机待 YG）
- 时间：2026-10-10
- 触发：M04P13 接线上机「有声音没画面」。M04P13 加的取证日志一句话定位：

  ```
  视频解码器就绪：流=0 解码器=h264 输出格式=0 VT=false
  丢帧：硬解没生效，收到非 VT 帧（format=0）
  解码 3 秒后仍没有一帧进显示层：视频包=116 解出=0 丢非VT=114 音频样本=216
  ```

  → **模拟器上没有可用的 VideoToolbox 硬解**，libav 自己掉回软解；而当时的链路「只吃 VT 帧」，
  软解帧全被丢掉 —— 黑屏不是显示层的问题，是帧根本没走到显示层。

## 一、做法

1. **解码器两条路**（`LibavVideoDecoder.open(input:decoderMode:)`），**严格按设置、不自动降级**：
   - `.hardware`：先查 `VTIsHardwareDecodeSupported`（只对能确证的编码：H.264 / HEVC）——
     本机没有硬解就**当场报错**，让用户把设置改成软解；VT 设备建不出来同样报错；
     解码中途 libav 掉回软解也**不算数**（记旗标，由会话停下并提示）；
   - `.software`：不建设备，纯软解。
2. **软解帧 → BGRA 的 `CVPixelBuffer`**（`makeSoftwarePixelBuffer`）：`sws_getContext` +
   `sws_scale_frame`（FFmpeg 5 起有一对 `AVFrame` 的接口，省掉在 Swift 里摆 C 数组指针）
   + 自建 IOSurface 背书的 `CVPixelBuffer`，逐行拷进去；转换器按「源格式 + 尺寸」缓存。
   认不出的像素格式**如实丢帧并记账**（`droppedFrameCount`），不硬撑。
3. **帧自己知道走的哪条路**：`Frame.isHardware`；会话在第一帧时记下来（`lock` 保护），
   `stats()` 的「解码」行据此写 `videotoolbox` / `no` —— 这行是**实测回执**：
   设置与实情对不上时它第一个露馅。
4. **会话不再拒绝 `.software`**：删掉「第一版只有硬解，先把设置换成硬件解码」那条守卫。
5. 排障计数分开：`hardwareFrameCount` / `softwareFrameCount` / `droppedFrameCount`
   （日志里「丢非VT」相应改成「硬解帧 / 软解帧 / 丢帧」）；日志仍走 M04P13 的 `LibavTrace`。

## 二、口径与已知取舍

- 软解是 **8bit BGRA**：10bit / HDR 会被压下去，色彩矩阵用 sws 的默认（按尺寸猜）。
  软解定位就是**兼容路线**（HDR / 画质靠硬解那条）—— 这笔账划算，也如实标在设置页。
- **硬解 / 软解由人手动选**（2026-10-10 用户拍板，同 M02P3 对内核选择的纪律）：
  选硬解而硬解不可用 = **明确报错 + 引导改设置**，不自动降级。
  模拟器上根本没有 VT 硬解，所以模拟器上要手动选「软件解码」。
- 软解帧与硬解帧在显示层那条路完全同构（都是 `CVPixelBuffer` → `CMSampleBuffer`）——
  以后「有声音没画面」再出现，就只可能是显示层或时间轴，跟解码无关了。

## 三、故意没做

- ~~音轨切换~~（M04P16）；字幕（libass）上屏；~~逐帧步进 / 音频增益~~（M04P23）；
- 软解的色彩管理（给 sws 显式传 BT.709 / BT.2020 与颜色范围）：等 M04P2 现场验收按片源再定；
- 10bit 软解（P010 → x420 直通）：先把「有画面」解决，HDR 走硬解那条。

## 四、验证点（Mac）

1. `swift test --package-path Packages/CatVodPlayer`：
   - 「Libav 视频解码」+1：软解模式解 5 帧 → 全不是硬解帧、像素格式 = BGRA、尺寸 / 时间戳对得上；
     硬解那条补一句「全都是硬解帧」（免得软解帧把旧断言糊过去）；
   - 「FFmpeg 真会话」里「软解：明确拒绝」改成「软解：也能播」——喂满 30 帧、播放信息写「软件解码」；
     端到端那条补一句：硬解模式下播放信息必须是「硬件解码（VideoToolbox）」；
2. 全包测试 + App 编译照旧；
3. **上机（模拟器）**：内核选「自研 FFmpeg」+ 解码方式手动选**「软件解码」** → 播一集 → 应该出画面
   （播放信息的「解码」行写「软件解码」）。用「硬件解码」时应**明确报错**并引导改设置（模拟器没有 VT 硬解）。
   真机上硬解那条路不变；HDR / 色彩两行留到 M04P2。

## 五、教训（写给下一次）

- 一个「只吃某一种帧」的守卫如果不带取证，就等于把整条链路静默掐断：这次是 `guard format == VT else { return }`。
  现在它变成「能用就用、不能转就记账」。
