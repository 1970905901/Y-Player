# M09f 字幕上屏（覆盖层 + 时间轴 + 与弹幕共用时钟）

- 状态：覆盖层落地，12 条单测（时间轴 7 条 + 覆盖层 5 条）；**屏上效果待真机确认**
- 时间：2026-10-09
- 依赖：M09a（SRT / WebVTT 解析）、M09b（取用链）、M09c（接线，cue 在 `AppModel.subtitleCues` 里）、
  M08h（弹幕上屏 —— 同一套骨架）

## 一、这一步补的是字幕链的最后一环

字幕链此前与弹幕链长得一模一样：解析（M09a）、取用（M09b）、接线（M09c）都齐，
**只差画到视频上**（`AppModel+Subtitle.swift` 里那句「渲染还没有」）。本轮按 M08h 的形状接上。

## 二、三件事，与弹幕一一对应

| 字幕 | 弹幕（M08h） | 说明 |
| --- | --- | --- |
| `SubtitleTimeline`（**Core**） | `DanmakuPlan`（Core） | 内容查询放 Core，纯逻辑可测 |
| `SubtitleOverlayGeometry.text(timeline:at:)` | `DanmakuOverlayGeometry.commands(…)` | 「这一刻画什么」是纯函数 |
| `SubtitleOverlay` | `DanmakuOverlay` | 画只有一层，只能靠眼睛验 |

**没有合并成一个通用覆盖层**：两者取舍差得远 —— 弹幕要排轨道、算速度、几十条同屏、坐标自己算；
字幕只有一条、居中贴底，交给 `Text` 排版（换行与多行行距都是它的事）。

## 三、`SubtitleTimeline` 为什么放在 Core

一集字幕常有 800–2000 条，而这是播放页**最热**的路径（每秒 60 次查询）：每帧线性扫一遍
就是每秒十几万次比较。所以按 `start` 排好序 + 二分定位 + 在「最长一条的时长」窗口内回扫 ——
与 `DanmakuPlan` 完全对称。

一个容易漏的点：**回扫窗口必须按最长那条算**。写死一个常数就会漏掉长字幕，
`longCueIsFound` 那条单测就是钉它的。

## 四、两处刻意的决定

1. **重叠时拼成多行，不叠着画**：真实字幕文件里的「重叠」几乎都是刻意的一对（原文 + 译文），
   叠在同一行上会互相盖住。空白 cue 当没有处理（SRT 里空行就是「这条没内容」，
   画一个空背景框没有意义）；
2. **默认给一层半透明黑底**（而不是只描边）：字幕常压在人脸或亮色画面上，
   纯描边的白字在亮底上照样糊。

## 五、时钟改名与共用

`DanmakuClock` → **`PlaybackClock`**，并单独成文件：字幕与弹幕**共用同一个时钟** ——
两者都必须按同一刻的时间取内容，各自推一份只会互相错开。名字也顺势改成中性的：
被第二处依赖之后，就该按它**真正管的事**命名，而不是按第一个用它的功能命名。

`PlaybackView` 里那个 `danmakuRate()` 同理改名 `clockRate()`：暂停 / 缓冲 / 结束都停表，
弹幕与字幕一起停。

## 六、顺带修掉的过时说法

「渲染还没做」这句话散在 6 处（`AppModel.swift` 的 `subtitleCues` 注释、`SubtitleService` 的文件注释、
M08c / M08d / M08g 的状态行与遗留项、兼容矩阵那一行），本轮一并改成实际状态。

## 七、真机要看什么

1. 站点给了字幕的那一集：字幕是否出现在**画面底部居中**、白字带一层半透明黑底；
2. 是否**逐帧跟得上**（一秒闪一下 = 时钟没接上）、暂停时字幕是否停住；
3. 2 倍速下字幕是否与画面同步；
4. 多行 / 双语（重叠）字幕是否分成两行显示、不互相盖住；
5. 字幕与弹幕同屏时：字幕在**上层**（不被弹幕盖住）、底边距没被弹幕占掉。

## 八、没做（留口）

- 字幕设置页（字号 / 位置 / 背景 / 开关）—— 与 M08i 的弹幕显示设置同一套做法，
  参数已集中在 `SubtitleDisplayStyle`，改一处即可；
- ASS 样式不做（上游靠 ExoPlayer 的原生 ASS 库）：我们只认 SRT / WebVTT 的纯文本风格；
- 手动选字幕轨（站点给了多条时，现在 `SubtitleService.pick` 直接挑第一条可用）。
