# M03P19 画面比例按片记忆（对齐上游 `History.scale`）

- 状态：**已实现**（本地静态闸门全绿 + 新单测；Mac 编译 / 测试 / 上机待 YG）
- 时间：2026-10-10
- 触发：M03P9 的留口第 2 条 ——「**不落盘**：上游把 scale 按片存在 `History` 里，我们没有
  「按页面分的播放设置」这套容器，而一个全局落盘的值会把下一部片也按上一部选的比例放」。
  现在有容器了：进度记录本来就是「按片」的（M03P16 的片头 / 片尾也记在那儿）。
- 依据：`History.scale` / `VideoActivity.getScale()`（`mHistory.getScale() != -1 ? mHistory.getScale()
  : PlayerSetting.getScale()`）、上游播放页的 `onScale()`。

## 一、上游口径 → 本项目

| 上游 | 这里 |
| --- | --- |
| 存在 `History.scale`（按片） | `PlaybackProgress.scale`（存档位的 `rawValue`；GRDB 迁移 `v5.playbackScale` 加一列） |
| 读：有按片的值用它，否则回落到全局默认 | `PlaybackScaleMode.decode(_:)`：空串 / 认不出 → `fit`（坏存档不让画面变形） |
| 写：用户切档位时 | 播放页 `scaleBinding` 切完紧跟一次 `persist(force: true)`（与片头 / 片尾标记同一套） |
| 起播 / 换集套用 | `start()` 与 `loadActiveResource()` 在 `load` **之后**下发一次 `setScaleMode`（引擎换资源会复位，与倍速同一条理由） |
| 进 / 退全屏、切档位时清双指缩放 | 已有：`scaleBinding` 里 `zoomScale = 1`（M03P14） |

一处与上游的差别（有意）：上游还有一个**全局默认档**（`PlayerSetting.getScale()`），
我们没做那个设置项 —— 没存过的片就是「适应」，不引一个只有一处用的全局值。

## 二、为什么这次能落盘（M03P9 的顾虑怎么消的）

M03P9 拒的是「**一个全局值**」——那会让下一部片继承上一部的比例。按片存就没有这个问题：
记录本来就用 `(站点, vodID)` 做键，换一部片读到的是它自己的那份（没存过 = 空串 → 适应）。
与片头 / 片尾同一条记录、同一次 `persist` 落盘，不多一条时间线。

## 三、故意没做

- **全局默认档**（上游 `PlayerSetting.getScale()`）：见上；
- **直播页的独立档位**（上游 `LiveSetting.getScale()`）：直播现在与点播共用「按片」这套，
  而直播没有进度记录 → 也就是**每次都是适应**；要单独记就得再引一套直播偏好，等有人提；
- **「记住这一档」的开关**：直接记，不给一个「记不记」的二层开关（少一个开关少一个坑）。

## 四、验证点（Mac）

1. 放一部片 → 把「画面比例」切到 **4:3**（或裁剪铺满）→ 退出播放页、再进来 → 仍然是那一档；
2. 换另一部片 → 是「适应」（不会继承上一部的档位）；
3. 把老片的档位切成 4:3 后再进老片 → 还是 4:3（同一部片的记忆没丢）；
4. 手动往库里塞一个认不出的值（或用旧版本库升级上来）→ 显示「适应」，不崩、不变形。
