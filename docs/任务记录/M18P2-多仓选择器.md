# M18P2 多仓（`urls`）选择器：从「说清不支持」到「挑着能用」

- 状态：**已实现**（本地静态闸门全绿 + 新单测；攒着下次上机验）
- 时间：2026-10-10
- 承接 M18P1：那一片只做到「如实说清不支持」。这一片把它变成**能用** ——
  在「源地址」页把多仓里的子配置列出来，点一条就用它替换当前接口。

## 一、做法

1. `ConfigSubURLEntry` + `ConfigSubURLs.entries(_:relativeTo:)`（纯逻辑 + 单测）：
   把配置里的 `urls` 变成一条条可点的条目；**相对地址按当前配置地址解析**
   （配置里写 `./sub.json` 很常见），解析不出来就 `url == nil`；
2. `AppModel.configSubURLEntries`（按 `state.loadedSource` 现算）+ `AppModel.loadSubConfig(_:)`：
   **与用户手填地址是同一条路** —— 写回 `configURL` 再 `load(forceRefresh: true)`；
   不另立「多仓状态」，想回仓库那份就把仓库地址再填一次（页脚里写着这句）；
3. 「源地址」页新增 **多配置入口** 区：一条一行，点了就加载；
   **点不动的条目置灰 + 写明原因**（相对路径但这份配置没有基准地址）——不点没反应是禁止项；
4. 文案同步：`ConfigCoverage.urlsReason` 从「请直接把子配置地址填进源地址」改成
   「请到『源地址 → 多配置入口』点一条」；发现页空态也改成指路那一区。

## 二、故意没做

- **不做「仓库」概念**（记住仓库地址、能一键回退）：回退就是把仓库地址再填一次，够用；
  真要做该和「多接口管理」一起设计，不是在这里先糊一个；
- 不自动选第一条：用户没选过的不替他做主（M18P1 的决定不变）；
- 不做子配置的「缓存/切换历史」：它们各自走接口缓存那套，切过去就是普通配置。

## 三、验证点（Mac，和下一批一起跑）

1. 「设置 → 源地址」加载一份多仓配置（内联即可）：

```json
{"urls":["https://a.example/1.json","https://b.example/2.json","./relative.json"]}
```

2. 「**多配置入口**」区应列 3 条：前两条正常可点（地址与原文一致），
   第三条（相对地址、内联配置没有基准）应**置灰并写明原因**；
3. 点第一条 → 地址框换成它、开始加载（`a.example` 不存在会失败，但**加载动作与错误提示**要正常）；
4. 真正可用的多仓配置：点一条 → 站点清单换成那份配置的；
5. 发现页空态应写着「…去『设置 → 源地址 → 多配置入口』点一条加载」。
