## 三、判定与决策（为什么这么做）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 什么算「翻到底」 | 上游给了 `pagecount` 就比页码；没给就必须靠「返回空列表」 | 录屏里的源大多不给 `pagecount`，若只比页码就会无限请求空页（`DiscoverPaging` 单测覆盖三种组合） |
| 触发加载更多的方式 | 底部 `.task(id: loadMoreTrigger)` | 底部行出现在可视区就触发；`id` 用「页码 + 条数」，追加完成后能接着取下一页，上次因正在加载被跳过也能补上 |
| 空列表怎么处理 | 不追加、只置 `reachedEnd = true` | 后续页里带上分类/筛选/`pagecount` 就顺带更新，没有就保持原样（少见但上游确实会带） |
| 分类加载入口 | 事件方法 `selectCategory(_:)`，不用 `Binding` | 沿用 M02P10 的结论：程序内回写 `selectedCategoryID` 不能触发加载，否则一次加载变两次请求 |
| 站点切换入口 | 面板只改 `selectedSiteKey`，加载交给 `.onChange` | 沿用 M02P9 的收口，避免一次切换发两次首屏请求 |
| 展示方式 | 「横向」= 3 列海报网格（对齐录屏），「纵向」= 内容行（M2 原观感） | 设置 → 首页 → 展示方式这两个取值都能在录屏之外保留原有能力，共用同一份数据与同一条翻页路径 |
| 版本差异 | 新增 `adaptiveInlineNavigationTitle()`（iOS `.inline` / macOS 原样） | 遵循 `docs/UI 规范.md`：版本分支只允许出现在 `Platform/` 基础件里，业务视图不写 `#if` |

## 四、超出录屏的部分（诚实记录）

1. **右上角保留「刷新」按钮**：录屏里右上角是两个图标（分享类 + 搜索），本项目没有投屏/分享能力，
   不做假图标；而「刷新」是上拉加载后回到第一页并绕过缓存的唯一手段，因此保留。
   若要严格对齐录屏，删掉 `trailingButtons` 里的这一个 `Button` 即可（不影响其它逻辑）。
2. **搜索页未改**：录屏后半段是搜索页（搜索历史 + 胶囊），但用户本次只要求发现页；
   现有 `SearchView` 功能完整（站点选择 / 分页 / 结果），未做版式改动。
3. **没有做骨架屏 / 首屏占位图**：封面加载中露出淡灰占位（角标照常显示），不伪造内容。
