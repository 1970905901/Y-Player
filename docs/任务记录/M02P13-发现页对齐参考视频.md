## 一、录屏 → 实现位置（逐项对照）

| 录屏里的东西 | 实现 | 说明 |
| --- | --- | --- |
| 左上角「切换图标 + 当前站点名」（**没有下拉箭头**） | `HomeView.siteSwitcherButton` + `DiscoverSiteSwitchGlyph` | 图标是两个开关的字形（录屏放大实测；SF Symbols 无对应项，所以自绘）；站点名里的「☁️」是**上游名字自带**的表情，不是按钮图标 —— 见第七节 |
| 点左上角弹出的站点面板：贴左悬浮卡片，当前项右侧打勾 | `DiscoverSitePanel` + `DiscoverSiteList` | 面板宽约占屏宽 2/3、高约 0.78，面板外**不变暗**（透明点击层收起）；切换后由 `.onChange(of: selectedSiteKey)` 统一发一次首屏请求（沿用 M02P9/M02P10 的收口做法） |
| 右上角图标 | `HomeView.trailingButtons` | 搜索（`SearchView`）+ 刷新（回到第一页并绕过缓存）；**这是唯一超出录屏的控件**，理由见第四节 |
| 分类横条（选中项加粗变黑，无胶囊底） | `DiscoverCategoryStrip` | 横向滚动；点击 → `selectCategory(_:)`（重置筛选与翻页后加载一次） |
| 筛选：左侧名 + 右侧一串胶囊 | `DiscoverFilterStrip` / `DiscoverFilterChip` | 上游 `filters[].name` 为空的行**不占左侧标签列**（录屏里「玩偶」源就是这种形态） |
| 筛选点一下立即生效 | `applyFilter(_:value:)` | 录屏里没有「应用筛选」按钮；点当前项不重发请求 |
| 3 列海报网格 | `HomeView.posterGrid`（`LazyVGrid`）+ `DiscoverPosterCard` | 列数由 `HomeView.posterColumnCount = 3` 固定 |
| 封面右上角角标（更新至 58 集 / 全 9 集 / HD / 4K） | `DiscoverPosterCard.badge` | 数据取上游 `vodRemarks`，不做本地拼接 |

| 滚动到底「加载中…」并继续出内容 | `loadMoreFooter` + `loadMore()` + `DiscoverPaging` | 追加式翻页：`page + 1` 拉下一页，空列表 = 到底 |

## 三、判定与决策（为什么这么做）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 什么算「翻到底」 | 上游给了 `pagecount` 就比页码；没给就必须靠「返回空列表」 | 录屏里的源大多不给 `pagecount`，若只比页码就会无限请求空页（`DiscoverPaging` 单测覆盖三种组合） |
| 触发加载更多的方式 | 底部 `.task(id: loadMoreTrigger)` | 底部行出现在可视区就触发；`id` 用「页码 + 条数」，追加完成后能接着取下一页，上次因正在加载被跳过也能补上 |
| 空列表怎么处理 | 不追加、只置 `reachedEnd = true` | 后续页里带上分类/筛选/`pagecount` 就顺带更新，没有就保持原样（少见但上游确实会带） |
| 分类加载入口 | 事件方法 `selectCategory(_:)`，不用 `Binding` | 沿用 M02P10 的结论：程序内回写 `selectedCategoryID` 不能触发加载，否则一次加载变两次请求 |
| 站点切换入口 | 面板只改 `selectedSiteKey`，加载交给 `.onChange` | 沿用 M02P9 的收口，避免一次切换发两次首屏请求 |
| 展示方式 | 「横向」= 3 列海报网格（对齐录屏），「纵向」= 内容行（M2 原观感） | 设置 → 首页 → 展示方式这两个取值都能在录屏之外保留原有能力，共用同一份数据与同一条翻页路径 |
| 版本差异 | 新增 `adaptiveInlineNavigationTitle()`（iOS `.inline` / macOS 原样） | 遵循 `docs/UI 规范.md`：版本分支只允许出现在 `Platform/` 基础件里，业务视图不写 `#if` |

## 四、超出录屏的部分（诚实记录）

1. **右上角保留「刷新」按钮**：录屏里右上角是两个图标（分享类 + 搜索），本项目没有投屏/分享能力，
   不做假图标；而「刷新」是上拉加载后回到第一页并绕过缓存的唯一手段，因此保留。
   若要严格对齐录屏，删掉 `trailingButtons` 里的这一个 `Button` 即可（不影响其它逻辑）。
2. **搜索页未改**：录屏后半段是搜索页（搜索历史 + 胶囊），但用户本次只要求发现页；
   现有 `SearchView` 功能完整（站点选择 / 分页 / 结果），未做版式改动。
3. **没有做骨架屏 / 首屏占位图**：封面加载中露出淡灰占位（角标照常显示），不伪造内容。

## 七、二次核对：左上角确实是「站点切换」（2026-10-08 修正）

用户指出「发现页左上角是站点切换」，于是把录屏按**真实分辨率 888×1920**（此前按 1170×2532 估过，
所以局部裁剪一开始越界）重新裁剪放大（`Tools/out/crop_top.py`，crop + 3~9 倍 lanczos）后再判定：

| 放大后看到的东西 | 结论 | 落到代码 |
| --- | --- | --- |
| 左上角字形：**两个开关**（上一个空、下一个满），蓝色 | 这是「站点切换」入口，不是云图标 | `DiscoverSiteSwitchGlyph`（自绘：SF Symbols 没有这个字形） |
| 字形右边紧跟 `「盘」☁️玩偶` / `「盘」☁️木偶` | 整串都是**站点名**：`☁️` 是名字里的表情、`「盘」` 是上游名字自带的标签 | 按钮只显示 `Site.name`（空名回落 `key`），不再自己拼图标 |
| 该位置**没有** `chevron.down` | 录屏里没有下拉箭头 | 箭头删掉，靠图标本身示意 |
| 点开后：**贴左悬浮卡片**，行高约 44pt、行间细线、当前项右侧 ✓，从工具栏下方伸到接近屏底 | 面板形态 | `DiscoverSitePanel`（`ScrollView` + `LazyVStack` + `Divider`）+ 宽 `0.66` / 高 `0.78` |
| 面板外的内容**没有变暗** | 不用黑色遮罩 | 透明点击层（`Color.clear` + `contentShape`）点外部收起，点面板本体不穿透 |
| 面板顶部还有 `「荐」😊豆瓣`、`「设」⚙️配置` 和一行日期（如 `2026-10-07`） | 参考实现是「多接口 + 特殊条目 + 日期分组」的站列表 | **未做**：本仓库站点来自单一接口（js2p 宿主给出的 85 个站点），没有「多接口 / 日期分组」这层数据，面板只列当前接口的站点 |

两个刻意的克制（避免「看起来更像、实际更错」）：

1. **不拆解站点名里的标记**：`玩偶|4K` 是上游配置自己的命名口径（社区不同宿主的写法并不一致），
   本项目原样显示；擅自把 `|4K` 重排成 `「4K」玩偶` 会在换接口后立刻错位。
2. **不补假条目**：参考实现在面板顶部有 `豆瓣 / 配置` 这类特殊条目，本项目没有对应能力，
   就不摆只看不用的行（与第四节「不做假图标」同一原则）。

新增单测：`DiscoverSiteList.rows`（站点顺序 / 空名回落 `key` / 当前项打勾）与
`DiscoverSiteSwitchGlyph` / `DiscoverSitePanel` 的构造，见 `DiscoverPageTests.swift`。
