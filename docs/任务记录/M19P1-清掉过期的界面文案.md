# M19P1 清掉过期的界面文案（M3/M4 那句）

- 状态：**已实现**（纯文案与注释，静态闸门全绿）
- 时间：2026-10-10
- 触发：M03/M10 早就落地了，但界面上还留着「M3（MPVKit）/ M4（自研 FFmpeg）接入后会补上」
  这类**已过期**的话 —— 用户看到的是「这功能还没做」，而 MPV 其实已经能播、下载已经能用。
  「不撒谎」这条口径不只约束缺失项，也约束夸大的缺失说明。

## 一、改了什么

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| 设置 → 播放 → 播放界面（说明） | 「…M3/M4 接入后会补上」 | 系统内核交给系统；**MPV 有自己的最小控制条与手势、音轨/字幕在播放页选**；M4 接入后再补它的渲染与音视频选项 |
| 设置 → 播放 → 播放控制（当前形态） | 「控制方式：系统播放器」（写死，选 MPV 时也是这句） | **跟着当前内核算**：系统 / MPV / FFmpeg 三套文案各说各的（新增 `controlSummary` / `controlDetail`） |
| 设置 → 播放 → 播放控制（后续） | 「M3/M4 接入后会出现内核专属控制…」 | 只留给 M4：逐帧步进、音频增益、渲染选项 |
| `PlaybackView` 头注释 | 「MPV / 自研 FFmpeg 内核接入后会替换中间的渲染视图」 | MPV 已经接管（`MpvVideoView` + 最小控制条 + 手势），只有 M4 还是将来 |
| `StorageSpace` / `AppModel+Storage` 注释 | 「离线下载尚未接入」 | M10 起已可用；只有真下过东西那个目录才存在 |
