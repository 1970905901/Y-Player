## 一、先修的「洞」

`AppModel.selectedLiveKey` 从 M07c-2 起就有持久化，`selectedLiveSource` 也按它取源 —— 但**界面上
没有任何地方能改它**。配了多个直播源的接口，用户只能一直用配置里的第一个（除非清 App 数据）。
这一轮补上入口。

## 三、差异与取舍

1. **只有一个源时不显示这一栏**（上游 `isOnly()`）：没有可切的东西，显示了只会误导。
2. **摘要只在「已解析」时报频道数**：别的源有多少频道我们并不知道（清单还没拉），不编数字；
   已解析但清单为空时也只报类型（不写「0 个频道」）。
3. **切源走 `loadLivePlaylist(force: true)`**：它本来就会清掉节目单缓存与预取状态（换源后同一个
   `epgID` 可能指向另一个频道），所以这里不重复各清一遍；再补一次 `loadLiveFileGuide(force: true)`
   让文件形态的节目单立刻跟上。
4. **勾选的是「当前生效的源」**：`selectedLiveKey` 为空时生效的是配置里的第一个 —— 界面按
   `selectedLiveSource` 勾，避免出现「一个都没勾」的错觉。
5. **页面改名**：`LiveEPGSettingView` → `LiveSettingsView`。它现在装两件事，旧名字会误导；
   M07d-1 文档里的引用同步更新（纯改名，行为不变）。
6. **未做**：源的**增删**（配置是只读解码来的，改不了）；`boot`（开机自启）与 `pass`（分组名不当密码）
   两个源级字段的本地开关仍待做。

## 四、验收

- 本机自检：`check_swift.py` + `scan_report.py`（0 条真问题）、`check_wrap.py`。
- CI：Lint ✅ / SwiftPM tests ✅（见文末复盘）。
- 人工（需真机 / Mac）：
  1. 接口里只有一个直播源 → 设置页**没有**「直播源」这一栏；
  2. 接口里有多个 → 一栏列出全部，当前源带勾，第二行是类型（已解析的那个带频道数）；
  3. 点另一个源 → 回直播页：分组与频道换成新源的；
  4. 杀进程重开 → 仍是上次选的源。

## 五、回滚

删掉 `LiveSourceList.swift` 与 `AppModel+Live` 里的两个入口，`LiveSettingsView` 去掉「直播源」一栏，
文件名改回 `LiveEPGSettingView.swift` 即可。
