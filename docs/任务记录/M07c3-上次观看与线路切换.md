## 三、差异与取舍

1. **keep 存哪**：上游写在源对象自己的 `keep` 字段、随配置一起落库；本项目不持有可写的配置副本
   （配置是从地址只读解码来的），所以**按源名**存一份到 `UserDefaults`（`yplayer.liveKeep`）。
   源的 `keep` 仍会被读（有些源自己带一个起始值），本地存档优先 —— 一个接口里多个直播源的频道名会撞车，
   按源名分桶是必须的。
2. **不自动开播**：进直播页只把分组条切回上次那一组，列表上方给「继续观看」，**不**直接出声。
   上游手机版也是列表优先；自动播放的实现代价（`NavigationStack` 的 path 绑定）与打扰都不划算。
   这是对 M07c-2 交接里「自动回到上次频道」的一句收窄，界面上的入口仍然是一点就到。
3. **线路切换放在播放页工具栏**：上游在列表长按 / 弹层里选线路，本项目放在播放页右上角菜单 ——
   「换线路」是播放中的动作，放播放页就不必把列表页堆成两级弹层。菜单用 `Menu` + 当前项对勾（原生控件，
   平台各自外观），`>1` 条线路才出现。
4. **换线路靠 `id` 重建播放页**：`PlaybackView` 自己的 `.task` 只在视图出现时跑一次，不重建就会继续播
   旧线路。所以换线路 = 换 `id`；**写 keep 不依赖重建**（外层的 `.task` 不一定重跑），而是在菜单动作里
   直接写。
5. **CI 补漏**：`build.yml` 里 `CatVodUI` 一直是 `swift build`（注释写着「没有单测目标」，早就不准），
   于是 `CatVodUITests`（M02P12/P13/P14、M07c、M08b 陆续加的纯逻辑用例，包括本轮的）**从来没在 CI 里
   编译过**。改成 `swift test --package-path Packages/CatVodUI`：本轮新增的用例这次是真的在跑。
6. **线路名用清单里的原文**：上游用资源字符串（`R.string.line`）拼「线路 N」，属界面职责；
   清单里写了 `地址$线路名` 就用它（很多源靠这个区分「高清 / 流畅」）。

  + iOS/macOS 双端未签名构建。
- 人工（需真机 / Mac）：
  1. 进直播页 → 列表上方出现「继续观看」（上次看的频道 + 线路名）；
  2. 点它 → 直接播上次那条线路；列表里那个频道带「上次」标记；
  3. 播放页右上角切线路 → 立刻换成新地址（旧地址的播放停止），退出再进「继续观看」= 新线路；
  4. 冷启动 App 再进直播页 → 记录仍生效（落 `UserDefaults`）；
  5. 节目单页在多线路频道里时移回看 → 用的是当前线路的地址（页脚有说明）。
