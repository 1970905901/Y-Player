# M04P2 输出色彩（HDR 有没有真的送到屏幕）

- 状态：**已实现**（本地静态闸门全绿 + 新单测；真机由 YG 用 Mac 验证）
- 时间：2026-10-10
- 触发：M04P1 的播放信息只报**片源**（`video-params/*`）。而 M4 真正要回答的问题是
  「**片源是 HDR，输出还是不是 HDR**」—— 中间被压成 SDR 的话，片源那行照样写着 HDR，
  看上去一切正常，实际上屏幕上是 SDR。

## 一、做法：多读一组 `video-out-params/*`

mpv 除了 `video-params/*`（源），还暴露 `video-out-params/*`（**经过色彩转换、送给显示**的那一路）。
新增三个属性（`MpvEngine.statsPropertyNames`）：

```
video-out-params/primaries   → 输出的色域
video-out-params/gamma       → 输出的 transfer（pq / hlg / bt.1886…）
video-out-params/pixelformat → 输出的像素格式（p010 / yuv420p…）
```

界面上就是**两行**：

```
色彩：HDR · PQ (ST2084) · BT.2020      ← 片源
输出：SDR · BT.1886 · BT.709 · yuv420p ← 实际送显
```

判定与名词**与片源那行共用同一套**（`rangeText(primaries:gamma:)` / `isHDR(gamma:)`，
私有静态，`dynamicRangeText` 也改走它）——两处各写一遍迟早会飘。

## 二、三条口径

1. **不猜**：没读到输出参数时 `outputText` 是空串（那一行不显示）、`isOutputHDR` 是 `nil`
   ——「不知道」不等于「不是 HDR」。老版本 mpv 没有 `video-out-params`，那就别显示。
2. **HDR 只认 gamma**（`pq` / `hlg`），两条路都一样 —— 不拿色域判
   （BT.2020 + BT.1886 的 10bit SDR 也存在）。
3. 片源与输出都进诊断报告（「最近播放」段多一行「输出」），真机验证时一段文本就能看出
   「源 HDR / 出 SDR」这种中间被压掉的情况。

## 三、故意没做

- 不做「自动修」（比如按输出是 SDR 就去调 mpv 的色调映射参数）：先能量出来，再说怎么调 ——
  调参是 M4 渲染侧的事，而且得先在真机上看到实际数据；
- 不读 `target-colorspace-hint` 那类 VO 选项：那是「我们要求了什么」，不是「实际输出是什么」，
  容易看成结论。要的是后者。

## 四、验证点（Mac）

1. 用 MPV 播一集普通片：播放页「播放信息」里应同时有「色彩」与「输出」两行（都是 SDR）；
2. 播一个 HDR 片源（4K HDR 剧集）：
   - 两行都写 HDR → 这条链路是通的；
   - 「色彩」HDR、「输出」SDR → **HDR 被压掉了**（这正是 M4 要处理的现场，把诊断信息发我）；
3. 播一段后点「刷新」：两行内容应稳定（不会跳来跳去）；
4. 复制诊断信息 → 「【最近播放】」段里除了「色彩」还应有一行「输出」。
