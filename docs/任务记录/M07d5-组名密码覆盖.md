## 一、为什么现在补：M07d-4 的逃生门

M07d-4 把加密分组改成「默认不显示、输对密码才出现」—— 这正是上游行为，但它有个副作用：
**源里组名本来就有 `_` 的**（例如 `央视_高清`），解析时会被拆成「央视 + 高清」，
于是这一组变成加密分组**被藏起来**，而且**永远解锁不了**（那串「密码」其实只是名字的一部分）。

上游为这类源留了 `pass` 字段（为 true 时不拆）。本项目此前只用源里给的值、没有本地入口，
所以这类源在本机就是无解的 —— 补一个开关，两个方向都能拨。

## 二、落地了什么

| 件 | 说明 |
| --- | --- |
| `CatVodCore/Vod/Live/LiveSource+GroupPass.swift` | `applyingGroupPass(_:)`：`nil` = 不覆盖（跟源自己的 `pass`）、`true`/`false` = 本地覆盖的两个方向 |

| `AppModel.livePassOverrides` | 按源记的覆盖表（写一次落盘一次）；不在表里 = 跟随源字段 |
| `AppModel+Live` | `liveGroupPassEnabled`（有效值：覆盖优先）、`setLiveGroupPass(_:)`（落盘 → 强制重载清单 → 重拉文件形态节目单）；`loadLivePlaylist` 在**解析前**套用覆盖 |
| `LiveSettingsView` | 「分组名」一栏：`Toggle` + 一句说明（默认跟源字段；只对当前源生效；改完会重拉一次清单） |
| 单测 | `LiveSourcePassOverrideTests`（3 例）、`LivePassBookTests`（2 例）、`LivePlaylistParserTests` +1 例（真解析器上验证：默认拆成加密组 / 打开后组名原样且不隐藏） |

## 三、对齐与差异

| 上游 | 本仓库 | 差异 |
| --- | --- | --- |
| `Live.pass(boolean)`：清空 `groups` 后重新解析 | `setLiveGroupPass(_:)` → `loadLivePlaylist(force: true)` | 语义一致（重新解析）；本项目不缓存清单文本，所以要**重新请求一次**清单（一次请求，接受） |
| `pass` 是源自己的字段 | 源字段 + **本机覆盖**（按源名记） | 多加了一层：源里没写也能打开（救 `央视_高清` 这类源），源里写了也能关掉（用户的实际组名里没有密码） |
| `Group(name, pass)`：`pass` 为 true 时不拆 | 不变（`LivePlaylistParser` 早就读了 `source.pass`） | — |

**取舍**：覆盖存的是**显式布尔值**而不是「打开过的源集合」，就是为了两个方向都能拨；
`clearing(_:in:)` 留着给「回到跟随源字段」用（目前界面没给这个入口，等有需求再加 —— 不想为一个
少见操作再加一层三态 UI）。
