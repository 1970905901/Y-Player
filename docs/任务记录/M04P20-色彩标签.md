# M04P20 色彩标签（输出侧说真话）

- 状态：**已实现**（本地静态闸门全绿 + 新单测；Mac 编译 / 测试 / 上机待 YG）
- 时间：2026-10-10
- 触发：M04P2 验收的**最后一块仪器**。播放信息早就能报**源**是 SDR 还是 HDR
  （`video-params/primaries` / `gamma`），但「经过转换之后送给显示的那一路」一直是空的 ——
  「HDR 有没有真的送到屏幕」这个问题没有证据。

## 一、做法

1. **软解那条路，自己挂**：`LibavVideoDecoder` 打开时读源的色彩三件套
   （色域 / 传输特性 / YCbCr 矩阵），每次建 420v buffer 时按**源**挂 CoreVideo 标签
   （`kCVImageBufferColorPrimariesKey` / `TransferFunctionKey` / `YCbCrMatrixKey`）。
   以前一个都不挂，CoreVideo 只能按默认猜矩阵 —— 1080p 这类片子常常猜错。
2. **硬解那条路，VT 自己挂**：VideoToolbox 直出的 buffer 自带标签，我们不碰。
3. **读回的是「实际挂上的」**：会话每帧把送显示那张 buffer 的标签读回来
   （`CVBufferCopyAttachment`），与像素格式进同一个锁快照 —— 不是「我们打算挂的」。
4. **翻成播放信息那套名词**（`bt.709` / `bt.2020` / `pq` / `hlg`…，与源那两行同一套）：
   `stats()` 写 `video-out-params/primaries` 与 `video-out-params/gamma` ——
   播放页「输出」行与 `isOutputHDR` 自动生效（界面那侧一行没改）。

## 二、口径与取舍

- **认不出不挂、不显示**：AVCOL ↔ CoreVideo 两张映射表都只翻能确证的枚举值
  （BT.709 / BT.2020 / P3-D65 / SMPTE-C；PQ / HLG / 709 / Linear）；认不出给 nil，
  宁可空着也不写假的 —— 这一行是当「HDR 送出去没有」的证据用的。
- **不做色彩转换**：只是把源头的标签传给显示层；tone mapping / 色域变换是另一件事
  （要不要做，M04P2 验收之后另定）。
- **矩阵只挂、不读回**：播放信息没有矩阵的出口，读了就是没人看的死代码。

## 三、故意没做

- HDR → SDR 的 tone mapping、色域转换（软解那条仍是「值原样 + 标签照挂」）；
- 其余 `video-out-params` 项（矩阵 / 色深等）—— 界面没这些行；
- 软解 10bit（P010 → x420）照旧不做（另一件事，见 M04P18）。

## 四、验证点（Mac）

1. `swift test --package-path Packages/CatVodPlayer`：新两条 ——
   「挂上 → 读回」（BT2020 + PQ 回环、认不出的值什么都不挂）与「标签 → 名词」映射表；
2. 全包测试 + App 编译照旧（这次没加 / 删文件，不用清 `.build`；照规矩清也无害）；
3. **上机**（模拟器，软件解码）：播任意 SDR 片 → 播放信息「输出」行应带上 `SDR · …`
   （以前只有像素格式）；真机 + HDR 片 + 硬解时应写 `HDR · PQ (ST2084)` / `HLG` ——
   这就是 M04P2 要的验收证据。

## 五、教训（写给下一次）

- 读附件用 `CVBufferCopyAttachment`（复制一份，ARC 管），别用要自己处理 `Unmanaged` 的旧版
  `CVBufferGetAttachment`；
- 「实测值进快照」沿用 M04P13 的规矩：解码线程写、`stats()` 读，都过 `lock`；
- 测试 target 只依赖 CatVodPlayer（**不依赖 Libavutil**）：要传 AVCOL 枚举值时把字面量
  连同枚举名写在注释里（FFmpeg 枚举是稳定 ABI），别为一行测试去改 `Package.swift`；
- **CoreVideo 的常量名别凭记忆**：PQ 那条的正名是 `kCVImageBufferTransferFunction_SMPTE_ST_2084_PQ`
  （少一个 `_PQ` 就是 `cannot find ... in scope` —— 首轮 Mac 编译抓到的）；用新常量前去 SDK 头里对一遍。
