## 一、这一笔在补什么

`DanmakuAPIConfig` 从 M2 起就存在（设置 → 播放 → 弹幕 API：一个开关 + 四个地址槽），它的注释当时写着
「弹幕的请求链与渲染属于 M8，尚未接入」—— 而 M08a/M08b 把请求链做出来之后，**仍然没有人调用它**：
`DanmakuService` 除自己的文件和测试外没有一个调用点。

也就是说：用户填了地址、开了开关，什么都不会发生。这正是本项目反复出现的那类半成品
（「能力齐了、没人用」）。这一笔是把它接起来 —— 但**只接到「拿到弹幕行」**，不假装能上屏。

## 二、接法与取舍

- `AppModel+Danmaku.swift`：`loadDanmaku(_:)` / `clearDanmaku()`，状态是
  `danmakuLines`（原始行，给将来的渲染层）+ `danmakuStatus`（播放页那一行）；
- **不抛错**：弹幕是锦上添花的功能。网络失败只该让播放页显示「加载失败 — 原因」，
  不该把播放流程带崩，也不该弹系统级错误；
- **开关关着 / 四个槽都空 → 什么都不做，也不提示**：那是用户的设置，不是错误。
  「没填地址」只在设置页里说，不在播放页唠叨；
- **用 `search` + `lines(from:)`，不用 `load`**：这样能知道是哪条候选源给的弹幕，写进状态行
  （用户对着「弹幕：甲源 · 312 条」才知道该不该换地址）；`load` 仍留着做「只想要行」的便捷入口；
- **传输复用 `transportForConfiguration()`**：接口 header、代理（M06j）、广告拦截与站点完全一致 ——
  弹幕接口也常常需要同样的 header 或代理；
- `DanmakuRequest`（片名 + 集名）与 `DanmakuStatus`（五态 → 一行文案）抽成小类型：
  前者是因为上层拿到的是「片名 · 第1集」这种拼好的标题，让服务去猜怎么切不实在；
  后者是因为「加载中」与「没搜到」混起来用户只会以为卡住了，而「没搜到」必须指路
  （设置页那四个槽是唯一能改的地方）；
- `PlaybackView` 只多两个可选参数 `danmaku:` / `onDanmaku:`：**播放页不认识接口配置，也不该认识** ——
  它把「这次该搜什么」交给上层。两个点播入口（解析播放 / JS 站点分集）各自传片名与集名；
  直播与临时播放不传（`nil` = 这一入口不放弹幕）。
