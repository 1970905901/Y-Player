# M18P1 `urls`（多配置入口）：不接，但要说清

- 状态：**已实现**（本地静态闸门全绿 + 新单测；和 M04P2/M04P3 一起攒着下次上机验）
- 时间：2026-10-10
- 触发：`urls`（多仓 / 多配置入口）一直是**静默忽略**的 —— 它连 `ConfigCoverage` 的告警列表都不在。
  而多仓配置的 `sites` 通常是空的：用户把地址填进去、点加载，看到的是
  「还没有可用站点：请先在「设置 → 源地址」里加载配置。」—— 明明刚加载过，只会以为 App 坏了。

## 一、这一轮做到哪

**不实现多仓**（要在「源地址」页列出子配置让用户挑，是另一件事），只做到**说清**：

1. `ConfigCoverage` 增一条 `urls`：有值就进 `validationWarnings`
   （文案：本平台不支持多配置入口，请直接把其中一条子配置地址填进「源地址」），
   「设置 → 源地址 → 告警」里看得见；
2. `AppModel.configSubURLs`：把配置里的 `urls` 取出来（去空项），**只读、不自动加载**；
3. 发现页空态：站点为空**且**这份配置带 `urls` 时，明说
   「这份配置是多配置入口（`urls`，共 N 条），本平台不列出来挑 —— 请把其中一条子配置地址填进「设置 → 源地址」再加载」，
   而不是那句会误导人的「请先加载配置」。

## 二、故意没做

- **不做多仓选择器**：那要在源地址页列一遍、点一条切换并持久化 —— 属于独立一片；
- **不自动选第一条子配置加载**：用户没选过的东西不该替他做主（而且子配置地址可能是相对的，
  解析规则要先定清楚）；
- 不解析相对地址：这一轮只是「取出来 + 说清」，真加载时仍走用户手填的完整地址。

## 三、验证点（Mac，和下一批一起跑）

1. 「设置 → 源地址」里填这份内联配置再点加载：

```json
{"urls":["https://a.example/1.json","https://b.example/2.json"]}
```

2. 「状态」区站点数应为 0，但**「告警」区应有一条**「`urls` … 在本平台不生效」；
3. 回发现页：空态文案应是「这份配置是多配置入口（`urls`，共 2 条）…」，
   而不是「请先在设置里加载配置」。
