# M10g 本地地址接管（下好的集直接播本地文件）

- 状态：接管逻辑落地（按远端地址匹配、只认已完成、文件真在才算），接线测试 +2 条；
  **真机上要验一个容器问题**（第三节）
- 时间：2026-10-09
- 依赖：M10d（落盘）、M10e（接线与库）

## 一、接管点选在哪儿

`AppModel.proxiedMediaResource(_:)` 是**全仓播放地址的唯一必经点**（详情页 / 选集页 / 解析页 /
直播页共 5 处都经过它）—— 接管就放它里面：一处改动覆盖所有入口，调用点一行都不用动。

⚠️ 名字没改（仍叫 `proxiedMediaResource`）：改名要动 5 个调用点，留给下次顺手做。
它的职责现在已经是「播放资源的总入口」，函数注释里写明了这一点。

## 二、按「远端地址」找，不按片名 / 集名

播放流程拼出来的 `MediaResource` 手上只有**地址与 header**，片名/集名在更外层（详情页 / 选集页）。
而地址是同一份 —— 任务当初就是用它入的队（`DownloadRequest.url`）。所以匹配口径是它。

两处必须挡住的情况：

- **只认 `finished`**：排队中 / 半截的文件播不了；
- **文件真的在**（前缀扫目录）：记录说「下好了」、文件却被系统清理掉了，也不能接管。

接管之后把地址换成 `file://`、**header 清空**（留着会让播放器对本地地址也带鉴权头发请求），
续播位置保留。

## 三、真机上要验的一件事（已知风险）

拼接出来的 `.ts` 能不能被 `AVPlayer` 直接播，还没有结论（fMP4 的 `.mp4` 没问题）。
真机上：找一个**非 fMP4** 的 HLS 源下完一集，再播那一集 —— 播放页「媒体」那一行会显示
`file://…`，看它是不是真的放起来了：

- 能播：这条通了；
- 播不了：出路是「**保留分片 + 本地改写过的清单**」（`#EXTINF` 指向本地分片），
  让播放器走它本来就支持的本地 HLS 路径，而不是硬塞一个它不认的容器。届时 M10d 的落盘形态要改一处。

## 四、留口

- 详情页的「整部下载」入口；
- `proxiedMediaResource` 改名 `playbackResource`（5 个调用点）；
- ~~「下载管理」列表里「已完成」的条目没有播放入口~~ → **已补**（同批的小改动）：
  列表里「已完成」且文件在的话，多一个「播放」直接进播放页（资源用 `file://` 的那个文件）。

  （它是从站点结果来的）—— 要接的话得给任务加一列，留给以后。
