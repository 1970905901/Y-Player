# M17P2 「最近播放」进诊断报告

- 状态：**已实现**（本地静态闸门全绿 + 新单测；真机由 YG 用 Mac 验证）
- 时间：2026-10-10
- 触发：M17P1 的一键诊断里**故意没放播放信息**（分辨率 / 编码 / 色彩 / 实际硬解 / 丢帧），
  理由写的是「那是播放页的瞬时状态，要进报告得先提到 `AppModel`，留给 M4 真机验证那一片」。
  现在就是那一片 —— M4 的口径是「主做 HDR 与流畅度」，真机验证时最需要的就是这几个数。

## 一、数据怎么到 model

播放页按既有约定**不认识 `AppModel`**（只收值与闭包），所以新增一个回传口：

- `PlaybackView` 加 `onPlaybackStats: ((PlaybackStats) -> Void)?`
  （`refreshPlaybackStats()` 读到**非空**结果时回传一次；读不到不回传，免得冲掉上一次真实结果）；
- `AppModel` 加 `@Published public internal(set) var lastPlaybackStats: PlaybackStats?`
  + `internal func notePlaybackStats(_:)`；
- **7 个 `PlaybackView` 构造点全接上**：详情页、站点换地址页、解析页、直播页（含节目单两条）、
  追剧页播本地已下载的文件。少接一个就是「某个入口播了但报告里没有」。

## 二、报告里长这样

```
【最近播放】
画面：3840×2160
编码：hevc · yuv420p10
帧率：23.976
色彩：HDR · PQ (ST2084) · BT.2020
解码：硬件解码（VideoToolbox）
码率：12.4 Mbps
丢帧：无丢帧
```

- 行内容直接取 ``PlaybackStats`` 的那几个文案函数（与播放页那一块**同一套**，不另写一份）；
- 空项不出现；一次都没播过就写「（这次启动还没播过）」——这条最常被问（画质不对 / 卡顿），
  不给一个空行让人猜；
- 只记**最近一次**：不做历史、不做曲线（诊断要的是「现在」，历史属于另一件事）。

## 三、故意没做

- 不把播放信息落盘：它是排查用的快照，进程退出即失效（要长期数据得先有可观测性那一层）；
- 不做「多路对比」（同一片不同内核各播一次来比），真要做也是 M4 之后的事；
- 不记播放地址：地址可能带鉴权参数，报告里已经有脱敏规矩（M17P1），这里不开口子。

## 四、验证点（Mac）

1. 用 **MPV** 播一集（有画面的正常资源）；
2. 「设置 → 数据 → 日志管理 → 诊断 → 复制诊断信息」→ 粘贴出来，应有一段「【最近播放】」，
   行数与实际读到的项一致（画面 / 编码 / 解码至少要有）；
3. 播放页的「播放信息」块与报告里那几行**应当一致**（同一套文案函数）；
4. 切到系统播放器再播一集（AVPlayer 不报这些）→ 报告里那段应回到「（这次启动还没播过）」
   （因为系统内核读不到，不回传，也不会伪造）。
