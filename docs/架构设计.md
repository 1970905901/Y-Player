# 架构设计

## 一、分层

```
Apps（iOS / macOS 入口）
        │
CatVodUI（SwiftUI 组件与平台 shim，iOS 15 / macOS 13 兼容）
        │
CatVodSource（站点客户端、CatSpider 协议、js2p 宿主、解析嗅探、直播）
        │
CatVodNode（内嵌 Node 宿主适配：端口/env/就绪行/进程生命周期）
        │
CatVodNet（HTTP 传输抽象、请求管线、本地 HTTP 服务）
        │
CatVodCore（协议模型、宽松解码、播放列表/URL/播放请求规则、配置定位与 MD5）
```

依赖方向单向向下；`CatVodCore` 只依赖 Foundation，可在任意 Swift 平台单测。

## 二、并发模型

| 层 | 模型 |
| --- | --- |
| CatVodCore | 纯值类型（`Sendable`），无共享可变状态 |
| CatVodNet | `HTTPTransport` 为 `Sendable`；实现用 `actor` 保证串行化 |
| CatVodSource | 站点客户端为值类型；详情缓存为 `actor` |
| CatVodNode | 宿主适配为 `actor`（单实例、串行调用；进程生命周期与输出缓冲都在其中） |
| CatVodPlayer | `PlayerEngine` 命令方法 `async`；事件通过 `AsyncStream<PlayerEvent>` 下发 |
| CatVodStore | `AppDatabase` 协议，实现为 `actor` |
| CatVodUI | `@MainActor` |

语言模式：`CatVodCore`/`CatVodNet`/`CatVodSource`/`CatVodStore` 使用 **Swift 6 模式**；
`CatVodPlayer`/`CatVodUI` 先保持 **Swift 5 模式**（与 libmpv/FFmpeg 的 C API 交互密集），接口稳定后迁移。

## 三、两条源通道

1. **JSON/XML 猫源通道**：配置 JSON → `SourceConfig` → `ApiURLBuilder` 构造请求 → `SpiderResult` → UI。
2. **js2p 通道（主接口）**：`index.js` + `index.js.md5` → `ConfigLocator` 增量校验 → 交给内嵌 Node 执行 →
   本机 HTTP 服务 → `CatSpiderHTTPClient` 按 `/spider/<key>/{init,home,category,detail,search,play}` 调用。
   契约见 [`js2p宿主契约.md`](js2p宿主契约.md)。

两条通道产出统一的 `SpiderResult`/`VodItem`，UI 与播放层不感知来源差异。

## 三、UI 约定（版本自适应）

**UI 使用每个系统版本各自的原生外观，不做跨版本仿制**：

| 能力 | iOS 15 | iOS/iPadOS 16+ | macOS 13+ |
| --- | --- | --- | --- |
| 导航 | `NavigationView` + `.stack` | `NavigationStack` | `NavigationStack` |
| 列表 | `.insetGrouped` | 同左 | `.inset` |
| 工具栏 | `navigationBarItems` | `toolbar` + `ToolbarItem(.topBar…)` | `toolbar` + `.navigation/.primaryAction` |
| 搜索 | `.searchable` + `navigationBarDrawer` | `.searchable` | `.searchable` |

实现集中在 `Packages/CatVodUI/Sources/CatVodUI/Platform/AdaptiveNavigation.swift`
（`AdaptiveNavigationContainer` / `adaptiveListStyle()` / `adaptiveToolbar(leading:trailing:)` / `adaptiveSearchable(text:prompt:)`）。
**业务视图不得出现 `#available` / `#if os(...)`**；细节与禁止事项见 [`UI 规范.md`](UI%20规范.md)。

## 四、播放内核

```
设置（手动选择，不自动降级）
   ├── PlayerEngineKind：system（AVPlayer，M2 可用）/ mpv（M3）/ ffmpeg（M4）
   └── DecoderMode：hardware / software（对 .system 无效，UI 如实标注）
        │
PlayerCoordinator.resolve(settings:) ──► .ready(kind) ｜ .unavailable(kind, reason)
        │
   ├── AVPlayerEngine（@MainActor final class；iOS 18 SDK 起 AVPlayer 为 @MainActor）
   ├── MpvEngine   ：libmpv（MPVKit，LGPL）client API + render API
   └── FFmpegEngine：自定义 AVIO → demux → VideoToolbox/软解 → Metal → AudioToolbox/AudioEngine → libass
```

**策略：内核与解码方式均由用户在设置里手动选择，运行时严格遵循，不自动降级。**
所选内核不可用时给出原因并引导改设置，而不是静默切换（避免“设置不生效”与画质/兼容性意外变化）。

- 渲染路径（OpenGL ES / MoltenVK / SW→Metal）由 `MpvRenderView` 协议屏蔽，M3 先做三路径 PoC。
- `header` 必须覆盖主清单、子清单、分片、密钥与字幕请求（上游接入要求）；M6 统一走本地代理注入：
  本机回环服务（`LocalHTTPServer`，只绑 `127.0.0.1`）提供 `/proxy?url=…&h=…`，
  由 `ProxyForwardingPolicy` 过滤逐跳 header 并保证注入 header 覆盖播放器自带的同名 header（M06a 落地，播放器接线见 M06b）。
- 内核不可用时 `PlayerEngineKind.isAvailable` 返回 false，UI 如实提示。

## 五、不支持的形态与降级

| 形态 | 降级行为 |
| --- | --- |
| `csp_*.jar`、`parses[].type=2/3` | 需 JVM；站点/解析器标记不可用并显示原因 |
| `.py` Spider | 需 CPython；同上 |
| Widevine / PlayReady | Apple 平台无对应 CDM；仅 ClearKey 可自研 |
| WebHome 网页首页 | **不做**（已决定，2026-10-09）：iOS 侧没有对应形态的宿主；`homePage`/`chromeMode`/`extensions` 字段保留，只为让配置解码不报错 |

## 六、关键约束

1. 本机（Windows）只能产出代码与文档，**编译与真机验证必须在 macOS**（Xcode 16.4）。
2. iOS 无 JIT：内嵌 Node 与任何第三方 JS 引擎均解释执行，性能必须实测。
3. 未签名 IPA 侧载后无法加载事后下载的 dylib → **原生依赖必须随包**。
4. 仓库不内置任何影视源；接口由使用者自行添加。
